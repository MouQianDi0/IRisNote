# 全局横幅通知设计与调用规范

> 状态：组件与首批业务接入已实现（2026-09-09），自动化检查结果见末尾。真机交互由用户验收，尚未标记通过。草稿箱尚未落地，其示例为后续接入方式。

## 1. 定义与边界

全局横幅用于反馈操作结果、展示任务进度和提供可选操作。悬浮于顶部安全区下方，不挤动页面，不抢输入焦点，不自动收起键盘，横幅外区域保持可操作。页面跳转不销毁应用级通知。

应用页面、悬浮栏、抽屉和应用内弹窗都不应遮挡横幅。现有五处原生 Modal 已替换为共享 AppModal 包装，通过 OverlayProvider 向最上层原生窗口注入同一通知宿主。新增应用内 Modal 也必须使用此包装。其层级、手势及切换行为仍需真机验收；原生 Alert 不属于此包装的覆盖范围。多个宿主只能有一个负责可见呈现、计时及无障碍播报，避免重复。系统权限弹窗等系统界面不在应用层级保证范围内。

横幅不替代破坏性操作确认框、表单字段错误、首次加载骨架或页面内长期状态。关键故障即使在横幅展示，也应在相关页面可查询。

## 2. 布局、颜色与交互

```text
┌──────────────────────────────────────┐
│ 图标  标题                 操作   ×  │
│       可选补充说明                   │
│━━━━━━━━━━━━                          │
└──────────────────────────────────────┘
```

- 左侧为固定图标位置，未传图标时按类型提供默认图标；中间标题最多两行，说明可选。
- 右侧最多两个控件：一个可选操作按钮和最右侧关闭按钮。缺省按钮不占空白位置。左侧不放关闭按钮。
- 正文动作与操作按钮独立；没有正文动作时，正文不表现为可点击。点击按钮不得冒泡触发正文动作。
- 类型映射使用统一主题 Token，不允许业务自行传背景色；深浅主题均需保证文字、按钮可读，不能只靠颜色表达状态。

| 参数 type | 用户语义 | 建议颜色 | 默认生命周期 |
| --- | --- | --- | --- |
| success | 及时反馈／成功 | 柔和绿色 | 5 秒自动关闭 |
| important | 重要 | 柔和橙色 | 常驻，可关闭 |
| special | 特殊 | 柔和紫色 | 5 秒自动关闭 |
| neutral | 不重要／普通信息 | 中性灰色 | 5 秒自动关闭 |

通知颜色、展示优先级和生命周期分别配置。“十分重要且持续到解决”使用 critical 优先级和 until-resolved 生命周期，不新增业务自定义颜色。

## 3. 常驻与并行展示

- 十分重要的通知固定在顶部，例如服务器连接失败；普通通知在其下方并行展示，不能替换或赶走该通知。
- 每条普通通知独立计时；某条关闭不影响其他通知的剩余时间。
- 常态最多同时展示三条完整横幅，常驻区优先占位，普通通知至少保留一个位置，其余排队。
- 相同任务使用稳定 ID 原位更新，重复连接失败不会产生多条横幅。
- 多个常驻问题超过两个时，常驻区收拢为一张“有 N 项问题待处理”摘要卡，可展开查看全部问题；所有问题仍保留，摘要持续显示，普通区继续工作。不得静默删除或用普通通知替换未解决问题。展开列表是用户主动操作。
- until-resolved 通知不显示关闭按钮，禁止上滑关闭，只能由业务在状态恢复或该状态所属会话结束时清理。右侧可显示“重试”或“详情”。
- 普通常驻 persistent 通知允许关闭；关闭仅表示隐藏提醒，不代表业务问题已解决。
- 普通等待队列建议上限 20 条，溢出时丢弃最旧的低优先级通知；不丢弃未解决问题。业务可设置排队有效期，过期通知不补弹。

## 4. 计时、手势与任务进度

- 自动消失默认 5000 ms，从实际可见时开始计时；排队期间不消耗显示时长。
- 底部缩短细条只表示剩余显示时间。常驻通知不显示此条。
- 按住、拖动、无障碍焦点位于横幅内、应用进入后台或横幅被宿主暂时隐藏时暂停计时，恢复后继续。
- 可关闭横幅上滑时跟随手指移动并渐隐，达到距离或速度阈值后关闭，否则回弹。横向和向下拖动不关闭。每次只拖动手指命中的那一条。
- until-resolved 不跟随关闭手势；减少动态效果开启时简化动画。控件需有无障碍标签及足够点击区域。
- 普通消息温和播报，严重故障首次出现时提高播报优先级，连续进度更新不能反复打断朗读。
- 任务进行中使用左侧加载图标和文字；只有真实分子、分母可得时才显示百分比，不能伪造进度。任务进度不借用底部倒计时条。
- 同步完成后更新同一 ID 为结果通知，此时启动关闭倒计时。

## 5. 业务场景

| 场景 | 文案示例 | 类型／生命周期 | 动作与触发条件 |
| --- | --- | --- | --- |
| 用户主动同步 | 正在同步笔记… | neutral／persistent | 同一任务 ID 更新，左侧加载图标 |
| 同步完成且有新增 | 同步完成，本次新增 12 条 | success／5 秒 | 可选“查看”；数量取实际入库新增结果，不取响应数组长度 |
| 主动同步但无变化 | 同步完成，暂无新内容 | success／5 秒 | 对主动操作给予完成反馈 |
| 后台同步无变化 | 不显示横幅 | 静默 | 不因每次进入页面重复提示 |
| 服务器连接失败 | 无法连接服务器，正在重连 | important／critical／until-resolved | “重试”；由连接状态协调层汇总，同一故障一条 |
| 连接恢复 | 服务器连接已恢复 | success／5 秒 | 原 ID 转换；以真实服务端请求成功为依据，网络联网不等于服务恢复 |
| 本地保存成功 | 笔记已保存在本机 | success／5 秒 | 本地事务提交成功后调用；不能暗示云端已同步 |
| 云端保存成功 | 笔记已同步到云端 | success／5 秒 | 已确认服务端接受，必要时更新同一保存通知，避免两条重复反馈 |
| 本地保存失败 | 保存失败，内容仍保留在编辑页 | important／persistent | “重试”；页面必须实际保留输入，不得提前离开 |
| 主动保存草稿成功 | 已保存到草稿箱 | success／5 秒 | 可选“查看”；草稿箱路由实现后接入 |
| 自动保存恢复副本 | 不显示成功横幅 | 静默 | 避免随输入持续打扰；失败时按实际风险汇总提醒 |
| 再按返回退出 | 再按一次返回退出应用 | neutral／短时 | 仅根页面，显示时长与退出有效窗口一致；过期或离开根页立即关闭 |
| 欢迎提示 | 欢迎回来 | special／3 秒 | 每次会话最多一次，低优先级，排队过期则丢弃 |

补充：401、权限不足、单次业务校验失败不能一概当作“服务器连接失败”。仅在确认本地持久化正常时，才能附加“笔记仍保存在本机”。删除确认、放弃编辑及恢复草稿选择仍使用各自确认交互。

## 6. 公开接口

统一从 `@/core/notifications` 导入 `banner`。该入口已实现，类型以 `src/core/notifications/notification.types.ts` 为准。

```ts
type BannerId = string;
type BannerType = "success" | "important" | "special" | "neutral";
type BannerPriority = "low" | "normal" | "high" | "critical";
type BannerLifetime =
  | { mode: "timed"; durationMs?: number } // 默认 5000，必须为正数
  | { mode: "persistent" }               // 常驻，用户可关闭
  | { mode: "until-resolved" };          // 常驻，用户不可关闭

type BannerAction = {
  label: string;                         // 按钮文案／正文无障碍动作说明
  onPress: () => void | Promise<void>;   // 普通动作或调用业务路由跳转
  dismissOnSuccess?: boolean;            // 默认 false；异步操作完成后才处理
};

type BannerContent = {
  title: string;
  message?: string;
  type: BannerType;
  priority?: BannerPriority;             // important 默认 high，其余 normal
  lifetime?: BannerLifetime;             // 按类型使用上表默认值
  icon?: "check" | "info" | "warning" | "cloud-off" | "sparkles";
  progress?:
    | { mode: "indeterminate" }
    | { mode: "determinate"; value: number }; // value 范围 0..1
  bodyAction?: BannerAction;             // 未配置即不可点击、不可跳转
  action?: BannerAction;                 // 最多一个右侧业务按钮
};

type BannerOptions = BannerContent & {
  id?: BannerId;                         // 缺省生成；稳定 ID 用于去重
  scope?: "session" | "app";            // 默认 session；退出／换账号清理
  queueTtlMs?: number;                   // 排队有效期；缺省 30000
};

interface BannerApi {
  show(options: BannerOptions): BannerId;
  update(id: BannerId, patch: Partial<BannerContent>): boolean;
  resolve(id: BannerId, result: BannerContent): boolean;
  dismiss(id: BannerId): boolean;
  clearSession(): void;
}
```

接口语义：

- `show`：同步入队并返回 ID，不等待关闭。同 ID 已存在时去重，保留现有内容和计时；改变状态应显式调用 `update` 或 `resolve`。ID 被清理后可重新使用。
- `update`：仅更新存在的通知，不存在返回 false，不重新创建。省略字段保留原值；显式传 undefined 清除可选字段；lifetime/progress/action 按整个对象替换。
- 普通文字／进度更新不重置计时；显式传入 timed lifetime 则重新计时，进入 persistent/until-resolved 则停止计时。
- `resolve`：业务确认问题解决或任务完成后，全量替换可变内容，清除旧进度、旧动作及旧说明；保留 ID 和作用域。结果默认转为 timed 5000 ms，不接受 until-resolved；不存在返回 false，不补弹旧任务消息。
- `dismiss`：关闭可关闭通知或移除其排队项；until-resolved 或不存在时返回 false。组件不提供强制关闭未解决问题的普通业务接口。
- `clearSession`：退出登录或切换账号时移除全部 session 通知（包括未解决项），作废旧会话异步回调；app 通知不得包含账号私有内容。不是将故障标记为已修复。
- critical 必须配合 until-resolved，until-resolved 自动采用 critical；这类通知不受 queueTtlMs 限制。
- 动作执行中禁用该条通知的动作入口，暂停倒计时、防重复点击。失败保留通知并结束忙碌态；业务回调负责给出准确失败文案，不能泄露原始服务端错误。
- until-resolved 禁止使用 dismissOnSuccess 自动关闭，必须由业务显式 resolve。其他动作默认保留通知，成功跳转可设置 dismissOnSuccess: true。
- 异步动作若已 update/resolve 同一通知，旧动作完成后的自动关闭不得移除新状态；实现需校验通知版本和会话。

## 7. 调用示例

### 7.1 本地保存成功

```ts
import { banner } from "@/core/notifications"; // 已实现的统一入口

// 必须放在本地事务提交成功之后。
banner.show({
  id: `note-save:${noteId}`,
  type: "success",
  title: "笔记已保存在本机",
});
```

### 7.2 同步任务更新

示例中的 runId、runSync 为业务提供的任务标识和函数，不是通知 API。

```ts
const id = banner.show({
  id: `notes-sync:${runId}`,
  title: "正在同步笔记…",
  type: "neutral",
  lifetime: { mode: "persistent" },
  progress: { mode: "indeterminate" },
});

try {
  const result = await runSync(); // result.addedCount 为实际新增入库数量
  banner.resolve(id, {
    type: "success",
    title: result.addedCount > 0
      ? `同步完成，本次新增 ${result.addedCount} 条`
      : "同步完成，暂无新内容",
  });
} catch {
  banner.update(id, {
    type: "important",
    priority: "high",
    title: "同步失败，请稍后重试",
    progress: undefined,
    lifetime: { mode: "persistent" },
  });
}
```

若连接状态协调层已经展示服务器故障横幅，任务层应关闭自己的普通进度提示，避免再显示相同故障。后台静默同步不必先创建进度横幅。

### 7.3 服务器故障常驻与恢复

```ts
const connectionId = "server-connection";

// 由连接状态协调层在状态转为故障时调用，而非每个 HTTP catch 各弹一次。
banner.show({
  id: connectionId,
  type: "important",
  priority: "critical",
  title: "无法连接服务器，正在重连",
  icon: "cloud-off",
  lifetime: { mode: "until-resolved" },
  action: { label: "重试", onPress: retryConnection },
});

// 实际请求验证服务恢复后调用，联网事件本身不足以触发。
banner.resolve(connectionId, {
  type: "success",
  title: "服务器连接已恢复",
  lifetime: { mode: "timed", durationMs: 5000 },
});
```

retryConnection 是业务函数；失败时保留常驻故障，成功由协调层 resolve。同一服务器故障在“显示已恢复”的 5 秒内复发时，应 update 原 ID 为 important/critical/until-resolved 并恢复动作，而不是只重复 show。连接检测需要抑制瞬时抖动，不将一次超时直接认定为持续故障。

### 7.4 草稿箱跳转

```ts
// 草稿持久化完成后；openDraftBox 由业务在草稿箱路由落地后提供。
banner.show({
  id: `draft-save:${draftId}`,
  type: "success",
  title: "已保存到草稿箱",
  action: {
    label: "查看",
    onPress: openDraftBox,
    dismissOnSuccess: true,
  },
});
```

若整个正文也可跳转，再传入同语义的 bodyAction。通知组件自身不硬编码笔记或草稿路由。

### 7.5 返回退出和欢迎

```ts
banner.show({
  id: "back-exit",
  type: "neutral",
  title: "再按一次返回退出应用",
  lifetime: { mode: "timed", durationMs: exitWindowMs },
  queueTtlMs: exitWindowMs,
});
// 根页面退出有效窗口结束或离开根页面时，业务同时调用：
banner.dismiss("back-exit");

banner.show({
  id: "session-welcome",
  type: "special",
  priority: "low",
  title: "欢迎回来",
  lifetime: { mode: "timed", durationMs: 3000 },
  queueTtlMs: 3000,
});
```

退出有效时间由现有返回处理器控制，不由横幅动画决定；从触发时起到期即取消通知，包括排队项，不能因排队延长退出窗口。欢迎“一次会话最多一次”由业务会话标记保证，不能仅依赖通知 ID（关闭后 ID 可复用）。

## 8. 实现落点与接入约束

通知管理位于 `src/core/notifications/`，纯横幅展示位于 `src/shared/ui/Banner/banner-card.tsx`，共享弹窗插槽位于 `src/shared/ui/Overlay/`，主题映射位于 `src/shared/theme/banner.ts`。`AppProviders.tsx` 挂载 Provider，根布局放置 OverlaySlot。现有锚点气泡、笔记菜单及三个分类弹窗通过 AppModal 接入；共享 UI 不反向导入 core。

业务 Screen、Hook 或状态协调服务在真实状态转换时调用统一接口，组件不请求接口、不重试网络、不自行决定保存是否成功。不要在 render 函数或没有去重的 effect 中发送通知，不要在 HTTP 拦截器无差别弹出每个错误。

需要向用户显示全局非阻断状态时必须使用该入口，不自行新增 Toast、散落的提示条或仅用于“成功”的 Alert。普通后台无变化及自动保存成功维持静默；“统一调用”不是要求把所有内部状态都弹出来。破坏性确认和字段内错误保留专用交互。

## 9. 实现验收清单

- [ ] 服务器故障常驻时，保存成功等普通通知仍可同时出现并独立消失。
- [ ] 未解决通知不可关闭或上滑移除，真实恢复后同 ID 转成功并自动关闭。
- [ ] 多个常驻问题收拢后仍可全部查阅，且普通通知有展示位置。
- [ ] 同 ID 去重、排队过期、队列上限、关闭后重新发送及故障复发均符合契约。
- [ ] 输入焦点、键盘、页面滚动不受干扰，横幅外点击可穿透；大字体、小屏、深浅主题可用。
- [ ] 普通手势跟手及回弹正确，按压／后台／无障碍焦点暂停倒计时，进度与倒计时不混淆。
- [ ] 页面、抽屉、锚点菜单及原生 Modal 打开时均验证最高应用层级，播报和计时无重复。
- [ ] 异步重试防重复、失败保留，旧回调不关闭新状态，不把旧账号通知带入新会话。
- [ ] 文案区分本机保存与云端同步，新增数量来自真实入库统计。
- [ ] 返回退出提示与实际窗口一致；欢迎每会话一次；后台无变化不打扰。

## 11. 本次接入细节与验收安排

### 已接入的行为

- 保存：`note-save.service.ts` 提供可选 `onLocalSaved(note)`，本地事务成功后通知编辑页；提示回调抛错不会中断保存／上传。编辑页使用同一通知 ID 更新云端结果，保留原有草稿和错误处理。
- 同步：`NotesScreen.tsx` 的主动下拉刷新由 `NotesSyncHeader.tsx` 在列表内展示，不调用横幅。列表到顶后继续下拉，达到阈值松手后拉取云端笔记并合并到本地；显示笔记总数、小转圈及同步状态，成功或失败后短暂停留再收起。`reconcileServerNotes` 的可选第四参数 `onReconciled({ addedCount })` 统计事务内实际新增数；此入口不代表待上传笔记已全部上传，不展示虚构百分比。全局服务器连接故障横幅仍独立工作。
- 连接：Shared HTTP 仅发布事件，协调层在连续两次连接不可用结果后显示常驻故障。第一次失败即可启动只读确认请求；GET 缺省超时 15 秒，确认请求 `/user/profile` 超时 8 秒，重试间隔 2/4/8/16/30 秒，上限 30 秒。后台暂停、会话结束取消；不自动重放创建或更新请求。
- 请求结果：2xx 可结束连接故障；502/503/504 及网络错误／超时计入不可用；取消不计入。其他业务响应不当作连接故障，若此前存在故障则转为可关闭的“服务器已响应，请检查当前请求状态”，不伪报业务成功。
- 返回：沿用根页面 1500 ms 二次返回窗口，期限到达或离开根页立即撤掉提示，不受排队延长。
- 欢迎：同一登录会话最多一次，3 秒显示／排队有效期；退出或换账号清理会话通知。
- 无障碍：读屏启用时，计时通知暂停自动消失，用户仍可通过关闭按钮移除；动态进度不逐帧播报。

### 异步调用的会话保护

所有跨 await 的通知发送需捕获会话，避免退出后旧任务重新弹出通知。通知组件能保护自己的动作回调，但不能自动识别任意业务异步函数所属的旧会话。

```ts
import { banner, captureNotificationSession } from "@/core/notifications";

const isCurrentSession = captureNotificationSession();
const result = await saveContent(); // 业务函数
if (isCurrentSession()) {
  banner.show({ type: "success", title: "操作已完成" });
}
```

不要把笔记正文、凭据或原始服务端报错直接放进横幅。账号级动作回调也需在重试完成后校验会话。
