# IRisNote 业务模块与运行逻辑

本文档解释当前业务“如何运行”。如果只想查某个文件的位置，请先看 [项目架构与文件索引](./项目架构与文件索引.md)；如果要新增功能，请看 [后续开发指南](./后续开发指南.md)。

## 1. 全局启动流程

```text
src/app/_layout.tsx
└── AppProviders
    └── ApplicationDatabaseProvider
        ├── 打开 irisnote.db
        ├── 启用 foreign_keys 与 WAL
        ├── 核对并执行数据库迁移
        └── AuthProvider
            ├── 从 AsyncStorage 恢复 Token 和 User
            ├── 从服务端同步最新用户资料
            └── GestureHandlerRootView
                └── Expo Router Stack
                    └── (tabs)/_layout.tsx
                        ├── 认证加载中：ActivityIndicator
                        ├── 未登录：Redirect /auth/login
                        └── 已登录：Tabs + FloatingMenu
```

关键文件：

| 文件 | 在启动链中的作用 |
| --- | --- |
| `src/app/_layout.tsx` | 创建根 Stack，并加载全局样式。 |
| `src/core/providers/AppProviders.tsx` | 按数据库、认证、手势的顺序组合全局 Provider。 |
| `src/core/database/ApplicationDatabaseProvider.tsx` | 获取共享数据库租约并注入受控端口，卸载时释放租约。 |
| `src/core/database/application-database-resource.ts` | 打开并初始化正式库，管理连接和失败清理。 |
| `src/features/auth/providers/AuthProvider.tsx` | 恢复和维护会话。 |
| `src/app/(tabs)/_layout.tsx` | 根据认证状态决定显示加载、登录页或主 Tabs。 |

### 1.1 本地数据库启动与访问规则

Android、iOS 和 Web 共用 `src/core/database` 的迁移清单及公共端口。原生文件库事务使用独立连接；Web 和内存库复用主连接。所有公开操作进入同一串行队列，事务连接先启用并确认外键，再执行 `BEGIN IMMEDIATE`，结束后提交或回滚。

同一运行时按数据库路径串行初始化，迁移在写锁内重新核对版本和登记表。多个 Provider 共享初始化及端口；最后一个租约释放后等待初始化完成、拒绝新任务、排空已接收任务并关闭一次；新租约等待旧连接关闭。正常关闭失败时阻断重开，初始化失败不删除正式库。

阶段 1 引入迁移登记表，阶段 2A 引入 `local_notes` 和点击保存时的本地优先落盘；阶段 2B 引入独立 `note_drafts`；阶段 3A 引入 `note_revisions` 本地版本表，结构版本为 4——点击保存才创建不可变版本，无变化不建版本，服务器对账内容变化时追加 reconcile 版本。自动草稿与保存版本均已接入，历史查看 UI 尚未实现；原生数据库诊断及运行验证仍待完成。

业务模块只能使用 `useApplicationDatabase` 或建立在其上的 Feature 仓库。原始 SQLite 实例不会进入应用组件树，Feature 不得直接导入 `expo-sqlite`。用户数据必须使用绑定参数，禁止拼接到 SQL 字符串中。

## 2. HTTP、Token 与设备标识

所有业务 API 都使用 `src/shared/http/client.ts` 中的 Axios 实例。

### 2.1 请求流程

```text
Feature API 调用
└── shared/http/client.ts
    ├── 读取 AsyncStorage.authToken
    ├── 有 Token：附加 Authorization: Bearer <token>
    ├── 验证码/注册/登录请求：附加 X-Device-Id
    └── 发送到 EXPO_PUBLIC_BASE_URL 或默认 API 地址
```

设备 ID 首次生成后存入 AsyncStorage，之后复用。当前只有 URL 以 `/verify/`、`/auth/register` 或 `/auth/login` 开头时才附加设备 ID。

### 2.2 错误处理

页面和业务 Hook 使用 `getApiErrorMessage`，不直接解析 Axios 的 `response.data`：

```ts
import { getApiErrorMessage } from "@/shared/http/errors";

try {
    await request();
} catch (error) {
    const message = getApiErrorMessage(error, "操作失败，请稍后重试");
}
```

它会优先读取服务端的 `error` 或 `message`，并在存在时追加剩余重试时间或剩余尝试次数。

## 3. Auth：认证业务

### 3.1 相关文件

| 文件 | 作用 |
| --- | --- |
| `features/auth/api/auth.api.ts` | 验证码、登录和注册接口。 |
| `features/auth/api/session.api.ts` | 获取当前用户资料。 |
| `features/auth/auth.types.ts` | 请求、响应和上下文类型。 |
| `features/auth/auth.context.ts` | 认证 Context。 |
| `features/auth/providers/AuthProvider.tsx` | 全局会话状态源。 |
| `features/auth/hooks/useAuth.ts` | Feature 和 Layout 读取会话的入口。 |
| `features/auth/hooks/useEmailValidation.ts` | 邮箱校验。 |
| `features/auth/screens/LoginScreen.tsx` | 登录 UI 和流程编排。 |
| `features/auth/screens/RegisterScreen.tsx` | 注册 UI 和流程编排。 |

### 3.2 会话恢复

```text
AuthProvider 挂载
├── 读取 storageKeys.authToken
├── 读取 storageKeys.authUser
├── 恢复本地登录状态
├── loading = false
└── 首次本地恢复完成后，有 Token 时异步调用 GET /user/profile
    └── 同步成功后更新 AsyncStorage 和 Context 中的 User
```

服务端资料同步不会阻塞 `loading` 结束；同步失败时保留本地 User。Provider 所在路由重新获得焦点时会再次读取本地会话，使登录页写入的 Token/User 能被主 Tabs 感知。

### 3.3 登录

登录与注册 UI 使用同一套 HyperOS 表单组件。校验错误在字段失焦后显示；接口失败在主按钮上方显示并保留输入。验证码发送成功显示全局横幅并进入 60 秒倒计时。请求使用同步 Ref 锁防止重复触发；提交中锁定输入、发送和页面切换入口。认证成功完成 Token/User 保存、refresh 和 syncProfile 后直接进入用户页，并显示成功横幅，无需系统确认框。未登录访问主 Tabs 时先进入欢迎页；欢迎页提供注册和登录入口。表单间切换使用 replace，返回按钮及 Android 返回键使用 dismissTo 回欢迎页，路由栈没有欢迎页时替换当前页；发送/提交中不响应返回。已登录访问欢迎页会回到笔记列表。

```text
LoginScreen
├── useEmailValidation 校验邮箱
├── 请求验证码并启动 60 秒倒计时
├── 提交邮箱、密码和验证码
├── auth.api.loginWithPassword
├── 保存 Token 与 User 到 AsyncStorage
├── 通知 AuthProvider 刷新/同步资料
└── 导航到用户页
```

当前 API 已封装 `loginWithCode`，但现有登录页面主要走“密码 + 验证码”流程。不要在文档或 UI 中把纯验证码登录描述为已经启用。

### 3.4 注册

RegisterScreen 在请求前检查：

- 邮箱格式有效。
- 昵称非空。
- 密码至少 6 位。
- 两次密码一致。
- 验证码已填写。

注册成功后的 Token/User 保存方式与登录一致。

### 3.5 退出登录

ProfileScreen 的退出按钮直接调用 `useAuth` 提供的退出逻辑，当前没有二次确认框：

```text
用户点击退出
├── 删除 AsyncStorage Token
├── 删除本地 User
├── AuthProvider 更新登录状态
└── Tabs 守卫重定向到欢迎页
```

## 4. Notes：笔记业务

### 4.1 列表首次加载

```text
NotesScreen 挂载
├── getNotes()
│   ├── normalizeNote
│   ├── withLocalOrder
│   ├── 计算最大 pinned_order
│   └── setCachedNotes
├── getCategories()
└── loading = false
```

`notesRequestRef` 和 `categoriesRequestRef` 保存正在执行的 Promise。如果同一请求尚未完成，新的调用会复用已有 Promise，避免重复并发。

### 4.2 排序规则

排序由 `notes.selectors.ts` 负责：

1. 置顶笔记排在非置顶笔记前。
2. 置顶笔记按 `pinned_order` 从大到小。
3. 非置顶笔记按 `local_order` 从小到大。

简单调用示例：

```ts
import { sortNotesByPinned, withLocalOrder } from "@/features/notes/notes.selectors";

const notes = sortNotesByPinned(withLocalOrder(apiNotes));
```

### 4.3 分类筛选

```text
CategoryBar 点击分类
├── setCurrentCategory(id, name)
├── NotesScreen.setCurrentCategory(String(id))
└── filteredNotes 根据 category_id 过滤
```

ID 为 `0` 的“全部”是前端虚拟分类，不会写入后端。选择“全部”时不做 `category_id` 过滤。

### 4.4 新建笔记

相关文件：

- 路由：`app/pages/note/create.tsx`。
- 页面：`features/notes/screens/CreateNoteScreen.tsx`。
- API：`features/notes/api/notes.api.ts`。
- 本地仓库：`features/notes/data/note-local.repository.ts`。
- 保存服务：`features/notes/services/note-save.service.ts`。
- 分类选择：`features/notes/categories/category-selection.ts`。
- 列表刷新事件：`features/notes/notes.events.ts`。

流程：

```text
FloatingActionButton
└── /pages/note/create
    └── CreateNoteScreen
        ├── 校验标题和正文非空
        ├── 读取当前分类
        ├── 当前为“全部”：不传 category_id
        ├── 当前为普通分类：传 category_id
        ├── SQLite 事务创建本地笔记（稳定负数客户端 ID）
        ├── setCachedNote + notifyNotesChanged({ note })
        ├── POST /notes，并记录上传进度与响应状态
        ├── 成功：保存 server_id 并标记 synced
        ├── 失败或未知：保留本地笔记和同步状态
        └── router.back()
```

NotesScreen 已订阅 `onNotesChanged`，收到携带完整笔记的事件后直接增量覆盖列表，不再因保存事件重新拉取整表。主动加载时先展示当前账户的 SQLite 数据，再把 `GET /notes` 结果与本地表合并；只有 `synced` 行允许被服务器覆盖。

### 4.5 笔记详情

```text
点击 NoteCard
└── /pages/note/[id]
    └── NoteDetailScreen
        ├── 校验 id 是非零整数（负数表示本地新建笔记）
        ├── getCachedNoteById(id)
        ├── 命中：直接展示
        ├── 未命中：查询 SQLite；仍缺失才 GET /notes 并合并
        ├── 找到：NoteViewer
        │   ├── 顶部编辑按钮跳转 /pages/note/edit/[id]
        │   └── 底部浮动工具栏入口（滚动显隐），跳转编辑页并自动聚焦正文
        ├── 未找到：not-found 状态
        └── 请求失败：error + retry
```

模块级 `Map` 仍是当前进程的读取加速层，并使用“用户 ID + 笔记 ID”复合键避免换号串读；SQLite `local_notes` 才承担重启后的保存恢复，并按登录用户 ID 隔离。

### 4.6 编辑笔记

详情页顶部编辑按钮和列表长按菜单共用现有动态编辑路由：

```text
/pages/note/edit/[id]
└── EditNoteScreen
    ├── 校验 id
    ├── 优先读取进程缓存
    ├── 缺失时查询 SQLite；仍缺失才 GET /notes 并合并
    └── NoteEditor（Notes 适配层）
        ├── 将 Note 转换为纯文本编辑值
        ├── PlainTextEditor（core/editor）维护临时输入
        ├── 校验并裁剪标题
        ├── SQLite 事务保存本地改动
        ├── setCachedNote + 携带完整笔记的 notifyNotesChanged
        ├── 使用 server_id 调用 PUT /notes/:id
        ├── 输出上传进度和 accepted/rejected/unknown 日志
        └── 返回上一页
```

新建笔记由 `NoteEditor` 适配；既有笔记统一在 `NoteViewer` 详情合并页编辑，并由 `useNoteDraft` 建立按账户和笔记 ID 隔离的唯一草稿会话。进入详情页先读取稳定笔记，再创建或恢复 `note:<clientId>` 草稿；本次页面会话中的标题、正文与分类变化始终写入同一份草稿。

`PlainTextEditor` 不调用 API，也不知道笔记 ID、分类、缓存或事件；只通知输入变化与失焦。Notes 会话按 750ms 防抖/5 秒最长等待落盘，写入中合并最新快照。正常返回等待补写；后台/页面隐藏/卸载也请求补写，失败提示并重试。

既有笔记收起键盘或输入失焦时只补写本地草稿，不创建 Revision，也不触发云同步。真正退出详情页时，导航拦截器先锁定并排空草稿，在本地事务内验证会话、序号和基础版本指针，提交稳定笔记并创建本地版本（内容无变化时不建版本，已同步时跳过上传）；本地提交成功后允许页面退出，再由 `note-exit-sync-coordinator` 串行静默上传。云端接受后条件清理本次草稿；失败、结果未知或草稿已被新页面会话接管时保留。旧上传响应按 Revision 条件确认，不得把更新的本地版本误标为已同步。

新建笔记仍沿用原有显式保存流程：每账户一个新建草稿槽，已关联笔记的草稿恢复后更新原笔记，结果未知的新建不会自动重复 POST。放弃草稿需要二次确认。

基础快照仅检测本地变化，冲突时保留供查看/复制并阻止直接保存；正式 Revision 和服务端基础版本校验尚未实现。异常终止前未落盘的输入不能保证恢复。

### 4.7 滑动操作

`SwipeableNoteItem` 将手势、卡片和操作层组合起来：

- 右滑最多 138px，显示置顶和标星。
- 左滑最多 76px，显示删除。
- 超过 48px 才保持展开。
- `openedNoteId` 保证同一时间只展开一个列表项。
- `useDebouncedAction` 用动作键防止快速重复点击。

组件关系：

```text
SwipeableNoteItem
├── NoteSwipeActions
│   ├── 置顶
│   ├── 标星
│   └── 删除
└── NoteCard
    ├── PinBadge
    └── StarBadge
```

### 4.8 置顶与标星的乐观更新

```text
用户点击置顶/标星
├── 记录 previousNotes
├── 先修改本地列表和缓存
├── 关闭滑动操作项
├── PUT /notes/:id
├── 成功：保留本地结果
└── 失败：恢复 previousNotes 并提示错误
```

置顶时还会生成新的最大 `pinned_order`；失败时同时恢复置顶顺序 Ref。

### 4.9 删除笔记

NotesScreen 先显示系统确认框。确认后调用 `DELETE /notes/:id`，成功时同时：

- 从列表删除该项。
- 从 `notes.cache.ts` 删除该项。
- 关闭已展开的滑动操作。

## 5. Notes/Categories：笔记分类

### 5.1 分类为什么属于 Notes

当前分类只用于：

- 筛选笔记列表。
- 新建笔记时指定分类。
- 展示笔记详情的分类名。
- 删除分类时删除该分类下的笔记。

它没有被 Todo 或 Excerpt 使用，所以放在 `features/notes/categories`。只有未来成为多个业务共用的标签系统时，才考虑提升为顶层 Feature。

### 5.2 分类栏

```text
CategoryBar
├── useAvatar：展示用户头像
├── getCategories：加载后端分类
├── ALL_CATEGORY：添加前端“全部”入口
├── 置顶分类列表
├── 普通分类列表
├── CategoryButton：点击选择、长按操作
└── CategoryActionModal：编辑或删除
```

分类栏和 NotesScreen 都订阅 `onCategoriesChanged`。任何分类写操作成功后广播事件，两处分别刷新自己的分类数据。

### 5.3 创建分类

```text
AddCategoryButton
└── CreateCategoryModal
    ├── 输入名称
    ├── CategoryIconPicker 选择图标
    ├── 调用 onAdd(name, icon)
    │   └── NotesScreen 异步 POST /categories，成功后 notifyCategoriesChanged()
    └── 不等待请求结果，立即关闭并重置表单
```

当前弹窗不会等待异步 `onAdd` 完成，因此请求失败时弹窗也已经关闭，错误只写入控制台。可选图标统一维护在 `category-icons.ts`。后端返回未知图标名时，开发环境会警告并降级为 Folder。

### 5.4 分类置顶、标星、改名和改图标

四个 Hook 的结构一致：

```text
CategoryActionModal 触发动作
├── PUT /categories/:id
├── 更新 CategoryBar 的 categories 数组
├── 更新弹窗当前 category 对象
└── notifyCategoriesChanged()
```

对应文件：

- `useCategoryPin.ts`
- `useCategoryStar.ts`
- `useCategoryRename.ts`
- `useCategoryChangeIcon.ts`

### 5.5 删除分类

删除不是单个 API 调用。当前前端会先删除该分类下的笔记，再删除分类：

```text
CategoryActionModal
├── 进入删除模式
├── 图标向垃圾桶拖动超过 50px
└── CategoryDeleteConfirmModal
    └── useCategoryDelete
        ├── GET /notes
        ├── 筛选 category_id
        ├── 每批最多 3 条 DELETE /notes/:id
        ├── 批次之间等待 100ms
        ├── DELETE /categories/:id
        ├── notifyCategoriesChanged()
        └── notifyNotesRemovedByCategory(categoryId)
```

NotesScreen 收到 `notesRemovedByCategory` 后增量移除本地列表中的对应笔记，并更新缓存。

当前删除流程没有服务端事务。若中途请求失败，可能出现部分笔记已经删除、分类尚未删除的状态。后续更可靠的方案是增加服务端事务型批量删除接口。

## 7. Core Navigation：主导航

### 7.1 Tab 配置

`navigation.constants.ts` 是主 Tab 唯一配置源。菜单展示顺序与手势索引顺序是两组不同配置：

```text
TAB_MENU_ITEMS 展示顺序：note → todo → excerpt → user
TAB_ORDER / TAB_INDEX_BY_KEY：user → excerpt → todo → note
```

上滑会取 `TAB_ORDER` 中的前一个索引，因此从 Note 开始的表现为 `note → todo → excerpt → user`；下滑方向相反。

每个 Tab 同时有一个主操作：

| 当前 Tab | 主操作目标 |
| --- | --- |
| Note | `/pages/note/create` |
| Todo | `/pages/todo/create` |
| Excerpt | `/pages/excerpt/create` |
| User | `/pages/user/settings` |

### 7.2 浮动菜单

FloatingMenu：

- 根据 Tabs State 显示当前激活项。
- 使用 `router.replace` 切换 Tab，避免不断增加返回栈。
- 激活图标播放 pulse 动画。
- 订阅 `floating-menu-visibility`，在笔记列表滚动时临时移出屏幕。
- 在菜单区域使用 `useSwipeTab` 上下滑循环切换 Tab。
- 组合 FloatingActionButton 提供当前页面的主操作。

### 7.3 导航防重复

普通业务跳转优先使用：

```ts
const navigate = useDebouncedNavigation();
navigate("/pages/note/create");
```

第一次调用会立即建立全局导航锁，100ms 后执行跳转，再过 500ms 解锁。在锁定期间，任何后续目标都会被忽略；`pendingRouteKeyRef` 另外记录待处理目标。长按入口使用 `useLongPressNavigation`，不要在业务组件内重复实现一套手势和定时器。

## 8. 当前状态机制总表

| 状态 | 所在文件 | 是否持久化 | 作用范围 |
| --- | --- | --- | --- |
| Auth Token/User | AsyncStorage + AuthProvider | 是 | 全应用 |
| Device ID | AsyncStorage | 是 | 登录、注册、验证码请求 |
| 笔记详情缓存 | `notes.cache.ts` 的 Map | 否 | 当前进程 |
| 笔记变更事件 | `notes.events.ts` | 否 | 当前进程 |
| 纯文本编辑输入 | `core/editor` 组件状态 | 否 | 当前编辑页面 |
| 当前分类 | `category-selection.ts` 模块变量 | 否 | 分类栏与新建笔记页 |
| 分类变更事件 | `categories.events.ts` | 否 | 当前进程 |
| 浮动菜单隐藏状态 | `floating-menu-visibility.ts` | 否 | 当前进程 |

这些模块变量不是 Zustand Store，也不会在应用重启后恢复。当前依赖中虽然安装了 Zustand，但现有业务没有使用它。
