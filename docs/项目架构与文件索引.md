# IRisNote 项目架构与文件索引

本文档是当前源码的开发地图，用来回答以下问题：

- 一个文件夹负责哪一类代码？
- 一个页面的路由文件和真正的业务 Screen 分别在哪里？
- 每个业务由哪些文件组成？
- 修改某个组件时，还需要检查哪些依赖文件？

本文档以当前仓库源码为准。Todo、Excerpt 和 Settings 仍是占位模块，文档不会把尚未存在的 API、Store 或组件描述为已实现。

## 1. 架构分层

```text
src/app       Expo Router 路由层，只定义 URL、Layout、重定向和 Screen 转发
src/core      跨业务应用核心，例如全局 Provider、主导航、系统返回和通用编辑器
src/features  按业务领域组织页面、API、业务组件、Hook、类型和状态协调
src/shared    跨业务复用且不包含具体业务语义的基础能力
```

主要依赖方向：

```text
app ──────────────→ core / features / shared
core ─────────────→ features（全局编排时）/ shared
features ─────────→ core（导航等壳层能力）/ shared
shared ───────────→ 第三方库或 shared 内部文件
```

`core` 内部仍需按模块约束依赖：`core/editor` 只能依赖 React、React Native、第三方库和 `shared`，不得依赖任何 Feature；`core/providers` 因全局编排可以组合 Feature Provider。

必须遵守的边界：

- `app` 中不实现表单、请求、缓存或业务状态。
- `core` 中不放只属于笔记、认证或头像等单一业务的代码。
- `features` 可以使用 `core` 和 `shared`，但业务之间应避免直接读取彼此内部文件。
- `shared` 不得反向依赖 `features`、`core` 或 `app`。
- 笔记分类只服务于笔记，因此位于 `features/notes/categories`，而不是顶层 `features/categories`。

## 3. 路由层：`src/app`

`src/app` 是 Expo Router 的文件系统路由目录。除 `_layout.tsx` 和重定向外，页面文件都应是薄包装：

```tsx
export { default } from "@/features/notes/screens/NotesScreen";
```

## 4. 应用基础设施：`src/core`

### 4.1 `core/editor`

| 文件 | 职责 | 主要使用方 |
| --- | --- | --- |

| `editor/components/editor-bottom-toolbar.tsx` | 四区工具栏：无键盘为 225×48dp、14dp 圆角矩形，键盘期为 43.2dp 紧贴输入法的通栏；第一区聚焦正文、后三区禁用预留，并负责 24/100dp 滚动显隐与防重复点击。 | `PlainTextEditor`、`notes/components/viewer/NoteViewer.tsx` |

| `testing/run-database-diagnostics.ts` | 临时库检查持久化、并发迁移、事务外键、回滚、端口排空和备份；尚未执行。 | 显式开发诊断开关 |

| `index.ts` | 数据库模块公共出口，不导出原始 SQLite 实例。 | 全项目 |

`core/database` 是跨业务应用基础设施。原始 SQLite 实例不会通过 Expo SQLite Context 暴露给应用组件树；Feature 禁止直接调用 `expo-sqlite`，所有业务 SQL 必须通过公共端口的参数绑定方法执行。

- `navigation.types.ts` 的 `TabKey`。
- `navigation.constants.ts` 的顺序、索引、菜单项、路径识别和主操作。
- `app/(tabs)/_layout.tsx` 的 `Tabs.Screen`。
- 新 Tab 对应的 `app/(tabs)/<name>` 路由目录和 Feature Screen。

### 7.1 当前脚本和配置现状
