## 2. 基础约定

### 2.1 地址与认证

- 本文路径相对于现有共享客户端的 API base URL，例如 `/todos`，不得再重复拼接 `/api`。
- 请求为 JSON；认证使用 `Authorization: Bearer <token>`，遵循实际会话机制，不在本稿另设 Token 有效期。
- 所有读取、写入、幂等记录、游标和快照按当前认证用户隔离。
- 所有者由服务端认证上下文确定；请求正文不允许传入 `user_id` 或 `owner_user_id` 指定归属。
- 当前客户端的 `X-Device-Id` 只在部分认证链路附加，不能声称待办已具备设备标识上传。未来若需要源设备信息，另行明确字段；本契约不依赖它进行鉴权。

### 2.2 身份与命名

| 名称 | 类型 | 含义 |
| --- | --- | --- |
| `id` | 正整数 | 服务端待办 ID，路径参数使用此值 |
| `client_id` | UUID 字符串 | 首次本地创建时分配，重试保持不变；同用户唯一 |
| `version` | 正整数 | 单条服务端版本；创建为 1，实际变更递增，无变化不递增 |
| `expected_version` | 正整数 | 修改/删除基础版本；不匹配则冲突 |
| `operation_id` | UUID 字符串 | 逻辑写操作身份，用于结果未知后的相同请求重试 |
| `change_seq` | 十进制字符串 | 当前用户变更流内部序号；字符串避免大整数精度丢失 |

客户端本地身份使用 `clientId`，获得服务端 `id` 后不替换列表 key。客户端与 API 的 camelCase/snake_case 转换由独立适配层完成。

本稿中的数值 ID和 version 必须落在 JavaScript 最大安全整数范围内，服务端和客户端都校验边界；超出时应先升级契约为字符串表示，不能由 JSON 解析静默丢失精度。change_seq 始终按十进制字符串传输。

接口拒绝未知写入字段，不允许任意 JSON 属性直接映射数据库列。读响应中的服务器归属字段仅供校验，不能当作客户端授权来源。

### 2.3 草案参数

| 参数 | 建议值 / 状态 |
| --- | --- |
| 正文最大长度 | 4000 个 Unicode 码点，与逻辑层草案一致；最终容量评审可统一调整 |
| 查询 `limit` | 默认 50，最大 200 |
| 单次批量项目数 | 1–100，超限拒绝，不静默截断 |
| 幂等结果保存窗口 | 至少 7 天，正式 SLA 在后端立项时确定 |
| 快照有效期 | 立项确定；超期返回明确错误并从头建立快照 |
| 变更记录 / 删除墓碑保留期 | 立项确定，必须支持游标过期后的完整恢复 |

以上是待评审参数，不是现有服务限制。若正式值改变，客户端校验、错误文案和配套文档需同步。

## 3. 字段契约

### 3.1 单条资源 DTO

| 字段 | 格式 | 含义 / 写入规则 |
| --- | --- | --- |
| `id` | 正整数 | 服务端分配，只读 |
| `client_id` | UUID | 创建必传，后续不可修改 |
| `user_id` | 正整数 | 服务端认证归属，只读 |
| `body` | 非空字符串 | 创建必传，后续可改；换行规范化为 LF，用 trim 判断空白，保留正文空格 |
| `priority` | `low / normal / high` | 默认 normal；拒绝旧 `medium` 值，迁移时映射为 normal |
| `is_completed` | 布尔 | 默认 false，使用明确目标值 |
| `completed_at` | UTC RFC 3339 或 null | 完成时间，规则见 §3.3 |
| `is_starred` | 布尔 | 默认 false |
| `is_pinned` | 布尔 | 默认 false |
| `date_id` | `YYYY-MM-DD` | 必传真实公历日期，不转换为 UTC 日期 |
| `start_time` | `HH:mm` 或 null | 00:00–23:59，每分钟都可取值 |
| `end_time` | `HH:mm` 或 null | 依赖 start_time，且同日不早于开始 |
| `time_zone` | IANA 标识或 null | 设备时区参考；不隐含固定时区绝对时刻承诺 |
| `reminder_enabled` | 布尔 | 默认 true，只表达用户意愿，不保证任何设备已调度 |
| `created_at` | UTC RFC 3339 | 客户端首次本地保存时间，创建必传；格式校验后存储且后续不可改 |
| `updated_at` | UTC RFC 3339 | 服务端实际变更时间，服务端生成，只读 |
| `version` | 正整数 | 服务端条件提交版本，只读 |
| `deleted_at` | UTC RFC 3339 或 null | 删除墓碑时间，服务端生成，只读 |

客户端上传 `created_at` 用于保留离线创建顺序，服务端另存接收/审计时间。不能把客户端时间用于鉴权、版本决胜或增量游标；设备时钟不准会影响用户看到的创建顺序，但不会破坏并发保护。

单条资源示例：

```json
{
  "id": 123,
  "client_id": "c0d91284-e090-41a9-9bd5-ce39610b20b3",
  "user_id": 42,
  "body": "准备会议材料\n整理本周进度",
  "priority": "normal",
  "is_completed": false,
  "completed_at": null,
  "is_starred": true,
  "is_pinned": false,
  "date_id": "2026-09-18",
  "start_time": "09:01",
  "end_time": "09:37",
  "time_zone": "Asia/Shanghai",
  "reminder_enabled": true,
  "created_at": "2026-09-18T00:50:00.000Z",
  "updated_at": "2026-09-18T00:50:03.000Z",
  "version": 1,
  "deleted_at": null
}
```

### 3.2 禁止上传或保存的衍生/设备字段

- 标题、筛选状态、五色显示状态、卡片色值、搜索词、排序模式和批量选中集合。
- 系统日历事件 ID、目标日历 ID、通知调度 ID、权限结果和某设备是否实际调度成功。
- 本地版本、待上传序号、队列重试错误、表单 sessionId 和草稿快照。

关联笔记、循环规则、提前提醒参数、服务端推送令牌本期不定义；不能以这些字段已预留为理由顺带实现相关能力。系统通知调度依然属于设备平台任务，后端不调用系统日历，不直接承诺本地提醒触达。

### 3.3 完成与时间戳

- false→true：客户端提交 `is_completed: true` 和本地完成操作时间 `completed_at`；时间仅表达业务事实，不用于并发顺序。省略时可由服务端使用当前时间补齐。
- true→false：服务端清空完成时间；客户端应同时传 null。
- 同值完成请求：不重新盖章，不改变完成时间；不允许单独修改 `completed_at`。
- 新增时可带已完成状态，覆盖离线新建后勾选、尚未首次上传的情况；false 时 completed_at 必须为空。
- 服务端返回 accepted 完成时间作为同步事实。卡片当日/隔日显示依然由所属 date_id 决定。
- `created_at` 永不因编辑、重试、映射服务端 ID而变化。`updated_at` 和 version 只在业务字段有实际变化时更新。

### 3.4 PATCH 省略与清除

省略字段表示保持原值；null 只用于允许清除的字段，不能清空 body、date_id、priority 或布尔值。服务端在合并后的完整候选实体上校验。

清除开始时间需要同时提交 `start_time: null` 和 `end_time: null`；仅提交开始为空而原结束仍有值则返回字段组合错误，不能留下悬空结束时间。清除结束不影响开始。结束等于开始允许，早于开始拒绝，不自动跨日。

小时 00–23、分钟 00–59，**1 分钟步进**；例如 09:01、09:37 均合法。不得增加分钟模 5 的校验，不默默四舍五入。纯日期待办不制造 00:00 开始时间，表示全天。

`time_zone` 非空时校验 IANA 标识；客户端无法捕获时允许 null，不能擅自补成 UTC 或 Asia/Shanghai。跨设备固定时区及夏令时语义仍待平台立项决定。

## 4. 通用响应、校验与幂等

### 4.1 写入成功

创建/更新使用统一包装，DTO 结构见 §3.1：

```json
{
  "data": {
    "id": 123,
    "client_id": "c0d91284-e090-41a9-9bd5-ce39610b20b3",
    "user_id": 42,
    "body": "准备会议材料\n整理本周进度",
    "priority": "normal",
    "is_completed": false,
    "completed_at": null,
    "is_starred": true,
    "is_pinned": false,
    "date_id": "2026-09-18",
    "start_time": "09:01",
    "end_time": "09:37",
    "time_zone": "Asia/Shanghai",
    "reminder_enabled": true,
    "created_at": "2026-09-18T00:50:00.000Z",
    "updated_at": "2026-09-18T00:50:03.000Z",
    "version": 1,
    "deleted_at": null
  },
  "meta": {
    "operation_id": "4e5df7ef-f13f-41ca-879d-c80205efc89a",
    "replayed": false,
    "changed": true
  }
}
```

服务器先持久化事务和幂等结果再回应；超时不代表服务器未保存。`replayed` 表示复用原操作结果，`changed` 表示此次逻辑操作是否有实际业务变更。

### 4.2 幂等规则

所有写请求携带 `Idempotency-Key: <operation_id>`；批量操作另有项目 operation_id，见 §9。

1. 幂等命名空间按认证用户隔离，记录 method、规范化路径、请求体摘要和结果。
2. 同操作 ID、同指纹重试返回原结果，且不重复写入或递增版本。重放结果可能是历史版本，客户端不能直接覆盖较新镜像。
3. 同操作 ID用于不同请求返回 409 `IDEMPOTENCY_KEY_REUSED`，不执行新请求。
4. 幂等命中检查优先于基础版本检查，避免已经成功的操作重试因旧版本而假冲突。
5. 同键并发处理中返回 409 `OPERATION_IN_PROGRESS` 与 `Retry-After`；相同请求延后重试，不生成新键。
6. `client_id` 同用户唯一约束作为创建第二道保护。不同键再次创建同 client_id 返回 409 `CLIENT_ID_EXISTS`，提供其服务端 ID及是否已删除；不能盲目生成新 client_id。
7. 删除后该 client_id 不能再次创建，唯一身份索引/最小删除身份账本至少保留至账号删除；裁剪变更流墓碑不等于释放身份。
8. 7 天只是建议最小结果窗口。超窗的未知结果先查询资源或进入人工处理，不靠换新键猜测成功；版本校验仍防止旧更新覆盖，创建唯一身份仍防重复。

明确成功或确定字段/冲突结果可缓存；暂时性网络和服务器失败允许原请求继续重试。修正字段或重新处理冲突后属于新逻辑操作，使用新键和最新基础版本。

### 4.3 条件提交

每个修改/删除请求必须提供 expected_version。服务端在事务内按用户和 ID读取、验证版本，再比较候选值；版本不匹配则返回冲突及当前资源，不执行任何部分写入。

不以客户端 updated_at 较大为理由覆盖。无变化且版本匹配返回成功，changed=false，version、updated_at 和变更流均不刷新。

## 5. 创建：POST /todos

请求头含认证和幂等键，成功首次返回 201。创建 body、client_id、date_id、created_at 必传，其余字段使用 §3 默认值。

```json
{
  "client_id": "c0d91284-e090-41a9-9bd5-ce39610b20b3",
  "body": "准备会议材料\n整理本周进度",
  "priority": "normal",
  "is_completed": false,
  "completed_at": null,
  "is_starred": true,
  "is_pinned": false,
  "date_id": "2026-09-18",
  "start_time": "09:01",
  "end_time": "09:37",
  "time_zone": "Asia/Shanghai",
  "reminder_enabled": true,
  "created_at": "2026-09-18T00:50:00.000Z"

```

响应使用 §4.1 格式。首次版本为 1，归属从登录身份确定。相同幂等键重放保持原业务结果与原成功状态码，meta.replayed=true。

新增前不存在服务端版本。未首次上传就继续本地编辑时，只有尚未发送的创建候选可合并为最新内容；已经发出的请求必须冻结，以原指纹重试，后续编辑等待创建回执后另发 PATCH。

## 6. 列表查询：GET /todos

### 6.1 参数

| 参数 | 规则 |
| --- | --- |
| `date_from`、`date_to` | 可选、含首尾的有效日期；同日查询两者相同；起始不得晚于结束 |
| `limit` | 默认 50，1–200 |
| `cursor` | 可选、不透明分页游标；后续页使用服务器返回值 |
| `snapshot_token` | 首次返回后后续页原样携带，与游标和日期条件绑定 |
| `client_id` | 可选精确身份恢复查询，见 §7.1；与日期范围、分页参数互斥 |

未提供日期范围时表示当前用户全量活动待办分页，是重建同步镜像的入口。服务端不按自己的“今天”默认截断数据，不返回已删除 DTO作为活动列表。

本接口不提供 pending/inProgress/expired 参数；时间状态依赖设备本地时钟，由客户端在完整本地数据上推导。分页排序使用稳定 id 升序，属于传输次序，不替代界面时间/优先级排序。

### 6.2 返回与快照一致性

响应为：`data`（DTO 数组），`page`（next_cursor、has_more、snapshot_token），`sync`（完整快照对应的 changes_cursor）。无数据返回空数组，不造数据。

```json
{
  "data": [],
  "page": {
    "next_cursor": null,
    "has_more": false,
    "snapshot_token": "opaque-owner-bound-snapshot"
  },
  "sync": {
    "changes_cursor": "opaque-owner-bound-change-cursor"
  }
}
```

后端须提供固定水位对应的完整活动数据视图；分页期间修改、创建或删除不能导致漏行、重行或读取水位之后的混合数据。具体实现可用版本历史重建或物化快照，立项时选择；仅在当前行上加 updated_at≤水位条件不能满足此契约。

只在**无日期过滤、所有分页完整取得并成功事务应用**之后，客户端才能用 changes_cursor 建立全量同步基线。日期过滤结果用于查询，不能据此清除其他日期记录、移动全局游标或宣称全量同步完成。

next_cursor、snapshot_token 绑定用户、日期条件、分页参数及契约版本；篡改/改变条件返回 400，过期返回 410 `SNAPSHOT_EXPIRED`。快照过期时丢弃未应用的暂存分页并重新建立快照，保留本地未同步修改。

## 7. 单条查询与更新

### 7.1 GET /todos/{id}

活动记录返回 200 `{ "data": <TodoDTO> }`。当前用户已删除记录返回 410 `TODO_DELETED` 及该用户的最小墓碑，便于结果未知恢复。不存在或不属于当前用户统一返回 404 `TODO_NOT_FOUND`，不泄露他人资源。

可使用 `GET /todos?client_id=<UUID>` 做创建结果恢复：该参数与日期分页互斥，精确查询当前用户对应活动 DTO；已删除返回 410 及最小墓碑，不存在返回 404。这个精确查询扩展属于本列表接口预留，不新增旁路认证接口。

### 7.2 PATCH /todos/{id}

expected_version 必传；至少包含一个可修改业务字段。使用明确目标值，不接受 toggle 指令。

```json
{
  "expected_version": 1,
  "body": "准备会议材料\n补充数据截图",
  "end_time": "09:38",
  "is_pinned": true
}
```

成功 200，返回最新 DTO及写入 meta；发生变化版本增至 2。清除时刻示例：

```json
{
  "expected_version": 2,
  "start_time": null,
  "end_time": null
}
```

完成示例：

```json
{
  "expected_version": 3,
  "is_completed": true,
  "completed_at": "2026-09-18T01:40:00.000Z"
}
```

服务端校验合并后的整体实体，事务内写入 DTO、版本、变更流和幂等回执。已经删除的实体拒绝更新，不能自动复活。

## 8. 删除：DELETE /todos/{id}

幂等键通过请求头传递；expected_version 通过查询参数传递，例如 `DELETE /todos/123?expected_version=4`。不依赖 DELETE 请求体兼容性。

成功返回 200：

```json
{
  "data": {
    "id": 123,
    "client_id": "c0d91284-e090-41a9-9bd5-ce39610b20b3",
    "version": 5,
    "deleted_at": "2026-09-18T01:45:00.000Z"
  },
  "meta": {
    "operation_id": "23c4a270-b4eb-4e43-8b62-b9e390439f13",
    "replayed": false,
    "changed": true
  }
}
```

删除不立即移除唯一身份；保留最小墓碑并写变更流。相同键重试返回原成功回执。不同键再次删除已删除资源返回 410 `TODO_DELETED` 与墓碑，客户端可按“目标已删除”完成本地删除意图，不把它当作新删除或重新盖章。

删除确认弹窗与 2 秒倒计时在客户端，不能靠服务端睡眠模拟。服务端不负责清理本设备日历或通知；端上保留平台清理意图，随后独立恢复。

## 9. 批量：POST /todos/batch

### 9.1 请求

一个请求只执行一种 action：`set_starred / set_pinned / delete`。标星/置顶提交共同 value，不接受“全部取反”或“多数态”指令。每项必须有独立 operation_id 和 expected_version。

外层请求头幂等键识别整个固定批次；项目 operation_id 在当前用户的统一操作命名空间去重。一次 1–100 项，不允许重复资源 ID或项目操作 ID；外层与项目操作 ID不得相同。

项目指纹由 action、目标 id、expected_version 和明确目标 value 组成，不包含外层批次键、其他项目或项目位置。这样同一未确定项目重新分批时仍可命中原结果；项目键用于不同 action 或候选值仍拒绝复用。

```json
{
  "action": "set_starred",
  "value": true,
  "items": [
    {
      "operation_id": "89b90a4c-ae4b-4309-9a32-43991837e18a",
      "id": 123,
      "expected_version": 3
    },
    {
      "operation_id": "54bcbff7-8f26-4413-9ef9-24a20b1a2408",
      "id": 124,
      "expected_version": 2
    }
  ]
}
```

delete 不传 value。结构、认证、批次数量错误拒绝整个请求；合法批次按项独立事务和版本判断，允许部分成功。

### 9.2 响应与重试

合法批次返回 200，`results` 与输入顺序一致。每项包括 operation_id、id、status（`succeeded / failed`）、changed，以及成功 data 或失败 error。成功 data 为最新 DTO，delete 为墓碑；失败 error 遵循 §11，可附该用户当前 DTO。外层 summary 提供 succeeded、failed 数量。

客户端不以外层 200 判断全部成功。保存本地修改后，云端失败项仍保留未同步/冲突状态，不回滚已经成功的本地业务操作。

- 整批超时：同外层键、同 body 重试，返回原批次结果；不再次取反。
- 只有未确定的项目需要重新分批：新外层键，仍使用原项目 operation_id 和冻结的原项目指纹。
- 已确定的版本冲突：先处理冲突，新项目 ID和最新 expected_version 形成新操作；原冲突操作不偷偷改 body。
- 服务端暂时性项目失败不永久固化为最终结果；原项目键允许重试。确定的成功、字段错误和冲突可返回已保存结果。

内存首版本地批量事务是全成全败；本节是未来云端提交的逐项结果契约，两者不混同。

## 10. 增量同步：GET /todos/changes

### 10.1 请求和响应

参数为必传 cursor、可选 limit（默认 50，最大 200）。首次完整基线从无日期过滤的 `/todos` 快照取得，不用“最近几天待办”初始化全局同步。

响应 `data` 是按 change_seq 升序的事件数组：

- upsert：包含 change_seq、operation=`upsert`、该事件版本的完整 DTO。
- delete：包含 change_seq、operation=`delete`、服务端 ID、client_id、version、deleted_at，不含被删正文。

示例为删除事件：

```json
{
  "data": [
    {
      "change_seq": "105",
      "operation": "delete",
      "id": 123,
      "client_id": "c0d91284-e090-41a9-9bd5-ce39610b20b3",
      "version": 5,
      "deleted_at": "2026-09-18T01:45:00.000Z"
    }
  ],
  "page": {
    "next_cursor": "opaque-next-change-cursor",
    "has_more": false
  }
}
```

服务端游标不可由客户端拼接 change_seq 替代；绑定用户、契约版本、分页水位和已应用位置。空变更也返回可持久化的 next_cursor。has_more=true 时继续取同轮水位内下一页，耗尽后再开始新一轮。

### 10.2 不漏变更的后端要求

实体写入、版本递增、变更流和幂等回执必须在同一事务提交。每个用户的水位需按提交顺序推进；仅调用普通数据库 sequence 后并发提交可能出现较小序号晚提交，被已推进游标漏掉。

立项时可选择用户级事务锁与事务内计数器，或等价的可靠提交序列机制；不能用客户端时钟或 updated_at 时间窗口替代。事件 DTO必须是对应事件版本快照，不能把历史事件拼成当前行的新内容。

### 10.3 端上应用与删除防复活

一次分页的变更应用及 next_cursor 写入同一本地事务，失败不推进游标；重复页按版本/事件身份幂等处理。更旧 DTO不能覆盖新镜像。

收到云端数据时，有未确认本地编辑或删除意图的记录不能直接被替换。保留本地候选与基础版本，进行冲突或回执匹配；不得把拉取成功当作所有本地修改已上传。

云端删除与本地编辑并发时保留未提交候选供用户恢复处理，不自动复活原资源。若用户后续决定复制为新待办，须明确操作并分配新 client_id。

### 10.4 游标过期与全量恢复

变更/墓碑被裁剪或游标版本失效时返回 410 `SYNC_CURSOR_EXPIRED`。客户端建立新完整快照，暂存所有分页，保留未同步候选与本地删除墓碑，再原子对账与保存新游标。

仅对“已有服务端身份且本地无待提交修改”的活动镜像，完整快照中缺失才可视为云端已不存在；不能删除未上传新建、待上传编辑或本地删除意图。部分分页、日期筛选、认证失败和网络失败均不能证明记录已被删除。

## 11. 错误契约

通用失败示例：

```json
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "结束时间不能早于开始时间",
    "request_id": "opaque-request-id",
    "fields": [
      {
        "field": "end_time",
        "code": "END_BEFORE_START",
        "message": "结束时间不能早于开始时间"
      }
    ]
  }
}
```

版本冲突返回 error.code=`VERSION_CONFLICT`，并附 `current`（仅当前用户 DTO）和 current_version；不存在/他人资源不附数据。错误文本不得包含 SQL、堆栈、凭据或被删正文，客户端显示可理解文案而非原始服务异常。

| HTTP | code | 端上处理 |
| --- | --- | --- |
| 400 | `INVALID_REQUEST / INVALID_CURSOR` | 修正结构/参数；不自动重试原错误 |
| 401 | `UNAUTHENTICATED` | 保留本地数据，暂停当前用户任务，按现有认证流程处理 |
| 403 | `ACTION_FORBIDDEN` | 保留本地，明确禁止；不无限重试 |
| 404 | `TODO_NOT_FOUND` | 区分未知创建结果和已有映射丢失，不自动新建替代 |
| 409 | `VERSION_CONFLICT` | 保留本地候选、基础及服务器当前值，进入冲突处理 |
| 409 | `CLIENT_ID_EXISTS / IDEMPOTENCY_KEY_REUSED` | 查询/对账已有身份或检查错误复用，不换 ID规避 |
| 409 | `OPERATION_IN_PROGRESS` | 同键同请求按 Retry-After 重试 |
| 410 | `TODO_DELETED` | 应用删除事实；并发本地编辑保留候选 |
| 410 | `SNAPSHOT_EXPIRED / SYNC_CURSOR_EXPIRED` | 重建完整快照，保留待提交修改 |
| 422 | `VALIDATION_FAILED` | 映射字段错误；未同步数据保留 |
| 429 | `RATE_LIMITED` | 遵循 Retry-After，同键退避重试 |
| 500 / 502 / 503 / 504 | `INTERNAL_ERROR / TEMPORARILY_UNAVAILABLE` | 保留本地候选，同键同指纹退避重试 |
| 无 HTTP 响应 | 超时、断网、请求被中止 | 结果可能未知，不能据此判定服务器未写入 |

字段错误至少覆盖 BODY_REQUIRED、BODY_TOO_LONG、INVALID_DATE、INVALID_TIME、END_WITHOUT_START、END_BEFORE_START、INVALID_PRIORITY、INVALID_TIME_ZONE、INVALID_COMPLETED_AT。所有校验针对合并后候选实体。

## 12. 客户端同步编排预留

1. 本地事务写业务实体、递增 localSequence，并记录待提交意图；持久化未立项前不把内存数据当作可靠 outbox。
2. 队列按 owner 与 client_id 串行发送，保存请求的 operation_id、基础服务端版本、固定字段集合和发送时 localSequence。
3. 尚未发送的同实体编辑可合并；已发出的请求不能改变指纹。新修改排在其后，不复用旧键提交新 body。
4. 发送前校验当前身份及会话代次；账号变化则暂停旧账号任务，不能由 HTTP 拦截器用新 Token发送旧账号数据。
5. 回包校验资源 ID、client_id、用户、版本、字段和请求关联。401 后不把旧请求直接换成新账号重试。
6. 用请求捕获的序号确认上传；若本地还有更高序号，保留较新的本地实体及待同步状态，只更新允许的映射/基础镜像。
7. 成功写回包不推进增量拉取游标；只有完整变化页事务应用后才能推进。
8. 版本冲突保留候选与基础，禁止自动 LWW 覆盖；冲突恢复 UI另立方案，不在本次文档任务中新增弹窗。

未上传创建后直接删除：如果确认从未发送，可在本地事务撤销创建意图并完成平台清理；只要创建已发送且结果未知，就先用原幂等键恢复结果或按 client_id 查询，再按获得的版本提交删除。不能简单删队列后让服务器残留活动记录。

具体队列任务名称、取消上传后的待同步语义、游客转账号和登出清理在实现任务中评审。无论队列或平台失败，本地待办和输入都保留。

## 13. 后端模型与迁移清单

建议独立 `todos` 模型、用户变更流和幂等结果记录，实际数据库方案以后端仓库为准，本期不执行 SQL或生成迁移。

| 旧草案 / 缺口 | 后续要求 |
| --- | --- |
| 只有 `title` | 以 body 为事实；标题派生，历史 title 如何迁移需验证真实存量 |
| `due_date` 可空 | date_id 业务必填；空历史日期回填策略需明确，不能一律设今天 |
| `priority = medium` | 映射 normal，约束 low/normal/high |
| 缺少 start/end | 存本地民用时刻，不默默转换 UTC；检查时刻组合及顺序 |
| 缺少 completed_at、starred/pinned、reminder_enabled | 增事实字段及一致默认值 |
| 缺少 time_zone | 允许参考时区空值，不虚构创建地 |
| 缺少 client_id、version、deleted_at | 同用户唯一身份、条件写入、删除账本 |
| 旧时间字段及默认 NOW | 区分客户端业务创建时间与服务端接收/变更时间，核查真实时区类型 |
| 缺少变更流 | 与实体同事务的可靠提交序列、事件版本快照、用户级水位 |
| 缺少幂等回执 | 用户隔离、请求指纹、并发同键及批量项目结果 |

建议索引：`(user_id, client_id)` 唯一、`(user_id, date_id, id)` 活动查询、`(user_id, change_seq)` 增量、`(user_id, operation_id)` 幂等。所有修改和读取都包含归属条件，防止仅凭 id 访问他人资源。

版本与 change_seq 不能靠 JS 浮点无限递增；服务端确定整数范围，DTO change_seq 为字符串。时间字段格式和完成事实在客户端、数据库及 API 中一致，UTC 时间戳与民用日期不能混为一列。

## 14. 后续联调验收

| 场景 | 必须证明的结果 |
| --- | --- |
| 创建请求已提交但响应丢失 | 原键重试同一 id/client_id，不重复创建 |
| 同键不同 body / 并发同键 | 拒绝复用 / 明确处理中，不执行两次 |
| 删除后再次创建同 client_id | 不复活，返回既有身份冲突 |
| 09:01、09:37、23:59 | 均接受，不做模 5 校验或舍入 |
| 无开始有结束、非法日期 | 422，未写任何字段 |
| PATCH 省略 / null | 省略保留；合法 null 清除；非法组合拒绝 |
| 无变化写入 | version、updated_at、change 流不刷新 |
| 两设备相同基础版本修改 | 一次成功，另一次冲突，本地候选仍在 |
| 旧写回包到达时本地又有修改 | 新内容和待同步状态不被抹除 |
| 批量部分成功及未知结果重试 | 逐项确认，成功项不重复变更，明确目标值不反复取反 |
| 快照分页期间创建/修改/删除 | 固定水位完整无漏行；之后增量覆盖后续变化 |
| 较小 change_seq 事务晚提交 | 序列设计保证不会被游标跳过 |
| 修改日期 A→B | 完整变更反映新事实，日期过滤不被当作全量删除依据 |
| 游标过期、删除已裁剪 | 全量恢复能移除无本地修改的旧镜像，保留待提交候选 |
| 云端删除与本地编辑并发 | 不自动复活，保留候选处理 |
| 账号切换 / 他人 ID / 他人游标 | 不串账号、不泄露数据，旧回包不作用新会话 |
| 只取部分页、断网或 401 | 不清空本地、不推进错误游标 |
| 平台权限拒绝或调度失败 | 不影响本地及云端待办事实 |

本次仅检查文档结构、字段映射、规则一致性、链接和差异。未请求真实接口、执行数据库迁移、运行应用测试、构建或设备验收，不宣称接口可用或可发布。

## 15. 立项前必须确定的事项

- 是否启用云同步、默认策略、游客数据迁移和旧账号任务保留。
- 真实后端待办表/路由现状及存量数据迁移，不以旧教学/规划 SQL作已部署证据。
- 幂等窗口、快照有效期、增量事件和删除账本保留/裁剪；明确超期恢复 SLA。
- 稳定快照实现和用户级提交序列机制，不能留给接口调用方猜测。
- 跨设备时区、夏令时、完成后的提醒/日程处理、提前提醒量；当前只存意愿和民用时间。
- 多设备冲突恢复产品流程、单个关联笔记和循环实例的未来扩展。
