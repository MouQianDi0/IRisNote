## 1. 目标与实施边界

逻辑层承接界面设计中的交互规则，使新增、编辑、完成切换、筛选、排序和批量操作使用同一套业务判断。最初内存版本已完成；本次将应用仓库接入统一 SQLite 数据库，事务提交成功后才更新页面快照。Node SQLite 隔离文件测试覆盖关闭重开恢复；Expo 真机杀进程恢复仍待用户主动验收。云同步尚未实现。

### 1.1 首版范围

- 待办模型及字段校验。
- 新增、编辑、确认保存、取消、遮罩和系统返回路径。
- 单条完成切换、标星、置顶、删除。
- 按日期、状态、关键词筛选及三种排序。
- 长按批量选择、当前结果全选、批量标星、置顶和删除。
- 设备本地时间下的状态推导与跨午夜刷新。
- 所有者隔离、旧异步结果保护及开发种子数据隔离。
- SQLite 本地持久化、稳定游客命名空间和异步事务回执。

### 1.2 后续独立立项

独立云端 API 与同步、系统日历写入、普通本地通知、笔记关联和循环待办仍需独立立项。本地持久化不请求这些权限，也不把待办写入笔记表或套用笔记上传任务。

本次持久化改造保留现有界面布局、颜色、组件尺寸和保存中状态，不新增依赖或后端实现。界面结构和 dp 规格以界面基线为准。此前只在进程内存在的数据没有可靠迁移来源，首次升级的待办表为空。

## 3. 分层与依赖方向

```text
页面 / 业务组件
  ├─ 查询控制器：日期、筛选、搜索、排序、批量选择
  └─ 表单会话：新增 / 编辑、修改字段、保存锁、退出原因
             ↓
       待办业务服务
         ├─ 纯领域函数：校验、标题、状态、筛选、排序
         └─ TodoRepository：SQLite 实现 + 同步内存测试适配器
                    ↓
           统一 ApplicationDatabase 事务队列 / local_todos
                    ↓（后续）
           同步编排 / 日历适配 / 通知适配
```

依赖约束：

1. 公共 `BodyInput`、`TimePickerField` 和 `AppCalendar` 只管理输入和展示，不导入待办仓库、HTTP、权限或同步队列。
2. 页面通过业务入口发出命令，不直接修改实体对象；领域函数不导入 React、路由、网络或数据库。
3. 业务服务依赖仓库接口，调用方必须等待写入回执；内存测试适配器仍可同步返回。列表/get 读取已提交快照，写入事务重新读取数据库最新值。
4. 状态推导接收明确的当前时刻和本地日期上下文，不能在比较器内反复读取系统时间。
5. 外部能力失败不得回滚已经成功的待办保存。

## 4. 数据模型

下列名称为逻辑层建议命名；API 使用 snake_case，通过明确映射转换。

### 4.1 业务实体

| 字段 | 类型 / 默认值 | 规则 |
| --- | --- | --- |
| `clientId` | UUID 字符串 | 新会话分配一次，列表 key 和本地身份稳定；关联服务端后不换 key |
| `ownerKey` | 所有者命名空间 | 登录账号使用 `user:<用户ID>`；游客使用独立本机命名空间，不能与账号混用 |
| `body` | 字符串 | 正文非空；首版建议上限 4000 个 Unicode 码点，API 草案同值 |
| `priority` | `low / normal / high`；默认 `normal` | 对应不重要、正常、重要；旧表的 `medium` 需迁移映射 |
| `isCompleted` | 布尔；默认 `false` | 事实字段，不保存推导筛选态 |
| `completedAt` | UTC RFC 3339 时间或空 | 未完成为空；完成时记录完成操作时间，取消完成时清空 |
| `isStarred` | 布尔；默认 `false` | 不形成额外排序层 |
| `isPinned` | 布尔；默认 `false` | 影响排序，置顶组仍用当前排序规则 |
| `dateId` | 本地 `YYYY-MM-DD` | 必须是有效公历日期 |
| `startTime` | `HH:mm` 或空 | 任意分钟 00–59，1 分钟步进，不含秒 |
| `endTime` | `HH:mm` 或空 | 有结束必须有开始；同日且不得早于开始 |
| `timeZone` | IANA 时区标识或空 | 捕获设备时区作为参考；不可获取时首版不阻断保存 |
| `reminderEnabled` | 布尔；默认 `true` | 首版只保存意愿，不实际提醒 |
| `createdAt` | UTC RFC 3339 时间 | 首次合法保存尝试时生成并冻结，失败重试保持，编辑不改变 |
| `updatedAt` | UTC RFC 3339 时间 | 有实际业务变化时更新，无变化保存不刷新 |

正文统一将 CRLF/CR 转为 LF，保留用户的段落和空格；用 `body.trim()` 判断是否为空，不因校验修改正文。长度按 Unicode 码点计数，不直接把 JavaScript UTF-16 长度当成码点数；后续 `BodyInput` 的计数和限制需与业务校验一致。

标题从 `body.trim()` 的第一行提取，不独立保存，不允许标题与正文出现两份事实。显示省略由卡片负责，搜索使用完整正文。

新建日期取打开时的有效选中日期；没有选中值时取打开时的今天。打开后跨午夜不擅自改变表单日期。开始与结束时间默认均为空，不自动套用示意图中的 09:00–09:30。

### 4.2 本地并发与同步元数据

| 字段 | 首版 / 后续 | 用途 |
| --- | --- | --- |
| `localVersion` | 首版 | 每次实际写入递增；防止旧表单或旧命令覆盖新数据 |
| `serverId`、`serverVersion` | 后续 | 服务端映射及条件提交依据 |
| `localSequence`、`acknowledgedSequence` | 后续 | 判定待上传修改，避免旧回包误清除新修改 |
| `syncStatus`、`lastSyncError` | 后续 | 队列、失败和冲突状态；不冒充首版已有同步 |
| `deletedAt`、删除操作 ID | 后续 | 离线删除墓碑与重试 |

首版不要求云端字段具备有效值。云端身份以实际登录账号为准，游客数据迁移到账号必须另行明确，不能自动并入。

### 4.3 设备本地平台元数据（后续）

系统日历事件 ID、目标日历、写入意愿与状态，通知调度 ID、调度版本与失败状态，均按所有者和设备保存。它们不随待办上传，也不能用另一设备的 ID 更新或删除本设备事件。

关联笔记 ID与展示快照、循环规则本期不接入；后续需独立评审关联归属、删除行为、重复实例身份及 API 字段。

### 4.4 API 映射与字段权威

| 逻辑层 | API |
| --- | --- |
| `clientId`、登录态 `ownerKey` | `client_id`、响应只读 `user_id`；游客不能直接上传 |
| `body`、`priority` | `body`、`priority` |
| `isCompleted`、`completedAt` | `is_completed`、`completed_at` |
| `isStarred`、`isPinned` | `is_starred`、`is_pinned` |
| `dateId`、`startTime`、`endTime`、`timeZone` | `date_id`、`start_time`、`end_time`、`time_zone` |
| `reminderEnabled` | `reminder_enabled` |
| `createdAt`、`updatedAt` | `created_at`、`updated_at` |
| `serverId`、`serverVersion`、同步删除事实 | `id`、`version`、`deleted_at` |

首次上传保留客户端创建时间，不能因云端回执改变默认创建顺序。云端启用后，服务端更新时间和接受的完成时间进入基础镜像；本地尚有新修改时不覆盖本地候选。version 是服务端并发依据，localVersion 是本地并发依据，两者不能相互替代；设备平台元数据不映射到 API。

## 5. 校验与时间语义

### 5.1 保存校验顺序

1. 校验当前所有者及会话是否仍有效。
2. 校验正文非空和长度。
3. 校验日期格式及真实日期，拒绝 2026-02-30 等自动进位结果。
4. 校验时间严格为 `00:00–23:59` 的 `HH:mm`；允许 09:01、09:37 等所有分钟，不做 5 分钟对齐。
5. 有结束无开始时拒绝；结束早于开始时拒绝。相等允许，表示零时长，不自动改成下一日。
6. 校验枚举、布尔字段和本地版本，最后执行一次仓库事务。

日期选择器不能替代业务校验。禁止通过 UTC 字符串截取日期，也不把 `new Date("YYYY-MM-DD")` 当作本地日期合成方法。

### 5.2 清除、日期变更与未完成输入

- 清除开始时间同时清除结束时间；清除结束时间保留开始时间。
- 改变日期保留已设置的时刻，重新校验，不自动跨日。
- 子日期/时间面板只提交到表单；取消子面板不修改表单，也不保存待办。
- 遮罩或系统返回遇到非空但不合法的表单时，保持父弹窗打开并原位提示；不能绕过时间校验自动保存。
- 编辑清空正文后，确认、遮罩、系统返回均不保存、不删除，弹窗保持打开；显式取消可以丢弃该修改并退出。

### 5.3 时区边界

首版遵循界面基线：所属日期和时刻按当前设备本地时间解释，设备时区变更后重新推导状态。保存时捕获的 `timeZone` 是参考信息，不代表已实现“固定原时区绝对时刻”。API 只保存民用日期、时刻及参考时区，不把日期转换为 UTC 午夜。

跨设备提醒是否固定创建地时区，夏令时缺失/重复时刻如何处理，必须在日历和通知立项前决定。届时需明确异常提示与解析策略，不能依赖系统自动进位或猜测偏移。本期不生成日历事件、绝对提醒时刻或 `startAt` 事实字段。

## 6. 推导状态与刷新

一次查询固定使用同一份 `now`、本地今天和本地时刻上下文，先判断完成，再判断未完成状态。

### 6.1 筛选状态

| 顺序 | 条件 | 结果 |
| --- | --- | --- |
| 1 | `isCompleted = true` | `completed`；只有“全部”显示，三个未完成筛选均排除 |
| 2 | 日期早于今天；或等于今天且结束时刻严格早于当前时刻 | `expired` |
| 3 | 日期晚于今天；或等于今天且开始时刻严格晚于当前时刻 | `pending` |
| 4 | 日期等于今天且不满足上述条件 | `inProgress` |

时间边界按完整当前时刻比较：现在恰好等于开始时间时已进入进行中；恰好等于结束时间时尚未过期，严格超过才过期。只有开始时间的待办当天不会因开始已过而过期；到次日才过期。无时刻待办当天视为进行中。

### 6.2 卡片显示状态

| 业务事实 | 显示状态 / 主题语义 |
| --- | --- |
| 未完成，优先级 low / normal / high | 不重要 / 正常 / 重要色对，包含未完成过期记录 |
| 已完成，所属日期大于等于今天 | 已完成绿色对 |
| 已完成，所属日期早于今天 | 已结束灰色对、标题灰色删除线 |

“已结束”看所属日期，不看 `completedAt` 的日期。五色不是四个筛选状态的一一映射，未完成过期记录仍用其优先级颜色。不保存色值或显示状态。

有开始时间显示铃铛，首版只代表设置了日程时间，即使 `reminderEnabled` 为假也不把铃铛改成已调度承诺；实际提醒状态的展示在通知立项时重新评审。

### 6.3 刷新机制

- 待办页使用一个业务时钟，不为每张卡片创建独立定时器。
- 计算下一次相关状态边界：开始时刻、结束时刻之后的首个时刻、本地午夜；到达边界重新查询。
- 分钟刷新作为补偿，避免设备改时钟后长期显示旧状态；应用返回前台立即刷新当前时刻与时区。
- 后台暂停页面定时器，卸载清理订阅；重新进入页面不沿用旧的“今天”。
- 只是刷新推导值，不改实体时间戳，也不触发持久化或上传。
- 查询日期的空值表示“今天”，随午夜变化；用户明确选中的日期保持原值。日期轨道的视觉刷新与业务时钟接入在后续 UI 实现时审阅。

## 7. 表单会话与退出状态机

### 7.1 会话内容

会话保存 `sessionId`、所有者、创建/编辑模式、稳定 `clientId`、基础实体及版本、表单值、修改字段集合、退出原因、保存状态和会话内已保存记录引用。表单输入不会逐键写入实体或启动云同步。

状态为 `editing → validating → saving → closed`；校验或仓库失败返回 `editing` 并保留全部输入。删除确认状态可返回原编辑状态。旧会话的异步结果不能关闭或修改新的弹窗。

### 7.2 退出矩阵

| 操作 | 创建态 | 编辑态 |
| --- | --- | --- |
| 确认 | 非空且合法则创建一次；成功后关闭 | 合法则提交修改字段；无变化直接关闭 |
| 取消 | 未保存时丢弃输入并关闭；同一创建会话已有记录则进入删除确认 | 丢弃表单修改并关闭；不回滚会话外操作 |
| 遮罩 / 系统返回 | 空白关闭；非空合法则自动保存；非法/失败保持打开 | 有合法变化则自动保存；无变化关闭；空白或非法保持打开 |
| 标题栏删除 | 未保存直接关闭；已有会话记录进入删除确认 | 删除该实体，走共享确认弹窗 |

保存时锁定标题栏、底部操作和遮罩关闭，重复命令复用同一个在途结果，不重复创建。父弹窗内打开子选择器或删除确认时，系统返回优先关闭最上层子面板，不穿透触发父表单自动保存。

### 7.3 自动保存记录生命周期

非空正文自动保存产生正式待办，不是可恢复草稿。成功即关闭弹窗并结束创建会话，静默更新列表；之后点击该卡片是新编辑会话，取消不删除原记录。

界面基线 §8.2 的“已有自动保存记录后取消创建需确认删除”，仅适用于仍持有同一创建会话及其已保存记录的恢复场景，不适用于普通列表编辑。首版成功即结束会话，不主动保留这种恢复入口；以后新增恢复入口必须保留确认删除规则。

事务结果以仓库回执为准：实体写入成功后，列表渲染或路由关闭失败不能重新执行创建。恢复时先按已分配 `clientId` 检查回执/实体；复用已保存实体，不生成新 ID。

### 7.4 编辑并发保护

- 记录打开时的基础版本，仅提交修改字段。
- 本地版本变化但变动字段与表单修改不重叠时，读取最新实体并合并后提交。
- 同一字段被双方修改时保持表单和基础快照，返回冲突；不得静默用旧快照覆盖。
- 当前记录已经删除或所有者已切换时禁止保存，不自动重建或转移归属。
- 非表单字段如完成标记，未被当前表单修改就不能随表单旧值提交。

## 8. 仓库契约与命令

### 8.1 仓库能力

仓库提供按所有者列出/获取、稳定 ID 创建、按基础版本更新、删除、批量写入和订阅变更能力。所有写入返回确定的成功回执或结构化错误；UI 不用“弹窗已经关闭”推断事务成功。

内存实现一次操作先验证所有目标和候选值，全部有效后替换集合并广播一次。持久化实现复用该规则，并在公共数据库事务内完成所有写入；任一语句或提交失败时回滚，保留原页面快照。成功提交后才一次性发布结果。

创建对同一所有者的相同 `clientId` 去重，相同请求返回同一实体，不同内容不能覆盖已有实体。版本更新使用比较后写入；无实际变化不更新版本和时间戳。

### 8.2 业务命令

| 命令 | 规则 |
| --- | --- |
| 创建 / 编辑 | 先完成全部校验再提交；失败保留表单 |
| 设置完成 | 提交明确布尔值；false→true 记录完成时间，true→false 清空；相同值为无变化 |
| 设置标星 / 置顶 | 提交明确布尔值，不传“toggle”到仓库或网络 |
| 删除 | 共享确认弹窗 2 秒倒计时完成后提交；失败不关闭表单、不清空选中集合 |
| 批量修改 / 删除 | 本地首版全部成功或全部失败；云端可能逐条失败，见 API 契约 |

列表勾选圈的点击由 UI 阻止冒泡，业务层仍分开完成命令和打开编辑命令。批量模式下完成命令不可用，不能把选择圈当作完成圈。

## 9. 列表查询与排序

### 9.1 查询状态

`selectedDateId`、筛选项、搜索展开状态、关键词、排序模式、批量模式及所选 ID 属于 UI 状态，不写入待办实体。默认：今天、全部、搜索关闭、时间正序、非批量模式。

当前轨道是单日筛选；浏览上一周/下一周只改变轨道可见周，不改变列表查询日期，直到实际选择日期。后续若引入日期范围需新增明确查询类型，不能把单日值偷偷解释成整周。

### 9.2 查询流水线

1. 取当前所有者未删除实体。
2. 按选中日期匹配，空选中值解析为当前今天。
3. 按统一时钟推导状态并过滤。
4. 搜索关键词去首尾空白、做不区分大小写的子串匹配；在完整正文及其标题投影中查找，不增设标题事实字段。
5. 用固定上下文排序并生成视图模型。

收起搜索时清空关键词。无结果时，有有效搜索词显示“无匹配待办”，否则显示“该日期暂无待办”，不补入种子或伪造记录。

### 9.3 确定排序

当前是单日列表，依次比较：

1. 置顶组先于非置顶组。
2. 每组有开始时间先于无开始时间；无时刻记录保持组内末尾。
3. 时间正序/倒序：有时刻组按开始时间升序/降序；同刻及无时刻组按创建时间升序。
4. 优先级模式：有时刻组和无时刻组分别按 high→normal→low；每个优先级内有时刻记录按开始时间升序，再按创建时间升序。无时刻组仍在当前置顶分组末尾，各优先级内按创建顺序。
5. 最终按 `clientId` 字典序升序，确保同时间仍有总顺序。

置顶优先于无时刻末尾规则，因此置顶全天记录仍在非置顶有时刻记录之前。标星不额外分层，不继承笔记排序设计。`updatedAt` 和推导状态变化不作为默认排序键。

## 10. 批量选择与操作

- 长按进入批量模式并选中该项；卡片点击切换选择，不打开编辑。
- 全选覆盖当前过滤结果，所选 ID使用集合去重；退出及系统返回清空选择。
- 用户改变日期、筛选、搜索条件或收起搜索时，退出批量模式并清空选择，防止隐藏记录仍被操作。
- 外部数据变更导致选中记录被删除或不再匹配时，从集合移除；集合为空则退出。
- 全部选中已标星则统一取消标星，否则统一标星；置顶同理。“多数态”按这一全体判断实现，不按数量投票。
- 操作启动时固定 ID、每项基础版本和目标值；保存中锁定相关操作，异步期间不跟随新的筛选重新扩大集合。
- 删除确认显示固定集合数量。确认前发生外部变化时，重新校验；目标已变化则保留/更新选择并提示重审，不静默替换集合。
- 批量标星/置顶成功后保留仍可见的选择；删除成功后清除已删除项，空集合退出。失败保留选择和明确错误。

后续云端逐项返回结果时，本地已成功的业务操作不能因云端部分失败而回滚；失败项保留待同步或冲突状态，不能让用户反复触发“取反”作为重试。

## 11. 账号隔离、错误及种子

### 11.1 所有者生命周期

仓库读取和命令都显式携带 `ownerKey`。账号切换使当前会话代次失效，清空界面查询/选择和该会话的内存快照，按新账号重新初始化；不把旧账号实体改名归入新账号。游客归属也不能冒充已登录账号。

游客使用安装内数据库的固定命名空间 `guest:local`，账号使用 `user:<用户ID>`；切换和登出保留各自落盘数据，回到原所有者时重新读取。游客数据不自动迁入账号；清除应用数据或卸载造成的本地数据删除不在恢复保证内。

异步命令在提交前和回执应用前检查所有者与会话代次。HTTP 认证拦截器只负责附加当前会话凭据，不能替代业务对旧任务归属的检查。

认证加载期间使待办会话失效；加载、写入排队及每次异步 SQL 回执后检查代次。事务已经进入 COMMIT 后发生的切换可能留下原所有者的合法写入，但不会发布到新账号快照或关闭新账号表单。加载失败保持背景，通过重要横幅重试；过期横幅的重试不会重新激活旧账号。

### 11.2 错误分类

| 分类 | 处理 |
| --- | --- |
| 字段校验 | 对应输入原位错误；保留弹窗 |
| 本地保存失败 | 保留全部输入，重要错误横幅，允许原命令重试 |
| 记录删除 / 本地字段冲突 | 保留输入并说明原因；不自动覆盖或复活 |
| 所有者失效 | 禁止向新账号提交旧会话，清理旧 UI |
| 云端 / 平台失败（后续） | 保留本地待办，进入可恢复状态，不回滚 |

服务端原始异常、凭据和正文不进入诊断日志。自动保存成功静默；只在失败时显示必要错误。

### 11.3 种子数据

种子只在显式开发验收开关下初始化一次，使用独立所有者命名空间，不能在正常账号空列表或搜索无结果时自动补入。生产不开启，不上传。

按初始化当天动态生成日期，覆盖：三种未完成优先级、当天完成绿色、历史完成灰色、未完成过期、未来/稍后待进行、全天、仅开始时间、起止时间、标星和置顶。时间变化测试使用固定时钟，不能依赖一组永远不变的旧日期。

## 12. 本地持久化与后续同步、平台预留

### 12.1 持久化

- 迁移 7 创建 `local_todos`，保存全部领域字段及版本和时间戳；`(owner_key, client_id)` 为复合主键，`(owner_key, date_id)` 为查询索引。字段检查覆盖身份格式、日期、时间组合、枚举、布尔值、版本及完成时间关系。
- 数据库连接和迁移由已有 `ApplicationDatabaseProvider` 管理，不在待办功能中另开应用数据库或关闭共享连接。
- 创建、编辑、完成、批量标星/置顶及删除等待同一事务的回执；稳定创建 ID 去重，无变化不写 SQL、不增加版本；更新/删除带所有者和版本条件。
- 查询使用当前所有者的内存快照；每次写入重新读取该所有者全部记录以复用现有领域规则。因此当前写入成本与该所有者待办数量相关，大规模数据的增量读取优化未实施。
- 测试覆盖 Node SQLite 文件关闭重开、数据映射、迁移结构和旧表保留、字段约束、账号隔离、版本冲突、批量回滚及加载/写入与账号切换竞争。未执行应用构建、浏览器、Expo 原生 SQLite 或真机杀进程验收；Web 仍遵循 SDK 57 SQLite 的 Alpha 支持边界。

### 12.2 云同步

保留同步关闭/仅本机模式；是否开启云同步仍需后续立项。开启时遵循：本地实体修改与待上传意图原子记录 → 按所有者和实体串行发送 → 条件提交与幂等重试 → 校验回包 → 按本地序号确认 → 拉取云端变更。

当前上传队列没有待办任务，后续需评审 `todo-sync` 等独立任务类型、处理器、取消/重试语义和用户界面，不直接把数据放入 `note-sync`。具体云端边界见配套 API 文档。

### 12.3 日历和提醒

平台工作在本地保存成功之后按最新实体版本执行；首版适配器不开启，不提前发权限请求。日历事件失败保留待办，提醒修改/删除需取消旧调度并按最新版本重建。

遮罩自动保存不能突然请求权限。没有开始时间不创建事件、不调度提醒；完成待办、取消完成、云端删除对日历/提醒的具体处理在平台立项时评审。删除后平台清理失败需保留本地清理意图，不能丢掉事件/调度 ID再尝试恢复。

平台依赖、权限和 API 在立项时依据项目实际 Expo SDK 57 版本文档确认，本文不新增原生依赖，不改变纯 JS 时间轮盘约束。

## 13. 实施顺序与验证边界

1. 明确模型和领域函数，完成固定时钟下的边界测试。
2. 实现内存仓库、稳定 ID、版本保护和原子批量。
3. 接入 store、表单会话和业务命令。
4. 按界面基线接入列表、弹窗与公共输入/时间组件。
5. 完成项目代码检查；用户主动发起设备交互验收。
6. 本次本地持久化已落地；云同步、日历、通知和笔记关联仍需分别立项。

代码实现任务须按项目规则运行修改前/后的 `npm run typecheck` 及最终 `npm run check`，并检查差异和冲突标记；本地持久化另运行定向 Todo 测试。检查结果与对应基线记录在项目根目录 CHANGELOG.md；这些检查不代替设备交互或应用重启验收。

### 13.1 后续逻辑验收案例

| 场景 | 预期 |
| --- | --- |
| 新建空白，点确认 | 输入错误，未创建 |
| 新建空白，点遮罩 / 返回 | 关闭，未创建 |
| 新建合法正文，点遮罩 / 返回 | 正式待办仅创建一次，静默关闭 |
| 自动保存失败 / 结果恢复 | 输入保留；同 clientId 重试或查回执，不重复 |
| 自动保存后重新打开并取消 | 按编辑取消处理，原记录保留 |
| 编辑清空正文，尝试自动保存 | 保持打开；显式取消可退出 |
| 结束有值但无开始 / 结束早于开始 | 阻止保存 |
| 09:01、09:37、23:59 | 均为合法时刻，不做 5 分钟对齐 |
| 清除开始 | 开始和结束同时清空 |
| 开始等于现在 / 结束等于现在 | 进行中 / 尚未过期；超过结束才过期 |
| 无时刻或仅开始时间，当天→次日 | 当天进行中，次日未完成则过期 |
| 所属历史日期完成 | 灰色已结束，判定不依赖完成时间日期 |
| 表单打开后会话外勾选完成 | 保存未修改字段不覆盖完成结果 |
| 同字段并发修改 / 记录已删除 | 保留输入并报冲突，不覆盖、不复活 |
| 同刻、同创建时间和不同 ID | 排序确定；状态刷新不改变排序键 |
| 批量混合标星状态 | 全部设为 true，再操作全部设为 false |
| 选择后切换日期或搜索条件 | 退出批量并清空集合 |
| 批量事务中任一目标无效 | 本地全部不改，选择保留 |
| 账号切换时旧命令回包 | 不写入/关闭新账号会话 |
| 生产空列表 / 搜索无结果 | 不自动注入种子 |

设备验收另覆盖键盘、窄屏、大字体、手势、父子弹层、系统返回和视觉状态。领域测试与静态检查不能证明这些交互已通过。
