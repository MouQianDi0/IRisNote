## 已交付的接口边界

- 后端提供 `/todos/snapshot`、`/todos/changes`、列表、单条、创建、批量、更新和删除；所有请求按认证用户隔离。
- 客户端以 `client_id`、`operation_id`、`expected_version` 和 `change_seq` 对接。请求写入 outbox 后冻结；重试沿用同一操作身份，之后的本地编辑产生新的序列。
- 本地数据库新增同步镜像、outbox、游标和快照暂存表。全量快照完整接收后原子对账；增量事件与游标同事务落库。
- 同步队列可显示待办待提交项；冲突可采用云端、保留本地重试或另存为新待办。删除冲突不自动复活原身份。

## 建议验收顺序

1. 在隔离测试库执行迁移，检查既有数据、约束、索引和回滚方案。
2. 部署后端，以测试账号验证接口身份隔离、幂等重试和版本冲突。
3. 打开 App 功能门，分别验证在线创建、离线累计、恢复网络、快照补齐和增量游标。
4. 使用两台设备制造同条编辑和云端删除冲突，确认三种处理动作的最终数据。
5. 以实际发布 APK 验证前后台、进程重启、登出换号和提醒调度；静态测试不替代本步骤。
