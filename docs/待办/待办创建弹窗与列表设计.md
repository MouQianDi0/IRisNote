# IRisNote 待办创建弹窗与列表设计

> 文档版本：1.0（2026-09-16）  
> 文档状态：设计规范，尚未实现  
> 适用范围：待办创建入口、创建弹窗、待办列表卡片及其复用组件契约  
> 视觉基线：[IRisNote视觉设计规范](../UI/IRisNote视觉设计规范.md) · [公共组件规范](../UI/公共组件规范.md) · [日历公共组件规范](../UI/日历公共组件规范.md) · [通知渠道适配](../UI/通知渠道适配.md)

## 1. 目标与范围

待办页提供“预设创建待办”操作。用户触发后直接打开“新增待办”弹窗，在同一弹窗内完成正文、日期时间、卡片颜色和关联笔记设置。待办列表沿用笔记卡片的视觉语言，右侧日期轨道继续负责按日期切换和筛选。

本文只定义界面、状态、交互、公共组件边界和后续数据契约，不代表页面、存储、系统日历或通知能力已经实现。

首版设计包含：

- 新增待办弹窗及标题栏操作。
- 可供待办正文和笔记注释复用的公共正文输入组件。
- 公共日期组件与公共时间选择组件的组合方式。
- 公共容器颜色选择器。
- 公共笔记关联组件及本地优先、云端补查流程。
- 取消、确认和点击弹窗外自动保存三种退出路径。
- 参考笔记卡片的待办列表卡片。
- 系统日历读写授权和开始时间提醒的产品边界。

首版不包含：

- 待办后端接口、跨设备同步和冲突处理。
- 重复待办、子任务、多人协作和附件。
- Android Live Updates、iOS Live Activities、鸿蒙实况窗或用重复通知模拟动态通知。
- 日历组件内部增加 agenda、日程标注点、农历或节假日。

## 2. 视觉原则

待办界面遵循现有 HyperOS / miuix 风格：白色分组卡片、连续圆角、克制的主题蓝、浅灰控件底和统一遮罩。主色继续使用 `#007AFF`。业务组件只使用语义 Token，不传入任意颜色覆盖公共组件身份。

| 项目 | 规格 |
| --- | --- |
| 弹窗遮罩 | `hyperScrim`，浅色模式 30% 黑；弹窗外边距 24dp |
| 弹窗卡片 | 白底、连续圆角 24dp、内边距 24dp、最大宽 440dp、最大高可用区域 85% |
| 弹窗标题 | 24sp，Regular，`textPrimary`，不使用粗体建立层级 |
| 列表主文字 | 17sp，Regular，`textPrimary` |
| 辅助正文 | 14sp，Regular，`textSecondary` |
| 元信息 | 13sp，Regular，`textSecondary` |
| 普通控件 | 高 48dp、连续圆角 16dp |
| 输入框 | 连续圆角 16dp、2dp 状态边框、左右内边距 16dp |
| 弹窗底部按钮 | 高 48dp、连续圆角 16dp、左右等宽、间距 10dp |
| 区块纵向间距 | 紧密关联项 12dp；主要区块 16dp |
| 最小触控范围 | iOS 不小于 44×44dp；Android 优先使用 48×48dp |

## 3. 新增待办弹窗

### 3.1 打开方式

待办页的预设创建操作进入现有“新建待办”入口，并立即显示创建弹窗。路由只负责承载弹窗和返回关系，不把同一表单再绘制成第二套全屏页面。

应用内弹窗必须使用共享 `AppModal` / Overlay 体系，使全局横幅仍能位于应用内弹窗上方。键盘展开或屏幕高度不足时，中间表单区域滚动，标题栏和底部按钮保持在弹窗卡片内。

### 3.2 整体布局

```text
遮罩：点击卡片外空白处，按 §8.3 自动保存规则处理

┌────────────────────────────────────────┐  最大宽 440dp
│ 新增待办                    ☆  📌  🗑   │  标题行高 48dp
│                                        │  标题行下 16dp
│ 正文                                   │  标签 14sp
│ ┌────────────────────────────────────┐ │  标签到输入框 8dp
│ │ 输入待办内容                       │ │
│ │                                    │ │  最小高 144dp
│ │                                    │ │
│ └────────────────────────────────────┘ │
│                                        │  下隔 16dp
│ [ 日期：2026年9月16日              > ] │  高 48dp
│                                        │  下隔 12dp
│ [ 开始时间  09:00 ] [ 结束时间  09:30 ] │  高 48dp，间距 10dp
│                                        │  下隔 12dp
│ [ 颜色                               > ] │  高 48dp
│                                        │  下隔 12dp
│ [ 关联笔记                           > ] │  高 48dp

└────────────────────────────────────────┘  圆角 24dp，内边距 24dp
```

### 3.3 标题栏

- 左侧固定显示“新增待办”。
- 右侧按“标星、置顶、垃圾桶”排列，图标分别使用 Lucide `Star`、`Pin`、`Trash2`，视觉尺寸 20dp。
- 每个图标使用 44×44dp 触控区，相邻触控区间隔 4dp。Android 实现可将触控区提升至 48×48dp，但不得改变标题栏视觉节奏。
- 标星和置顶未启用时使用 `textSecondary`；启用后使用主题蓝，并通过无障碍 `selected` 状态表达，不能只靠颜色区分。
- 垃圾桶是当前创建会话的删除入口。没有已保存内容时直接关闭；已有自动保存记录时打开共享删除确认弹窗。红色只用于最终确认删除按钮，标题栏图标保持中性灰色。

## 4. 公共正文输入组件

### 4.1 定位

新增公共正文输入组件，供待办正文和笔记注释复用。组件只管理输入外观、聚焦、错误、禁用、字数提示和无障碍属性，不管理待办保存、笔记保存、草稿或云同步。

建议公共名称为 `BodyInput`，以现有公共 `Input` 的多行能力为基础，不另建第二套输入状态样式。

### 4.2 视觉与状态

- 默认最小高度 144dp，为普通 48dp 输入控件的三倍高度。
- 文字 17sp，顶部和底部内边距 12dp，左右内边距 16dp，文字从左上角开始排列。
- 默认浅灰 `surfaceControl` 背景，2dp 透明边框；聚焦显示主题蓝 2dp 边框；校验失败显示错误红 2dp 边框。
- 圆角固定使用 `radii.field = 16dp`。
- 支持多行、自动换行和内部垂直滚动；不得随正文无限增高并挤出底部操作按钮。
- 待办场景占位文案为“输入待办内容”；笔记注释由调用方传入对应文案。
- 组件允许调用方传入 `value`、`onChangeText`、`placeholder`、`invalid`、`disabled`、最大长度和无障碍标签，不接受自定义身份色或圆角。

## 5. 日期与时间

### 5.1 日期选择

- 日期入口为高 48dp 的整行控件，点击后使用公共 `AppCalendar` 选择日期。
- 日期组件继续使用本地时区 Date ID（`YYYY-MM-DD`）作为边界值，禁止用 UTC 字符串截取日期。
- 日历弹窗标题为“选择日期”，取消和确定按钮等宽、高 48dp、间距 10dp。
- 待办业务不向 `AppCalendar` 注入自定义颜色、圆角或日程标注，避免破坏公共日历身份。

### 5.2 时间选择

新增公共时间选择组件，建议名称为 `TimePickerField`。它只输出本地时间值和清除动作，不请求权限、不创建系统日历事件、不调度通知。

- 开始时间和结束时间横向等分，间距 10dp，高 48dp。
- 结束时间可选；填写后不得早于开始时间，错误提示位于时间行下方 6dp，使用 14sp 错误红文字。
- 未设置开始时间时，待办只按日期归档，不创建系统日历事件，也不调度开始提醒。
- 日期与时间合成绝对时间的逻辑由待办业务层负责，并明确使用设备本地时区。

### 5.3 日历权限与日程写入

系统日历读写属于独立平台能力，不能由公共日历或时间组件发起。用户第一次明确选择“写入系统日历”时，待办业务层先说明用途，再请求系统权限；不在应用首启时冷启动权限弹窗。

- 授权成功：创建或更新系统日历事件，并保存平台事件 ID，供后续修改和删除时对账。
- 用户拒绝：本地待办仍正常保存，显示非阻断说明，并提供后续前往系统设置的入口。
- 写入失败：保留本地待办及其日期时间，标记日程待同步；不得因为外部日历失败而丢弃待办。
- 点击弹窗外触发自动保存时，不主动拉起系统权限弹窗。若权限已授予且用户已开启写入日历，则可继续写入；否则只完成本地保存，并把日历写入状态留待下次明确操作处理。

具体 Expo 依赖、config plugin 和平台权限文案在系统日历实现立项时依据 Expo SDK 57 官方文档另行确认。

## 6. 公共容器颜色选择器

建议公共名称为 `ContainerColorPicker`。组件用于选择特定业务容器的语义颜色预设，不接收任意十六进制颜色，不直接修改调用方状态。

- 入口为高 48dp 的整行控件，显示当前颜色预览、名称和右侧箭头。
- 展开面板使用共享弹窗或锚点气泡；色块触控区 48×48dp、圆角 16dp、间距 8dp并自动换行。
- 选中色块显示主题色描边和 `Check` 图标，并提供颜色名称和无障碍 `selected` 状态。
- 待办场景只改变待办卡片容器的预设背景或强调面，不覆盖文字、错误、选中、标星和置顶等身份色。
- 颜色值在数据层保存稳定的预设 ID，渲染时通过主题映射取得实际颜色，便于后续换肤。

## 7. 公共笔记关联组件

建议公共名称为 `NoteAssociationPicker`。组件负责搜索、选择、清除和展示关联笔记；导航和网络请求通过业务回调注入，公共 UI 不直接导入笔记仓库或 HTTP 客户端。

### 7.1 选择流程

1. 打开关联笔记面板后，先查询当前账号的本地笔记。
2. 用户输入关键词时先过滤本地标题和可搜索摘要。
3. 本地无匹配结果或已有关联 ID 但本地记录缺失时，再请求云端。
4. 云端请求失败时保留输入、本地结果和当前待办正文，只在面板内显示错误与重试操作。
5. 选择笔记后返回稳定关联 ID和展示快照；待办只保存一个首版关联笔记。

### 7.2 一键跳转

- 待办卡片和创建弹窗中的已关联笔记行均可点击跳转。
- 跳转前先按关联 ID 查找本地笔记；本地存在时直接进入笔记页。
- 本地不存在时请求云端，成功后按笔记本地优先规则落盘或对账，再进入笔记页。
- 离线、无权限或云端不存在时，保留待办关联信息并显示明确错误，不自动解除关联。
- 账号切换后必须按当前用户 ID重新解析关联，禁止读取上一账号的本地记录。

## 8. 保存与退出状态

### 8.1 确认创建

- “确认创建”为主题蓝 primary 按钮。
- 正文为空时保持弹窗打开，正文输入框进入错误态；不得创建空待办。
- 本地事务成功后关闭弹窗并更新列表。系统日历写入和通知调度作为可恢复的后续状态，不得阻塞或回滚已经成功的本地保存。
- 保存中锁定标题栏操作、遮罩关闭和底部按钮，防止重复创建。

### 8.2 取消创建

- “取消创建”为 secondary 浅灰按钮。
- 点击后放弃本次创建会话：未落盘内容直接清除；若本会话已因遮罩关闭产生自动保存记录，再次编辑时的“取消创建”需进入删除确认，而不是静默遗留记录。
- 取消路径不创建系统日历事件，不调度通知。

### 8.3 点击弹窗外自动保存

- 用户已输入非空正文时，点击遮罩自动保存为本地待办并关闭弹窗。
- 正文为空或仅含空白时直接关闭，不创建空待办。
- 自动保存成功保持静默，列表立即出现新卡片；失败时弹窗保持打开、输入保持原样，并显示重要错误提示。
- 已有开始时间且系统日历权限已经授予、用户已开启日历写入时，可在本地保存成功后创建日程。
- 尚未授权时不因遮罩点击突然拉起系统权限窗口；本地待办保存成功，并记录等待用户处理的日历状态。
- 系统返回键与遮罩点击遵循同一自动保存规则，避免两套退出行为。

## 9. 提醒与通知边界

待办开始提醒属于系统普通通知。实现立项后，在用户第一次保存带开始时间且开启提醒的待办时申请通知权限；未设置开始时间时不申请。

- 首版只在开始时间调度一次本地提醒。
- 应用位于前台时可同时显示应用内横幅；后台或应用被关闭时由系统通知承担触达。
- 用户拒绝通知权限不影响待办和日程保存，设置页提供后续开启入口。
- 修改或删除待办时必须取消旧调度，再按最新开始时间重建，避免残留提醒。
- 通知内容默认只包含待办摘要，不包含关联笔记正文、凭据或服务端原始错误。

依据现有[通知渠道适配](../UI/通知渠道适配.md)，待办和即将到来的日历事件不使用 Android Live Updates；iOS Live Activities 和鸿蒙实况窗也不属于本项目当前合规场景。不得持续发送重复通知模拟动态通知。

## 10. 待办列表卡片

待办列表参考当前笔记卡片的白底、阴影、16dp 圆角和 20dp 内边距。卡片宽度占满列表列，最大宽 400dp；卡片之间保持 12dp 间距。

```text
┌──────────────────────────────────────┐
│ □  待办正文，最多两行          ☆  📌 │
│    辅助正文或关联说明，最多四行       │
│                                      │
│    [九月十六日 09:00]  [关联笔记]     │
└──────────────────────────────────────┘
```

- 左侧完成控件使用至少 44×44dp 触控区；勾选后文字使用完成态，不只依赖删除线或颜色表达。
- 正文最多两行，17sp；补充正文最多四行，14sp；超出部分尾部省略。
- 右上角按“标星、置顶”显示 14dp 状态徽标，与笔记卡片保持同一层级。
- 底部元信息使用 13sp；日期时间和关联笔记分别作为语义胶囊或紧凑行，间距 8dp。
- 用户选择的容器颜色应用于卡片表面预设，文字对比度和状态色仍由主题配方保证。
- 点击卡片进入待办详情或编辑；点击完成控件、关联笔记和卡片本体的事件互不冒泡。
- 右侧日期轨道切换日期时，列表只显示该日期对应待办；无结果时显示该日期的空态，不显示伪造数据。

## 11. 后续数据契约

后续实现至少需要以下概念字段，最终命名以数据模型评审为准：

| 字段 | 用途 |
| --- | --- |
| 待办本地 ID、所有者 ID | 本地身份与账号隔离 |
| 正文 | 主内容，非空 |
| 完成、标星、置顶状态 | 列表状态与排序 |
| 日期、开始时间、结束时间、时区 | 日期筛选、日程与提醒 |
| 颜色预设 ID | 映射卡片容器主题 |
| 关联笔记 ID与展示快照 | 本地优先跳转和离线展示 |
| 系统日历事件 ID、写入状态 | 更新、删除和失败恢复 |
| 通知调度 ID、提醒状态 | 取消和重建本地提醒 |
| 创建、更新时间 | 排序、恢复与后续同步 |

待办后端接口当前没有契约。首版实现前必须决定待办是否只保存在本机，还是进入现有上传队列；在决定前不得套用笔记接口或把待办写进笔记表。

## 12. 后续实现顺序

1. 确认本地数据模型、自动保存身份和待办是否需要云同步。
2. 建立公共 `BodyInput`、`TimePickerField`、`ContainerColorPicker` 和 `NoteAssociationPicker` 契约，审计潜在调用方。
3. 实现待办本地存储、创建会话和列表卡片。
4. 接入公共日历、时间校验、颜色和笔记关联。
5. 独立立项系统日历权限、事件写入和失败恢复。
6. 独立立项普通系统通知权限、开始提醒调度和取消重建。
7. 完成静态检查；由用户主动发起真机权限、键盘、遮罩保存、通知和日历验收。

## 13. 验收清单

- [ ] 弹窗尺寸、圆角、内边距、标题字号、区块间距和按钮规格符合本文与视觉设计规范。
- [ ] 正文输入最小高 144dp，聚焦、错误、禁用和大字体状态不破坏底部按钮。
- [ ] 标星、置顶和删除具备独立无障碍名称、状态和触控范围。
- [ ] 取消创建、确认创建、遮罩关闭和系统返回四条路径不重复创建、不产生空待办、不丢输入。
- [ ] 日期使用本地 Date ID；结束时间早于开始时间时阻止创建并原位提示。
- [ ] 日历、通知被拒绝或失败时，本地待办仍保留并可恢复处理。
- [ ] 笔记关联本地优先，云端失败不清空当前选择；账号间数据隔离。
- [ ] 待办卡片与笔记卡片保持相同视觉层级，同时完成控件和日期信息清晰可辨。
- [ ] 不使用重复通知、Live Updates、Live Activities 或实况窗模拟持续动态通知。
- [ ] 真机验收覆盖窄屏、大字体、键盘、系统返回、权限拒绝、离线和应用前后台切换。
