# IRisNote 待办创建弹窗与列表设计

> 文档版本：1.3（2026-09-20）  
> 文档状态：设计规范；列表、筛选与弹窗 v1 以本文为实施基线（循环待办、关联笔记、日历写入、通知调度除外）  
> 适用范围：待办创建/编辑弹窗、待办列表（筛选栏、五色状态卡片、批量模式）及其复用组件契约  
> 视觉基线：[IRisNote视觉设计规范](../UI/IRisNote视觉设计规范.md) · [公共组件规范](../UI/公共组件规范.md) · [日历公共组件规范](../UI/日历公共组件规范.md) · [通知渠道适配](../UI/通知渠道适配.md)

## 1. 目标与范围

待办页提供"预设创建待办"操作。用户触发后直接打开"新增待办"弹窗，在同一弹窗内完成正文、日期时间、优先级和标星置顶设置；列表卡片单击唤起同一弹窗的编辑形态。待办列表使用五色状态卡片体系（§10），右侧日期轨道继续负责周切换与浏览，列表按可见周整周分组展示。

本文只定义界面、状态、交互、公共组件边界和后续数据契约，不代表页面、存储、系统日历或通知能力已经实现。

首版设计包含：

- 列表顶部筛选栏（全部 / 待进行 / 进行中 / 已过期）、时间排序入口与标题搜索。
- 五色状态待办卡片（底色 / 强调色成对，§10.1）。
- 长按批量选择模式（删除、标星、置顶，§10.4）。
- 新增与编辑复用的待办弹窗（正文、日期时间、优先级、标星置顶删除）。
- 可供待办正文和笔记注释复用的公共正文输入组件。
- 公共日期组件与公共时间选择组件的组合方式。
- 取消、确认和点击弹窗外自动保存三种退出路径。

首版不包含：

- 重复 / 循环待办（卡片时间行预留循环图标位，§10.3）。
- 公共笔记关联组件的接入（§7 整体延后）。
- 系统日历读写授权和日程写入（§5.3 边界保留）。
- 开始提醒通知调度（§9 边界保留）。
- 待办持久化存储与云同步：v1 以内存 store + 种子数据验收视觉与交互，存储方案另立任务（§11、§14）。
- 卡片滑动手势操作（长按批量已覆盖删除等诉求）。
- 公共容器颜色选择器 ContainerColorPicker：自由颜色选择被优先级状态色替代（§6）。
- Android Live Updates、iOS Live Activities、鸿蒙实况窗或用重复通知模拟动态通知。
- 日历组件内部增加 agenda、日程标注点、农历或节假日。

## 2. 视觉原则

待办界面遵循现有 HyperOS / miuix 风格：白色分组卡片、连续圆角、克制的主题蓝、浅灰控件底和统一遮罩。主色继续使用 `#007AFF`。业务组件只使用语义 Token，不传入任意颜色覆盖公共组件身份。

待办列表卡片是本项目中唯一一组"按状态着色"的业务表面：五种状态色对（底色 / 强调色）作为业务 Token 注册进主题（`default-light.json` palette + nativewindColorRefs，经 `npm run theme:sync` 生成，`npm run theme:check` 校验），页面与组件不得散落硬编码色值。状态色只作用于卡片表面与强调元素，文字、错误、选中、标星、置顶等身份色仍由主题配方保证。

| 项目 | 规格 |
| --- | --- |
| 弹窗遮罩 | `hyperScrim`，浅色模式 30% 黑；弹窗外边距 24dp |
| 弹窗卡片 | 白底、连续圆角 24dp、内边距 24dp、最大宽 440dp、最大高可用区域 85% |
| 弹窗标题 | 24sp，Regular，`textPrimary`，不使用粗体建立层级 |
| 列表主文字 | 17sp，Regular，`textPrimary` |
| 辅助正文 | 14sp，Regular，`textSecondary` |
| 元信息 | 13sp，Regular，`textSecondary` |
| 普通控件 | 高 48dp、连续圆角 16dp |
| 输入框 | 连续圆角 16dp、2dp 状态边框、左右内边距 16dp |
| 弹窗底部按钮 | 高 48dp、连续圆角 16dp、左右等宽、间距 10dp |
| 筛选 pill | 高 32dp、左右内距 12dp、圆角 16dp、pill 间距 8dp（§10.2） |
| 待办卡片 | 状态底色、圆角 16dp、无边框无阴影（§10.3） |
| 区块纵向间距 | 紧密关联项 12dp；主要区块 16dp |
| 最小触控范围 | iOS 不小于 44×44dp；Android 优先使用 48×48dp |

## 3. 新增 / 编辑待办弹窗

### 3.1 打开方式与复用关系

待办页的预设创建操作进入现有"新建待办"入口，并立即显示创建弹窗。路由只负责承载弹窗和返回关系，不把同一表单再绘制成第二套全屏页面。

列表卡片单击（勾选区除外）唤起同一弹窗的编辑形态：标题为"编辑待办"，预填该待办全部字段，标题栏垃圾桶变为删除该待办的入口（§3.3）。新增与编辑复用同一组件与表单结构，差异仅在标题、删除入口与初始值。

应用内弹窗必须使用共享 `AppModal` / Overlay 体系，使全局横幅仍能位于应用内弹窗上方。键盘展开或屏幕高度不足时，中间表单区域滚动，标题栏和底部按钮保持在弹窗卡片内。

### 3.2 整体布局

### 3.3 标题栏

- 左侧固定显示"新增待办"或"编辑待办"。
- 右侧按"标星、置顶、垃圾桶"排列，图标分别使用 Lucide `Star`、`Pin`、`Trash2`，视觉尺寸 20dp。
- 每个图标使用 44×44dp 触控区，相邻触控区间隔 4dp。Android 实现可将触控区提升至 48×48dp，但不得改变标题栏视觉节奏。
- 标星和置顶未启用时使用 `textSecondary`；启用后使用主题蓝，并通过无障碍 `selected` 状态表达，不能只靠颜色区分。
- 垃圾桶是当前会话的删除入口：创建态下，没有已保存内容时直接关闭；已有自动保存记录时打开共享删除确认弹窗。编辑态下，点击直接打开共享删除确认弹窗（沿用视觉规范《删除确认弹窗（DeleteConfirmDialog）》的 2 秒倒计时与红色确认按钮），确认后删除该待办并关闭弹窗。红色只用于最终确认删除按钮，标题栏图标保持中性灰色。

### 3.4 优先级行

- 整行高 48dp：三段等宽轨道，轨道底 `surfaceControl`、圆角 16dp。
- 选中段底色为该优先级的状态强调色（§10.1），文字黑色；未选段文字 `textSecondary`，字号 14sp。
- 三段为"不重要 / 正常 / 重要"，默认"正常"；切换即时生效。
- 各段提供独立无障碍标签与 `selected` 状态。
- 优先级决定未完成卡片的状态色（§10.1），弹窗内不再提供自由颜色选择（§6）。

## 4. 公共正文输入组件

### 4.1 定位

新增公共正文输入组件，供待办正文和笔记注释复用。组件只管理输入外观、聚焦、错误、禁用、字数提示和无障碍属性，不管理待办保存、笔记保存、草稿或云同步。

建议公共名称为 `BodyInput`，以现有公共 `Input` 的多行能力为基础，不另建第二套输入状态样式。

### 4.2 视觉与状态

- 默认最小高度 144dp，为普通 48dp 输入控件的三倍高度。
- 文字 17sp，顶部和底部内边距 12dp，左右内边距 16dp，文字从左上角开始排列。
- 默认浅灰 `surfaceControl` 背景，2dp 透明边框；聚焦显示主题蓝 2dp 边框；校验失败显示错误红 2dp 边框。
- 圆角固定使用 `radii.field = 16dp`。
- 支持多行、自动换行和内部垂直滚动；不得随正文无限增高并挤出底部操作按钮。
- 待办场景占位文案为"输入待办内容"；笔记注释由调用方传入对应文案。
- 组件允许调用方传入 `value`、`onChangeText`、`placeholder`、`invalid`、`disabled`、最大长度和无障碍标签，不接受自定义身份色或圆角。

## 5. 日期与时间

### 5.1 日期选择

- 日期入口为高 48dp 的整行控件，点击后使用公共 `AppCalendar` 选择日期。
- 日期组件继续使用本地时区 Date ID（`YYYY-MM-DD`）作为边界值，禁止用 UTC 字符串截取日期。
- 日历弹窗标题为"选择日期"，取消和确定按钮等宽、高 48dp、间距 10dp。
- 待办业务不向 `AppCalendar` 注入自定义颜色、圆角或日程标注，避免破坏公共日历身份。

### 5.2 时间选择

新增公共时间选择组件，建议名称为 `TimePickerField`。它只输出本地时间值和清除动作，不请求权限、不创建系统日历事件、不调度通知。

- 开始时间和结束时间横向等分，间距 10dp，高 48dp。
- 结束时间可选；填写后不得早于开始时间，错误提示位于时间行下方 6dp，使用 14sp 错误红文字。
- 实现约束：不引入原生选择器依赖（保持 Expo Go 可加载），采用纯 JavaScript 双列轮盘弹层（小时 0–23、分钟 0–59，按 1 分钟步进），挂接共享弹层体系（`AnchoredPopover` / `AppModal`）。
- 未设置开始时间时，待办只按日期归档，不创建系统日历事件，也不调度开始提醒。
- 日期与时间合成绝对时间的逻辑由待办业务层负责，并明确使用设备本地时区。

### 5.3 日历权限与日程写入

系统日历读写属于独立平台能力，不能由公共日历或时间组件发起。用户第一次明确选择"写入系统日历"时，待办业务层先说明用途，再请求系统权限；不在应用首启时冷启动权限弹窗。

- 授权成功：创建或更新系统日历事件，并保存平台事件 ID，供后续修改和删除时对账。
- 用户拒绝：本地待办仍正常保存，显示非阻断说明，并提供后续前往系统设置的入口。
- 写入失败：保留本地待办及其日期时间，标记日程待同步；不得因为外部日历失败而丢弃待办。
- 点击弹窗外触发自动保存时，不主动拉起系统权限弹窗。若权限已授予且用户已开启写入日历，则可继续写入；否则只完成本地保存，并把日历写入状态留待下次明确操作处理。

具体 Expo 依赖、config plugin 和平台权限文案在系统日历实现立项时依据 Expo SDK 57 官方文档另行确认。

## 6. 优先级选择与状态色（替代原公共容器颜色选择器）

v1.0 曾规划公共 `ContainerColorPicker` 供用户自由选择卡片颜色。v1.1 起待办卡片颜色改由"优先级 + 完成状态"推导（§10.1），自由颜色选择移出首版范围；`ContainerColorPicker` 构想保留，待出现真实的自由配色场景再立项。

- 弹窗内的颜色入口因此替换为 §3.4 优先级三段控件。
- 数据层不再保存颜色预设 ID，改为保存优先级（§11）；渲染时经 §10.1 映射取得底色与强调色，便于后续换肤。
- 状态色不覆盖文字、错误、选中、标星和置顶等身份色；Token 命名与注册方式见 §10.1。

## 7. 公共笔记关联组件

建议公共名称为 `NoteAssociationPicker`。组件负责搜索、选择、清除和展示关联笔记；导航和网络请求通过业务回调注入，公共 UI 不直接导入笔记仓库或 HTTP 客户端。**本组件整体延后，不在列表与弹窗 v1 范围内（§1）。**

### 7.1 选择流程

1. 打开关联笔记面板后，先查询当前账号的本地笔记。
2. 用户输入关键词时先过滤本地标题和可搜索摘要。
3. 本地无匹配结果或已有关联 ID 但本地记录缺失时，再请求云端。
4. 云端请求失败时保留输入、本地结果和当前待办正文，只在面板内显示错误与重试操作。
5. 选择笔记后返回稳定关联 ID和展示快照；待办只保存一个首版关联笔记。

### 7.2 一键跳转

- 待办卡片和创建弹窗中的已关联笔记行均可点击跳转。
- 跳转前先按关联 ID 查找本地笔记；本地存在时直接进入笔记页。
- 本地不存在时请求云端，成功后按笔记本地优先规则落盘或对账，再进入笔记页。
- 离线、无权限或云端不存在时，保留待办关联信息并显示明确错误，不自动解除关联。
- 账号切换后必须按当前用户 ID重新解析关联，禁止读取上一账号的本地记录。

## 8. 保存与退出状态

> v1 以内存 store 承载（§11）："本地事务成功"指写入内存 store 并广播列表更新；持久化落库后本节规则不变。

### 8.1 确认创建

- "确认创建"为主题蓝 primary 按钮。
- 正文为空时保持弹窗打开，正文输入框进入错误态；不得创建空待办。
- 本地事务成功后关闭弹窗并更新列表。系统日历写入和通知调度作为可恢复的后续状态，不得阻塞或回滚已经成功的本地保存。
- 保存中锁定标题栏操作、遮罩关闭和底部按钮，防止重复创建。

### 8.2 取消创建

- "取消创建"为 secondary 浅灰按钮。
- 点击后放弃本次创建会话：未落盘内容直接清除；若本会话已因遮罩关闭产生自动保存记录，再次编辑时的"取消创建"需进入删除确认，而不是静默遗留记录。
- 取消路径不创建系统日历事件，不调度通知。
- 编辑态的"取消"直接关闭弹窗，不回滚勾选完成等会话外已发生的状态变化。

### 8.3 点击弹窗外自动保存

- 用户已输入非空正文时，点击遮罩自动保存为本地待办并关闭弹窗。
- 正文为空或仅含空白时直接关闭，不创建空待办。
- 自动保存成功保持静默，列表立即出现新卡片；失败时弹窗保持打开、输入保持原样，并显示重要错误提示。
- 已有开始时间且系统日历权限已经授予、用户已开启日历写入时，可在本地保存成功后创建日程。
- 尚未授权时不因遮罩点击突然拉起系统权限窗口；本地待办保存成功，并记录等待用户处理的日历状态。
- 系统返回键与遮罩点击遵循同一自动保存规则，避免两套退出行为。

## 9. 提醒与通知边界

待办开始提醒已接入 Android/iOS 本地系统通知。明确确认保存未来开始且开启提醒的待办后才申请权限；无开始时间、已完成或过去时刻不申请。遮罩/返回自动保存不弹系统权限，未授权显示“待办已保存，系统提醒尚未开启”，由用户点击“开启”后申请。拒绝不会回滚待办。

- 首版只在开始时间调度一次本地提醒。
- 前台仍显示系统通知，不叠加应用内成功横幅；后台由操作系统调度。强制停止、OEM 省电及专注模式可能影响触达，不承诺闹钟级准点。
- 用户拒绝通知权限不影响待办和日程保存，设置页提供后续开启入口。
- 修改或删除待办时必须取消旧调度，再按最新开始时间重建，避免残留提醒。
- 通知内容默认只包含待办摘要，不包含关联笔记正文、凭据或服务端原始错误。
- 卡片右缘铃铛仍代表有开始时间（颜色规则见 §10.3），不等于权限或实际送达成功。`reminderEnabled` 默认开启；表单“开始时提醒”行位于时间与优先级之间，高 48dp，上下间距各 12dp，左右 padding 16dp，文字与原生 Switch 至少 12dp；无开始时间时显示关闭并禁用。
- 完成、删除和关闭提醒取消旧调度；取消完成且仍在未来时重新调度。设备绑定独立存于迁移 0008 表，不进入待办实体或后端契约。取消失败保留清理意图，启动/前台恢复对账重试。
- 按设备当前当地民用时间解释日期与开始分钟，时区变化后前台重算；DST 不存在时刻保留待办并报告失败，重复小时取较早时刻。点击通知进入当前账号待办的对应日期，不直接打开编辑；旧账号或已删除待办仅给通用提示。

动态通知（2026-09-23 决策反转，用户立项）：待办进行中状态已接入 Android 16 **ProgressStyle 进度式动态通知**——当天、开启提醒、未完成且处于开始—结束窗口内的待办，在应用前台各维持一条动态进度卡片（同屏上限 3 条，静默 LOW 渠道，同一通知 ID 原位分钟级更新；无结束时间用不定进度）；退后台或权限收回即全部撤下，后台到点仍由普通开始提醒兜底。**提升式 Live Updates（置顶/锁屏/胶囊）维持不接入**——政策禁止"普通提醒/即将到来的日历事件"且需 API 36.1；iOS Live Activities 和鸿蒙实况窗仍不属于本项目合规场景。不得持续发送重复通知模拟动态通知。详见[通知渠道适配](../UI/通知渠道适配.md) §6.2。

## 10. 待办列表：五色状态、筛选栏、卡片与批量模式

待办列表位于内容白卡内：顶部为筛选栏（§10.2），其下为待办卡片列表（§10.3）；长按任一卡片进入批量选择模式（§10.4）。卡片颜色遵循 §10.1 五色状态体系。v1.0"沿用笔记白底卡片"的方案自 v1.1 起废止。

### 10.1 五色状态体系

正常态（`#FDEBC4` 底 / `#F9C962` 强调）为用户指定基准；其余四对按同一明度关系推导（同色相、近饱和，底色明度 ≈ 88%、强调色明度 ≈ 68%）。数值可在校准轮成对调整，但必须同步主题 Token 与本表。

| 状态 | 底色 Token（建议名） | 底色值 | 强调色 Token（建议名） | 强调色值 | 触发条件 |
| --- | --- | --- | --- | --- | --- |
| 不重要 | `todoLowSurface` | `#C5DFFC` | `todoLowAccent` | `#64A9F7` | 未完成 · 优先级=不重要 |
| 正常 | `todoNormalSurface` | `#FDEBC4` | `todoNormalAccent` | `#F9C962` | 未完成 · 优先级=正常（基准，用户指定） |
| 重要 | `todoHighSurface` | `#FCCADB` | `todoHighAccent` | `#F76998` | 未完成 · 优先级=重要 |
| 已完成 | `todoDoneSurface` | `#CDF9DB` | `todoDoneAccent` | `#71EF9B` | 已勾选完成 · 所属日期 ≥ 今天 |
| 已结束 | `todoEndedSurface` | `#E6E8EA` | `todoEndedAccent` | `#ACB2B9` | 已勾选完成 · 所属日期 < 今天（隔日回看） |

- 底色用于卡片表面；强调色用于卡片左缘竖线与勾选圈（§10.3）。
- 十个色值注册进 `default-light.json`（palette + nativewindColorRefs）并经 `theme:sync` 生成；公共组件不得直接绑定这些业务色。
- 状态推导规则（与筛选栏四项一致，全部按设备本地时区，推导值不落库）：
  - **已完成**：勾选标记为真。所属日期 ≥ 今天显示浅绿，所属日期 < 今天显示灰（已结束，标题灰色删除线）。
  - **已过期**（未完成）：所属日期 < 今天；或所属日期 = 今天且结束时间早于现在。
  - **待进行**（未完成）：所属日期 > 今天；或所属日期 = 今天且设置了开始时间且开始时间晚于现在。
  - **进行中**（未完成）：所属日期 = 今天且不满足前两条（无时刻待办当天视为进行中）。
  - 已完成判定优先于过期判定；"今天"以本地 Date ID 为准。

### 10.2 筛选栏

```text
┌─ 筛选行 h-44 ──────────────────────────────────────┐
│ [全部][待进行][进行中][已过期]（gap-8）      ⏱   🔍 │
└────────────────────────────────────────────────────┘
pill：h-32 · 左右内距 12 · 圆角 16 · 字号 14
  未选：底 controlSurface(#F0F0F0) · 字 textSecondary
  选中：底 brandPrimary(#007AFF) · 字白
⏱ / 🔍：44×44 触控 · icon 20 · textSecondary · 贴筛选行右端
筛选行下缘距列表 12
```

- 日期轨道的可见周决定列表的日期范围（周一至周日）：列表按所属日期分节，每天显示"M月D日 周X"分组头（今天组追加"今天"标记；分组头 13sp、`textSecondary`，今天用主题蓝，右侧接 1dp `divider` 通栏分隔线；非首节分组头上间距 16dp，头部下缘距首卡 8dp，节内卡片间距 12dp），当天无待办的日期不显示分节；筛选栏在周范围内按 §10.1 推导态过滤，"全部"显示该周全部待办。点选轨道某天滚动到对应分节，滑动换周后列表回到顶部；定位后分组头保持在可视区内。
- **⏱ 时间排序**：弹出锚点菜单，选项为"时间正序 / 时间倒序 / 优先级"，默认时间正序；未设置开始时间的待办排同日期末尾，组内按创建序。置顶待办恒排最前（组内仍按当前排序）。
- **🔍 搜索**：展开内联输入行（高 44dp，Input 规范，圆角 16、`surfaceControl` 底），出现在筛选行与列表之间，按标题与正文实时过滤（不区分大小写）；收起时清空关键词。占位文案"搜索待办"。
- 空态：整周无匹配时显示周空态（"本周暂无待办" / 搜索无结果"无匹配待办"），不显示伪造数据。

### 10.3 待办卡片

```text
┌──────────────────────────────────────────────┐  底色 = 状态底色
│ ↕2dp                                         │  圆角 16 · 无边框无阴影
│ ▏┃ ← 竖线：宽 4dp · 强调色 · 距左缘 6dp       │
│ ▏│     · 上下各缩 2dp · 端部圆角 2dp          │
│ ▏│    ★ 标题 17sp（已结束：灰+删除线） 🔔 ○  │
│ ▏│    ↕4dp                                    │
│ ▏│    ⏱ 09:00–09:30 · 13sp（标题色浅化）      │
│ ↕2dp                                         │
└──────────────────────────────────────────────┘
```

- 列表：SectionList 按天分节（分组头规格见 §10.2 日期范围说明），节内卡片间距 12dp，宽度占满列表列、最大宽 400dp。
- 内距：竖线右缘到内容 12dp（即内容距卡左缘 22dp）；右缘 10dp；上下各 8dp。
- 竖线随卡片内容变高：上下各距卡片外缘 2dp、垂直居中。16dp 连续圆角在贴角处会内收裁剪竖线端部，按 `overflow-hidden` 裁剪呈现（竖线贴弧起止）；如需完全避让改为上下缩 4dp，需在实现轮确认。
- **标题行**：标题取待办正文首行，17sp `textPrimary`，单行尾部省略。已结束态标题为灰色（`textMuted`）并加删除线。标星待办在标题左侧显示 12dp ★ 徽标（`starBadge` 色）；置顶不显示徽标，只影响排序（§10.2）。
- **时间行**：`Clock` 图标 14dp + 4dp + 文本 13sp；文本为"开始–结束"，仅开始时间时显示单值，无时刻显示"全天"。引入循环待办后，图标切换为 `Repeat` 表达循环态，颜色规则不变（预留位）。时间行与图标颜色 = 标题当前色叠 55% 透明度（浅化跟随：已结束态自动跟随灰色）。
- **🔔 提醒图标**：18dp，设置了开始时间时显示，颜色同时间行浅化色（语义见 §9）。
- **勾选圈**：视觉 24dp、触控 44dp（hitSlop）。未勾选 = 状态强调色 2dp 空心描边；勾选 = 状态强调色实底 + 白色对勾 14dp；已结束态使用灰系强调色对。点击切换完成状态，事件不冒泡到卡片。
- 单击卡片（勾选圈以外区域）唤起编辑弹窗（§3.1）。

### 10.4 交互与批量模式

- **长按任一卡片**进入批量选择模式，初始选中该卡片；筛选行整体替换为批量工具栏：

```text
┌─ 批量工具栏 h-44 ──────────────────────────────────┐
│ [✕]  已选 n 项  [全选]              ☆    📌    🗑  │
└────────────────────────────────────────────────────┘
✕ 44×44 退出；☆ 📌 icon 20 中性灰；🗑 icon 20 destructive 红
```

- "全选"选中当前过滤结果全部；✕ 或系统返回键退出批量模式并清空选择。
- **🗑 删除**：打开共享删除确认弹窗（2 秒倒计时），确认后删除所选。
- **☆ 标星 / 📌 置顶**：对所选集合统一取反多数态——所选全部已开启则全部关闭，否则全部开启。
- 批量态下卡片单击为切换选中：卡片左缘竖线内侧显示选择圈（选中 = 主题蓝底白勾，未选 = 灰描边空心）；完成勾选圈在批量态不可用。
- v1 不提供卡片滑动手势（左滑删除等），长按批量已覆盖。

## 11. 后续数据契约

后续实现至少需要以下概念字段，最终命名以数据模型评审为准：

| 字段 | 用途 |
| --- | --- |
| 待办本地 ID、所有者 ID | 本地身份与账号隔离 |
| 正文 | 主内容，非空；卡片标题取其首行 |
| 完成标记、完成时间 | 完成态判定与"当日 / 隔日"显示分层（§10.1） |
| 优先级（不重要 / 正常 / 重要，默认正常） | 映射未完成卡片状态色（§10.1），替代颜色预设 ID |
| 标星、置顶状态 | 列表状态、批量操作与排序 |
| 日期、开始时间、结束时间、时区 | 日期筛选、状态推导、日程与提醒 |
| 提醒开关（默认开启） | 通知立项后的调度依据；立项前仅记录状态（§9） |
| 关联笔记 ID与展示快照 | 本地优先跳转和离线展示（延后，§7） |
| 系统日历事件 ID、写入状态 | 更新、删除和失败恢复 |
| 通知调度 ID、提醒状态 | 取消和重建本地提醒 |
| 创建、更新时间 | 排序、恢复与后续同步 |

- 待进行 / 进行中 / 已过期 / 已完成为推导值（§10.1），不落库。
- v1 以内存 store + 种子数据先行验收（种子覆盖五种状态与各优先级）；持久化存储与云同步另立任务。
- 待办后端接口当前没有契约。首版实现前必须决定待办是否只保存在本机，还是进入现有上传队列；在决定前不得套用笔记接口或把待办写进笔记表。
