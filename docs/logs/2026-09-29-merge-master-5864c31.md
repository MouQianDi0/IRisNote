## 二、与原代码对比及改动原因

1. 原本笔记星标/置顶依赖云权限并直接发送 API；现在先写 SQLite 与带版本的待发记录，再统一同步。网络失败保留本地状态，避免关闭云同步时失去本地操作能力。
2. 原本分类依赖服务端列表或缓存叠加队列；现在有持久本地实体、稳定本地 ID 和云端 ID 映射，分类保存与入队同事务，避免离线创建不能立即使用。
3. 原本云端笔记删除/恢复依赖在线确认；现在可记录本地意图，按身份及版本重放；云端冲突保留本地结果和错误信息，避免覆盖其他设备的新修改。
4. **行为变化**：已淘汰正文的笔记原本无云端正文不能恢复，现在可恢复摘要并保持 evicted 状态；不会生成空正文版本或上传缺失正文。
5. 写入结束触发同步从 100ms 改为 1500ms 尾部防抖；其他前台/定时/网络恢复触发仍为 100ms，减少连续操作引发的重复拉取。
6. 更新说明从纯文本改为公共轻量 Markdown；解析不携带业务默认标题，更新域显式提供兼容配置，便于其他页面复用。
7. **门控边界**：本地操作只要求当前账号会话有效，云请求仍必须通过原有云授权门控；没有默认打开用户云上传授权。

## 三、完整调用链路

- 标记：滑动按钮/长按菜单 → useNotePin/useNoteStar → toggleLocalNoteFlag → 本地会话校验 → SQLite 事务更新 local_notes 与 note_local_flags → 缓存/事件/列表回写 → 写入结束 → 协调器 1500ms 尾部防抖 → 云授权校验 → syncLocalNoteFlags → PUT → 按发送版本删除待发记录。旧版本回执不删除新标记；无云权限保留待发。
- 分类：分类弹窗 → enqueueCategoryCreate/Update/Delete → 本地分类与队列事务 → 分类事件刷新 → 上传协调器 → 云授权校验 → executeLocalCategoryTask → 创建/更新/删除 API → 持久化 server_id、按版本清 dirty → 回写事件。创建结果未知时阻塞并保留本地实体；本地负 ID 在上传笔记前映射为云 ID。
- 回收站：删除/恢复 UI → note-trash.service → 本地会话校验 → 本地归档/恢复及 note_trash_intents → 事件更新列表 → 恢复云授权后 synchronizeLocalTrashIntents → 读取云状态并核对身份/版本 → 删除/恢复 API → 条件清理意图；冲突保留本地内容及错误。
