## 2. 与原代码对比及原因

1. 原来 `DiffChunk` 给整个增删行设置文字颜色和背景，一字替换突出整行。现在行仍定位上下文，连续变更段内追加字符 Myers，只给实际增删字设置红/绿背景、删除线/下划线；共有字符保留普通样式。原因是缩小视觉范围，让长行和多个修改点易于定位。
2. 原来正文统计新增/删除行数，“上午 → 下午”显示 +1 行/−1 行。现在按码点统计 +1 字符/−1 字符，只突出“上 → 下”；“午”共有。标题使用相同精化，单独缓存和预算，不计正文数字。
3. 原来只有行内容和空行占位。现在空格、制表符、换行、回车分别有 `·`、`⇥`、`↵`、`␍`，无障碍朗读实际增删片段和空白名称。原因是字符级变化不能因不可见空白而漏掉。
4. 增删块比较整段，不按行号硬配对。跨行拆分/合并的公共文字继续作为共有字符；有后文时将分隔换行归入段尾，只有前文时归入段首，防止中间空行/末尾换行被算成零变化；共有边界换行从展示投影移除。
5. 原来所有任务使用单一正文完成状态。现在正文/标题各有输入引用与完成状态，改标题只安排标题任务；重试号也参与完成状态匹配，重试即隐藏旧结果。保持旧的 timer 清理、generator return 和迟到批次保护。
6. 原行接口仍返回行数，行/字符精化共用一个私有序列算法，无 npm 依赖；每次对比的行定位、字符拆分、搜索共享工作预算，防止多个段各自重置预算而阻塞交互。字符块合计也限界，超限无局部统计，历史全文仍可查看。
7. 单侧插入时历史投影可能全是共有字符，单侧删除时当前投影同理。共有侧不染色、不显示错误的增删符号，朗读标为“历史/当前”上下文；仅实际变化侧朗读“新增/删除”，避免空“删除：”标签。

默认 Tab、历史 → 实时草稿方向（含未保存改动）、行上下文折叠、恢复权限与版本 ID 判断均沿既有逻辑；无默认开关反转。

## 3. 完整实际调用链

```text
笔记查看页历史按钮
  → NoteHistoryPopover：列表 → 选中版本详情
  → useNoteHistory.select
  → readHistoryRevision
  → note-revision.repository 读取本机 SQLite note_revisions 全文
  → selected 历史快照 + currentValue 实时编辑草稿
  → NoteHistoryDiff
      ├─ 正文 input → useCharacterComparison → diffTextWithCharacters
      └─ 标题 input → useCharacterComparison → diffTextWithCharacters（独立缓存）
          → 统一 CRLF/LF，空正文按空串，检查输入上限
          → diffSequence：Myers 按行定位，共有前后缀与无共有单元优化
          → 连续删除/新增段合并，补入属于该段的边界换行
          → characters：Unicode 码点拆分，保留代理对
          → diffSequence：Myers 按字符精化
          → 双侧 span 投影 + 完整增删字符统计
          → textDiffSections：共有行保留两行上下文/长段折叠
          → DiffChunk：共有字普通显示，真实增删字突出、可见空白与朗读
```

- 数据源在本机；本次纯计算/渲染不新增数据库写入和网络请求，没有双端镜像算法。
- 分批调度每 2048 工作步让出 JS 线程，继续复用 150ms 延迟加载。输入变化/关闭/卸载清理定时器并关闭生成器，迟到批次不发布；全文 Tab 仍保留组件与结果。
- 双边输入合计上限：400000 UTF-16 码元、12000 行；各任务共享 200000 工作步预算；序列搜索块数限界 400，精化字符块合计限界 1200。正文/标题分别受限，任何阶段超限均返回 too-large，无部分统计。
- 计算异常显示重试/全文入口；正文或标题超限各显示全文提示。重试号使旧完成状态立即失效。
- 恢复入口仍由 NoteHistoryPopover → 既有草稿锁与本地恢复事务执行；该分支不经过字符算法，回归覆盖恢复失败、并发与版本权限。
- 字符以 Unicode 码点计数；空格/制表符/换行各计一，仅统一 CRLF/LF，不 trim。代理对不会拆坏，复杂 emoji/组合字可能包含多个码点，未引入字素簇分词。
