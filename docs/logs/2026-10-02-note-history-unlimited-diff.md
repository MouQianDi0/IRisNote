## 与原代码对比与改动原因

通过`git diff 6377a75 --`相关源码实测核对基点；本次只替换比较实现及对应结果消费，没有凭最终代码推断旧行为。

1. 原来双方合计超过400000 UTF-16码元、12000行或200000计算步，以及单次400块/总精化1200块就返回too-large；现在这些终止条件全部删除，正文和标题均完整比较。移除旧maxWork选项/失败结果类型，调用点只使用batchSize；搜索全部src/tests确认没有其他业务消费者依赖原失败契约。
2. 原来每层复制frontier到trace，保存整条搜索历史后反向回溯；现在仅有前向/反向Int32Array，找到最短编辑路径交点就分成两段，逐段处理，工作内存随输入线性增长。范围索引避免子段slice复制，显式任务栈避免深递归；公共前后缀及无共有单元快速增删仍保留。
3. 原来chunks/字符变更段使用push(...lines)，去掉原行数限制后13万行可能触发参数栈溢出；现在逐项追加并分批。这直接支撑本次取消上限，不是无关重构。
4. 原来超限显示“正文差异较大，已显示历史全文，暂无法统计和标注”或原始标题提示；现在页面不再按大小停算或退出标注。计算时仍显示原文和150ms延迟加载，完成后显示全部精确结果；真实计算错误才保留全文并提供重试，没有局部统计。
5. 原来取消用返回too-large占位，现在return(undefined)终止生成器；已取消的定时器/迟到回调不写状态。不把取消伪装成大小失败，也不发布假完整统计。
6. 原文/差异开关、字符新增/删除样式、连续变化计处数、标题分类排除正文统计、Unicode码点/CRLF/空白/空行/末尾换行、草稿快照与恢复行为保持。

算法依据：[Myers 1986 原论文](https://grantjenks.com/wiki/_media/ideas/diffalgorithmlcs.pdf)的线性空间变体（双向搜索交点与分治）；采用本项目的生成器/范围索引/显式任务栈实现，没有引入npm库或复制第三方软件模块。调度最多2048工作步只是让出执行的批次，不是超时或停止比较阈值。

## 完整调用链路

~~~text
最后编辑时间 → 历史摘要气泡 → 选版本push详情（原编辑页留在栈内）
  → 按账号/笔记/版本验证内存草稿快照
  → readHistoryRevision读取本机所选历史全文
  → NoteHistoryDiff先显示历史原文和原始标题
      正文/标题分别useCharacterComparison，独立缓存
      → diffTextWithCharacters（去掉全部大小/步数/块数终止条件）
      → 行定位diffSequence
          剥公共前后缀；无共有单元则直接完整增删
          否则middleSplit前向/反向搜索 → 交点 → 显式范围任务栈
          最长每2048工作步yield
      → 连续变更段按Unicode码点同样分治精化
      → 完整chunks + 统一spans + added/removed/changes
      → historyDiffRows → FlatList完整段落 → 字符交错标注与全部统计
      → 原文/标注开关复用缓存
      → 真实错误保留全文/重试；换输入/卸载清定时器并return(undefined)
  → 恢复按钮仍由原详情/原编辑器回调执行原本地草稿锁和事务
~~~

差异计算只使用本地读取的版本与打开时的草稿副本，不访问网络、写数据库、创建Revision或改上传队列。恢复链路未改，无新接口、迁移、双端镜像或原生行为。
