# Notesnook 二开开发手册（适合新手读源码）

> 目标：基于 Notesnook 源码进行二次开发，在保留原有笔记能力的基础上，增加自己的功能与界面。

---

# 1. 项目定位

Notesnook 本质上是一个：

```text
笔记系统
├── 富文本编辑器
├── 标签系统
├── 附件管理
├── 搜索
├── 同步
├── 加密
└── 多端支持
```

适合改造成：

- AI 笔记
- 学习资料库
- 个人知识库

不太适合改造成：

- ERP
- 电商平台
- 大型协同办公系统

# 4. 第一次运行项目

```bash
git clone https://github.com/streetwriters/notesnook.git
cd notesnook

npm install
```

启动 Web：

```bash
npm run web
```

启动 Android：

```bash
npm run android
```

启动 iOS：

```bash
npm run ios
```

目标：

- 能成功编译
- 能登录
- 能创建笔记

不要急着修改源码。

# 5. 如何读源码

第一次打开源码时：

```text
apps/
packages/
libs/
```

先不要看所有代码。

重点记录：

```text
页面入口在哪
导航在哪
编辑器在哪
数据库在哪
同步在哪
```

建议自己画图。

例如：

```text
首页
 ↓
组件
 ↓
状态管理
 ↓
数据库
 ↓
同步
```

```text
 ↓

```

# 11. 编辑器模块

这是核心。

研究顺序：

```text
工具栏
↓
编辑区域
↓
文本格式
↓
图片
↓
附件
```

不要一开始改编辑器。

因为编辑器通常是整个项目最复杂的模块之一。

# 14. 新手常见错误

## 错误1

上来就研究同步。

结果：

```text
看不懂
```

## 错误2

上来改编辑器。

结果：

```text
项目直接崩
```

## 错误3

直接改核心代码。

结果：

```text
后续无法升级官方版本
```

---

# 15. 最佳实践

推荐原则：

```text
新增
优于
修改
```

例如：

正确：

```text
新增 inventory 模块
```

错误：

```text
直接修改笔记模块
```

这样后期同步官方更新会容易很多。

---

# 总结

对于 Notesnook 二开：

```text
先 UI
再功能
再数据库
再同步
最后编辑器
```

遵循这个顺序，你会比直接硬啃源码快得多。
