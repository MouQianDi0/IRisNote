```text
    ├── src/features/notes
    │   ├── Screen / NoteViewer：详情页查看编辑合并、正文淘汰与下载状态、历史气泡入口
    │   ├── data：local_notes、note_drafts、note_revisions、云端镜像、
    │   │   正文淘汰、新建幂等操作、回收站、阅读进度等仓库

    │   ├── reading / categories：阅读进度与分类子域
    │   └── NoteEditor：新建笔记适配（含新建草稿箱）

        └── index.ts：稳定公共出口

```

依赖规则：

1. `app` 只负责路由转发和导航容器。
2. Notes、Excerpts 等 Feature 可以依赖 `core/editor`。
3. `core/editor` 禁止依赖任何 Feature，也不读取业务 API、缓存或数据库。
4. Notes 的草稿、版本、分类、同步和容量仍属于 Notes 领域。
5. Excerpts 当前尚无实体和保存契约，后续通过自己的适配层复用编辑器。
6. 原始 SQLite 实例不进入应用组件树；Feature 不得直接导入 `expo-sqlite`，只能使用 `core/database` 的公共端口。
7. Web 与原生共用迁移和数据契约；平台差异只允许存在于事务和运行环境配置层。

## 3. 当前具体操作与逻辑

### 3.1 详情页内激活编辑

1. 用户打开 `/pages/note/[id]`。
2. `NoteDetailScreen` 校验 ID 并加载笔记。
3. `NoteViewer` 直接挂载标题与正文可编辑节点，保持详情页原排版和阅读进度能力。
4. 单击标题或正文只定位光标；同一输入区 300ms 内第二次点击直接调起输入法，顶部不提供独立编辑入口。
5. 旧 `/pages/note/edit/[id]` 深链携带 `edit=1` 重定向详情页，不再维护第二套编辑界面。

### 3.2 初始化合并页编辑会话

1. `NoteDetailScreen` 先读取进程内缓存，缺失时读取当前用户的 SQLite 本地笔记；仍缺失才请求 `GET /notes` 并合并入本地表。
2. `NoteViewer` 把 `Note.title` 和可空的 `Note.content` 转成统一文本值。
4. `useNoteDraft` 取得按账户和草稿键隔离的会话，读取草稿及最新本地笔记，比较基础内容快照。
5. 普通草稿直接初始化到标题和正文；不再展示「发现本地草稿」整页 UI。基础版本冲突时保留紧凑确认，未经确认不能保存覆盖。
6. 合并页编辑会话随账户和笔记 ID 隔离，账户不匹配的笔记不能进入会话。

### 3.3 编辑与保存

1. 输入立即更新编辑器内存，同时通知 Notes 会话；草稿保留原始空白、空标题和空正文。
2. 停止输入 750ms 或连续输入达到 5 秒时，通过串行调度器写入 `note_drafts`；写入中只合并补写最新快照。
3. 失焦、页面失去焦点、返回、应用退后台、Web 页面隐藏和卸载请求补写。正常返回等待写入完成；写入失败显示错误并每 3 秒重试，也可手动重试。
4. 既有笔记收起输入法、输入失焦或应用退到后台时只排空草稿任务，不写稳定笔记、不创建 Revision、不访问云端。
5. 真正退出既有笔记详情页时，先锁定输入并排空草稿；事务校验会话/序号和基础版本，写入 `local_notes` 并创建有变化的 Revision。本地提交成功后先退出页面，退出后由 `note-exit-sync-coordinator` 按笔记串行写入持久 `upload_queue_tasks` 队列（2026-09 起由静默直传改为入队，网络与服务器确认由全局上传协调器执行）；云端接受后仅条件清理本次草稿，拒绝/结果未知保留，旧响应不得覆盖较新的本地同步状态。新建笔记自 2026-09-27 起带幂等键：请求体与版本先固定进 `note_create_operations`，结果未知自动原样重发，云端已建出时按身份认领，不产生重复笔记。
6. 新建入口每账户保留一个待处理草稿槽。已提交但云端失败的草稿关联已有笔记，恢复后更新该笔记；结果未知的新建不会自动重复 POST。
7. 放弃草稿需二次确认，按会话和序号删除并记录无正文日志；重新读取已保存内容后开始会话。

当前限制：草稿优先比较本地基础 Revision 指针，迁移前 NULL 指针退回内容快照；这不是服务端条件更新协议，冲突时保留草稿供查看/复制，阻止直接保存与历史恢复。块模型未开始。异常终止前未落盘的尾部输入仍可能丢失，后台事件不能保证执行完成。旧会话失去写入权后，未落盘输入须先复制保留。

### 3.4 历史查看与恢复（3B）

1. 详情页顶部 History 图标打开同一锚点气泡（300dp 宽、最大 520dp 高）；打开只收起输入法并请求草稿补写，不触发路由退出或正式保存。
2. `useNoteHistory` → `readNoteHistory`：同一 SQLite 事务读取当前版本指针、按账号/笔记隔离的版本摘要和本地分类名；自动草稿不加入历史列表，列表不传输整篇正文。
3. 选择一项后调用 `readHistoryRevision` 读取该版本全文；默认“与当前对比”，保留“历史全文”。`note-history-diff` 分批执行 `diffTextLines`，按历史 → 当前展示正文新增/删除、行数统计和标题/分类变化；未改动长段保留两行上下文并支持展开。当前基准来自页面内存，包含未保存输入；内容一致与当前版本 ID 分别判断。仅统一正文 CRLF/LF，保留空白、空行和末尾换行。
4. “恢复此版本”进入气泡内确认，取消只回详情；确认后 `draft.beginSave()` 锁定并排空草稿，`restoreNoteFromHistory` 调用既有恢复仓储的增强事务。
5. 校验当前版本未变化、目标归属与结构、草稿会话/序号/基础版本；拒绝垃圾桶/清除标记、同步中、正文被淘汰和当前空标题。有变化的当前输入按正常正式保存规则 trim 后留为 local-save，再创建 restore 节点，不修改旧版本正文。
6. 原子更新笔记与版本指针、按会话/序号删除旧草稿、替换同笔记上传任务；保留置顶/星标/排序/server_id，历史分类已删除则回退默认分类，保留云端删除及未知新建的防重复保护。
7. 本地提交成功后刷新缓存/事件，旧会话 abandon 并重读 SQLite 建立新会话；上传由既有持久队列在满足网络和云授权时处理。事务失败则完全回滚并解除保存锁，当前输入和草稿仍保留。
8. 关闭/切换选择/卸载后忽略迟到读取；恢复期间拒绝重复点击和关窗。恢复本身不等待网络，完整历史版本仍仅保存在本机。
