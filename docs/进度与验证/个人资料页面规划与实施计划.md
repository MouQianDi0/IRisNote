## 1. 目标与首版范围

让用户从「我的」第一张账户卡片，或「设置 → 个人资料」，进入同一个个人资料页面，完成账户资料查看和修改。

| 分类 | 首版规划 | 决策状态 |
| --- | --- | --- |
| 用户明确要求 | 两个入口、头像、用户名、邮箱、密码、平台绑定占位、个人简介、地区、性别 | 已明确需求，具体交互待确认 |
| 建议补充 | 用户 ID 只读与复制、注册时间只读、可选资料清空、验证码找回密码、统一保存反馈与返回保护 | 建议纳入首版 |
| 后续评估 | 恢复默认头像、生日、手机号、设备/登录记录、真实第三方绑定、账户注销 | 不纳入本次实施清单 |

- 首版围绕账户本人查看与维护资料；不新增公开个人主页、关注关系、会员或资料完成度任务。
- “用户名”暂按现有 `nickname` 映射为展示名称，页面可辅助说明“用于展示，不影响登录”；不新增唯一登录账号。邮箱继续承担现有登录标识职责。
- 简介、地区、性别为可选资料，不作为使用笔记功能的前提。
- 本文的字段长度、验证时限、地区字典与会话规则均为待确认设计，不描述为已经生效的服务端规则。

### 2.2 方案分析

1. **现象**：个人信息编辑入口分散且不完整，现有用户模型无法表达全部需求。
2. **原因**：「我的」主要承担个人内容概览；目前只有资料读取和头像上传客户端链路，还没有统一的资料编辑与账户验证流程。
3. **拟采用方案**：一个资料总览、按字段进入编辑页、邮箱与密码各自采用完整验证流程；两个入口共用同一份账户状态。
4. **选择理由**：单项保存便于判断提交结果；敏感修改可独立验证；邮箱验证失败不会影响已完成的用户名或简介修改。
5. **主要风险**：后端契约未知、旧账号缺少新增字段、验证码用途串用、修改邮箱后会话变化、异步响应覆盖新资料、云授权策略冲突。
6. **预期效果**：用户知道在哪里修改、哪些信息已经保存、失败时如何继续；返回「我的」后能看到服务端已确认的新资料。

## 3. 页面与入口规划

### 3.1 导航结构

```text
我的 → 第一张账户卡片 ─┐
                      ├→ 个人资料
设置 → 个人资料 ──────┘    ├→ 修改用户名
                           ├→ 编辑个人简介
                           ├→ 设置地区
                           ├→ 修改邮箱（同页分步骤）
                           ├→ 修改/重设密码（同页分模式）
                           ├→ 平台绑定（占位说明页）
                           ├→ 头像操作菜单 → 查看大图 / 相册 / 相机
                           └→ 性别选择弹窗
```

共 **7 个业务页面 + 4 类弹层**。验证码步骤在对应页面内切换，不为每一步新增路由；离开确认是共用弹层。

| 编号 | 页面 | 建议路由 | 页面内容 |
| --- | --- | --- | --- |
| P01 | 个人资料 | `/pages/user/profile` | 头像、基本资料、账户与安全、账户信息 |
| P02 | 修改用户名 | `/pages/user/profile/nickname` | 当前值、单行输入、字数/规则、保存 |
| P03 | 编辑个人简介 | `/pages/user/profile/bio` | 多行输入、字数、清空、保存 |
| P04 | 设置地区 | `/pages/user/profile/region` | 地区搜索、分级选择、当前路径、不设置、保存 |
| P05 | 修改邮箱 | `/pages/user/profile/email` | 原身份验证、新邮箱验证、最终提交与结果 |
| P06 | 修改密码 | `/pages/user/profile/password` | 当前密码验证、新密码、确认密码；验证码重设入口 |
| P07 | 平台绑定 | `/pages/user/profile/platforms` | 第三方平台绑定说明与“敬请期待”禁用占位 |
| M01 | 头像操作菜单 | 无独立路由 | 查看头像、从相册选择、拍照、取消 |
| M02 | 头像大图预览 | 无独立路由 | 已保存头像/待上传头像、关闭，待上传时提供确认 |
| M03 | 性别选择 | 无独立路由 | 不设置、男、女、自定义；暂存选择后点保存 |
| M04 | 未保存离开确认 | 无独立路由 | 继续编辑、放弃修改 |

### 3.2 两个入口的具体行为

- **「我的」第一卡片**：推荐整卡（含头像）点击进入 P01，右侧新增箭头；昵称、邮箱、加入时间与卡片外间距保持现状。这会把当前首页头像快捷菜单移至 P01，属于待确认的交互变更。
- **设置入口**：在标题之后、现有概览之前增加「账户」分组，放一行「个人资料」，辅助文字为“头像、用户名与账户信息”。不恢复已注释的旧账户卡片。
- 进入 P01 使用导航入栈；返回应回到实际来源「我的」或「设置」，保留来源页滚动位置。子页面返回 P01；直接链接进入且没有历史时回到 P01/P01 回到「我的」。
- 登录恢复中先展示加载态；确认未登录才进入现有登录流程。受保护的子页面和深链也检查登录态。
- 登录后的返回目标只保存允许的页面路由，不携带密码、验证码、新邮箱或未保存表单值。
- 资料页属于独立页面栈，不新增底部 Tab。既有返回动画、安全区与「我的」滚动/内容模块保持现有行为。

## 4. 字段与功能规则

| 要素 | 展示与编辑方式 | 建议规则 | 清空与默认值 |
| --- | --- | --- | --- |
| 头像 | P01 大头像；M01 选来源；M02 预览确认后上传 | 复用 1:1 系统裁剪与 2 MiB 限制；文件内容、类型和大小由服务端再次验证 | 无头像用现有默认图标；恢复默认头像需删除契约，列后续项 |
| 用户名 | 单行，进入 P02 | 暂定 1–30 个用户可见字符；去掉首尾空白，不允许全空白/换行；允许中文、表情与重名 | 旧账号未填时沿用现有显示名回退；修改时不允许提交空值 |
| 个人简介 | 总览最多两行，P03 多行输入 | 暂定 0–200 个用户可见字符；纯文本、保留合理换行；前后端字符计数统一 | 可清空；空态“介绍一下自己” |
| 地区 | 显示地区路径，进入 P04 | 国家/地区 → 省/州 → 城市，按字典决定层级，不强制每处三级；支持搜索 | 可选择“不设置”；不请求 GPS，不根据 IP 自动填入 |
| 性别 | 行尾显示当前值，M03 单选 | 推荐“不设置 / 男 / 女 / 自定义”；自定义暂定 1–20 个可见字符；均非必填 | 默认“不设置”，用户可恢复空值 |
| 邮箱 | P01 脱敏显示，P05 展示当前本人邮箱与修改流程 | 新邮箱不可与当前相同；格式、占用与验证码绑定由服务端核验；最终提交前保持旧邮箱生效 | 不允许清空 |
| 密码 | 仅显示“修改密码”入口 | 当前密码、新密码、确认密码；规则与后端统一，不回传或展示密码/哈希 | 无密码账号只有服务端明确返回能力状态才显示“设置密码” |
| 平台绑定 | P01 可进入 P07，P07 操作禁用 | 首版只说明未来支持第三方账户关联；具体平台名单待确认 | 文案“敬请期待”，不显示虚构的“已绑定/未绑定” |
| 用户 ID | 账户信息分组只读，右侧复制按钮 | 使用真实稳定 ID，支持反馈定位；不允许编辑 | 不生成另一套假的 ID |
| 注册时间 | 账户信息分组只读 | 基于 `created_at` 展示本地日期；异常值显示“暂不可用” | 不允许编辑 |

补充约束：

- 字符计数应覆盖 emoji/组合字符，前后端在契约阶段约定计数方法及服务端存储字节上限。
- 地区保存稳定编码与字典版本，展示名由字典解析；旧编码失效时保留已保存值并提示重新选择，不静默清空。
- 不收集街道/详细地址；生日与手机号没有当前业务必要性，不因“个人资料常见”而默认加入。
- 可选字段的“不设置”表示没有提供该信息，不描述为“已填写但对外保密”；公开展示能力另行设计。
- 暂不增加昵称修改次数/冷却天数；只有明确业务依据和服务端能力后才增加此类限制。

## 5. 页面整体文字预览（待用户确认）

### 5.1 共用视觉与尺寸

- 页面灰底沿用 `appBackground`（当前 `rgb(242,242,242)`），卡片白色，主操作沿用品牌蓝 `#007AFF`。
- 手机页面左右 **16dp**；设置类内容宽度沿用现有容器约定，最大 **560dp**。不扩展为新的桌面布局。
- 顶栏 **64dp**；返回触控区 **44×44dp**；标题 **24sp/Regular**。根布局已负责顶部安全区，不重复加顶部安全区。
- 卡片圆角 **16dp**，弹窗圆角 **24dp**；卡片内边距 **16dp**；分组间 **20dp**；分组标题与卡片 **8dp**。
- 普通资料行最小高 **56dp**，行内左右 **16dp**，图标与文字 **12dp**；右侧值与箭头 **8dp**。多行内容自然增高，不挤成固定高度。
- 分隔线 **1dp**，左右内缩 **16dp**；底部留 **底部安全区 + 24dp**，只由页面消费一次底部安全区。
- 编辑页输入框最小高 **52dp**；标签到输入框 **8dp**；表单项间 **16dp**；错误/说明到输入框 **8dp**；主按钮高 **52dp**。
- 主文字 **17sp**，说明 **14sp**，计数/元信息 **13sp**；颜色与字号优先使用当前主题和公共组件。
- 首版继承当前浅色方案，不把尚未接入的深色模式写成已支持；保留系统字体缩放和可访问名称。


### 5.4 P04 地区页与 M03 性别弹窗

- **地区页**：64dp 顶栏；16dp 后为 52dp 搜索框；再 12dp 为当前选择路径；再 12dp 为白色分级列表。行高至少 56dp，路径层级可返回修改；底部“保存”52dp，与列表间 24dp，所有内容可滚动。“不设置”为列表首项，选择后仍需保存。
- **性别弹窗**：屏幕外边距 24dp，面板内边距 24dp、圆角24dp、最大宽440dp。标题后12dp为选择列表，每行至少56dp；选中项浅蓝底、品牌蓝勾选。选“自定义”后，12dp 下方出现52dp输入框；列表/输入区域后24dp为按钮行。
- 性别弹窗底部左“取消”浅灰、右“保存”蓝色，等宽、间距12dp、高52dp；保存成功再关闭，保存失败保留选择。

- 成功显示明确结果；是否保留当前会话或要求重新登录依据最终后端契约，不提前展示“当前设备仍登录”之类未经确认的承诺。

### 5.6 P07 与头像、离开弹层

- **平台绑定页**：64dp 顶栏，16dp 后为白色说明卡（内边距16dp）；标题、正文间8dp；20dp后为“第三方平台绑定 · 敬请期待”禁用行，至少56dp。不给占位行绑定授权链接；不把帮助页已有 Discord 链接当作账户绑定。
- **头像菜单**：复用当前锚点菜单，建议宽232dp；显示最多4行时按行数计算高度，不能沿用当前180dp上限导致动作被裁切；每行至少56dp、左右16dp、图标与文字12dp。
- **头像预览**：AppModal 承载，屏幕左右24dp、面板内24dp；预览区按可用宽度正方形且最大280dp；关闭触控44dp。待上传状态下24dp后提供“重新选择/使用此头像”，等宽、间距12dp、高52dp；仅查看已保存头像时不显示上传按钮。
- **未保存确认**：24dp外边距与内边距；标题后12dp为“本次修改尚未保存，是否放弃？”；正文后24dp为左“放弃修改”浅灰、右“继续编辑”蓝色，按钮间12dp、高52dp。仅有改动时出现，取消选图不误触发。

## 6. 保存与账户修改流程

### 6.1 普通资料：用户名、简介、地区、性别

1. 进入编辑页时保存服务端基准值及版本；输入变更只进入当前页面状态。
2. 点击保存时验证字段，仅提交改动字段；未提供字段表示保持原值，可选字段清空明确提交 `null`。
3. 服务端确认后，以返回的完整规范化资料更新 `AuthProvider` 与当前账号缓存；再返回资料页并提示“已保存”。
4. 「我的」、资料页和设置入口如展示账户摘要，都消费相同账户状态，避免各自维护一份用户对象。
5. 保存成功但后续刷新/本地落盘失败时，区分“服务端已保存，正在刷新”与“提交失败”；不能因无回执就显示成功，也不能诱导重复提交已成功操作。
6. 超时导致结果未知时先重新读取当前资料核对，再决定是否重试；较旧响应和其他账号响应不得覆盖最新数据。
7. 首版不增加资料离线上传队列：离线可查看缓存、编辑当前页面内容，无法保存时明确提示并保留当前页输入；不承诺杀进程后恢复未提交资料。

### 6.2 头像

选择来源 → 按需请求权限 → 系统选择/裁剪 → 校验并预览 → 用户确认上传 → 服务端回执 → 刷新共享头像与缓存。

- 复用已有采集和上传方法；是否拆开现有“一次采集即上传”封装，由头像阶段文件清单明确。
- 上传中禁用重复提交；不显示没有真实进度来源的百分比。
- 无可用头像时禁用“查看头像”；上传尚在进行或结果未知时，返回流程须明确提示状态，不能把关闭页面当作服务端已经回滚。
- 上传失败继续展示旧头像，允许重试；选择取消不弹错误。超出上限给出中文提示。
- 原生裁剪行为需按 Expo 57 文档和真机确认；Web 截图不能证明相机/系统裁剪通过。[Expo 57 ImagePicker](https://docs.expo.dev/versions/v57.0.0/sdk/imagepicker/)
- 服务端核实文件内容类型，防止仅更改 MIME 标签；HEIC 等格式是否转换以及是否新增图片处理依赖，确认后单独列入范围。
- 头像缓存失效应作用于共享账户数据，不能只增加当前 `useAvatar` 实例的本地计数。

### 6.3 修改邮箱

1. 使用当前登录会话并验证原身份。推荐默认验证原邮箱验证码；后端返回与用户、用途和有效期绑定的短期验证凭据。
2. 输入新邮箱并发送专用验证码；校验格式、当前邮箱相同、已占用、发送频率、发送失败等状态。
3. 提交“原身份凭据 + 新邮箱验证”完成一次原子变更；不能先修改邮箱再验证。
4. 变更前仍使用旧邮箱登录；变更成功后更新所有账户展示，并按会话策略继续使用或重新登录。
5. 当前路由参数、本地缓存、诊断日志不得保存验证码或短期验证凭据；离开流程即丢弃，原身份未通过不能进入最终提交。
6. “无法使用原邮箱”只进入经确认的替代验证或人工找回说明；在没有真实找回机制时不得直接允许更换。
7. 账户邮箱变化的通知可列入后端设计，具体收件人、内容与发送能力需确认；本轮不发送任何邮件。

验证码有效期、重发间隔、最大尝试次数均由服务端返回/执行，客户端只展示倒计时；不能凭客户端布尔值证明身份验证成功。

### 6.4 修改与重设密码

- 正常修改：当前密码 + 新密码 + 确认密码 → 服务端验证并更新。提交前解释修改后登录状态变化。
- 忘记当前密码：验证已绑定邮箱 → 获得专用重设凭据 → 设置并确认新密码。复用 P06 页面状态，不直接复用“登录验证码验证成功”的前端状态。
- 支持密码显隐、粘贴和密码管理器；对两次新密码不一致提供就地错误。旧密码、新密码、验证码不持久化、不进入日志。
- 现有说明中的“至少6位”只作历史契约线索；新规则必须核对真实后端校验、哈希方案与字节长度限制，避免客户端接受但服务端截断。
- 推荐策略为修改成功后撤销旧会话并要求重新登录；保留当前设备需要后端明确支持新凭据轮换。最终选择列入待确认项。
- 会话失效只处理认证状态；不得清空本地笔记、草稿、同步队列或其他账号数据。

### 6.5 云存储授权与资料修改

| 请求 | 当前情况 | 首版建议 |
| --- | --- | --- |
| 读取自身资料 | `GET /user/profile` 属于基础账户请求 | 保持可用 |
| 修改头像、用户名、简介、地区、性别 | 头像已受控；新增资料写接口默认受控 | 延续云授权要求，提交前提示并由用户主动开启，不自动代授权 |
| 邮箱修改、密码修改/重设 | 相关新路由不在现有精确名单中 | 建议作为基础账户安全请求，仅对确认后的精确方法与路径放行；仍需登录/专用身份验证 |
| 平台绑定 | 首版无真实接口 | 占位页不发起授权或业务请求 |

这里的请求分类需要用户确认；不得用 `/user/*`、`/auth/*` 通配方式放开未知上传。云授权撤销、退出或切换账号时，阻止迟到回执写入当前账号。

## 7. 数据与接口规划（待后端核实）

### 7.1 数据模型建议

- 扩展用户资料：`bio`、`region`（稳定编码路径及字典版本）、`gender`、`gender_custom`、`profile_version`、`updated_at`。
- 性别默认 `null`；建议枚举 `male/female/custom`，只有 `custom` 配合自定义文本；切换为其他值时清除旧文本。
- 安全能力独立定义，例如 `has_password`、可用验证方式、邮箱验证状态；缺失状态按未知处理，不从有邮箱推断“已验证”或“已设置密码”。

- 新字段向旧账号兼容：服务端填空值/默认版本，客户端兼容字段缺失；暂不要求新增客户端 SQLite 表，先评估扩展现有用户缓存。
- 服务端迁移文件路径和编号待实际仓库核实；保存迁移、执行迁移、部署与线上验证分别记录。

## 11. 风险、遗漏与实施前反思

| 风险/遗漏 | 影响 | 处理计划 |
| --- | --- | --- |
| 后端未核实 | 页面可以完成但无法真实保存/验证 | S01 核实实际后端，冻结接口后再实施依赖部分 |
| 邮箱/密码修改触发退出 | 用户担心资料或未同步笔记丢失 | 确认会话策略，保留本地业务数据；操作前清楚说明 |
| 原邮箱不可用 | 改邮箱流程无法完成 | 明确真实替代验证/人工找回路径，不临时绕过验证 |
| 头像上传成功但资料刷新失败 | 显示旧头像却提示成功 | 回执与刷新拆开处理，共享头像版本并核对最终状态 |
| 多设备同时改资料/切换账号 | 旧值覆盖新值、写错当前账户 | 条件更新、请求身份/代际校验、冲突反馈 |
| 地区字典覆盖/许可不清 | 无法选择或未来编码无法解析 | 确认来源和版本策略后再接入，不先写死随意数据 |
| 用户名被误认为唯一登录名 | 用户以为改名会改变登录方式 | 辅助说明展示名语义；要求唯一账号时另行评估 |
| 新验证码复用注册/登录用途 | 跨流程凭据误用 | 服务端按目的隔离，前端使用独立流程与类型 |
| 既有公共组件与旧文档有差异 | 重复实现或样式漂移 | 以当前源码与主题为准，例如 DialogButton 已位于共享目录 |

**眼下最没有把握的事情是什么？**

账户后端真实支持哪些资料修改、身份验证和会话撤销能力。当前只证实了客户端接入情况，不能据 API 说明断言已部署；这是 S01 最先核实的依赖。

**关于当前情况，最大的遗漏是什么，我没有意识到什么？**

这项工作不仅增加几个输入框，还会改变身份信息与共享会话。最容易漏掉“云存储关闭时能否修改密码”“原邮箱无法接收验证码”“修改成功但本地刷新失败”“旧账号无安全状态字段”“切换账号后的迟到回执”和“重新登录后未同步笔记仍在”。这些必须在前后端契约和真机验收中显式覆盖。

- **实际切换能力以当前界面为准**。上述为任务配置建议，不代表已经启用，不替代用户确认，不扩大授权范围。
