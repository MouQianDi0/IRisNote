# 本地测试包构建指南（staging）

> 适用场景：给测试人员分发一个**免 Metro 开发服务器、免电脑连线、可独立运行**的测试 APK。
> 本文所有内容只涉及**本机测试包**，与正式发布流程（`docs/构建发布/android-releases.md`）互不影响。

## 一、测试包是什么

| 项 | 测试包（staging） | 正式包（release） |
| --- | --- | --- |
| 包名 | `com.mouqiandi.irisNote.staging` | `com.mouqiandi.irisNote` |
| 桌面显示名 | **IRisNote 测试** | IRisNote |
| 打包方式 | release 式（内嵌 JS bundle + Hermes 字节码 + 符号裁剪） | 同左 |
| 签名证书 | Debug 证书（本机 `debug.keystore`） | 生产正式证书 |
| 是否需要 Metro | 不需要，独立运行 | 不需要 |
| 应用内更新 | 自动禁用（包名非正式包名） | 走自有 `/api/releases` 更新接口 |
| 数据 | 与正式包完全隔离（独立数据库/存储/文件） | — |

**共存说明**：测试包与正式包包名不同，Android 视为两个独立应用，可同时安装、互不覆盖、互不影响升级。
两者本地数据（SQLite、AsyncStorage、文件目录）完全隔离，测试数据不会污染正式包。
应用内更新检查按包名判断（`updateSupported()` 要求 `applicationId === "com.mouqiandi.irisNote"`），
测试包中该功能自动禁用，手动检查只会提示"请在正式 Android 安装包中检查更新"，
不存在测试包误装正式更新包的风险。

**注意**：登录同一账号时云端数据不隔离（如云存储同步会连同一服务端账号，双向同步），测试时留意。

## 二、新电脑从零构建

> **前提**（本文不展开）：新电脑已装好 Node.js ≥ 20、JDK 17、Android SDK
> （Platform 36 + Build-Tools 35.0.0 + Platform-Tools + **NDK 27.1.12297006 + CMake 3.22.1**），
> 系统环境变量 `JAVA_HOME`、`ANDROID_HOME` 已设置。
> 其中 SDK/NDK/CMake 版本是构建链注入的默认值（随 Expo SDK 演进可能变化，以构建报错提示为准）；
> **NDK 与 CMake 缺失时构建会在原生编译阶段失败**（冷构建十几分钟后才报错，极难排查）——
> 暂不手装也可以，但需先执行 `sdkmanager --licenses` 接受许可，让 Gradle 自动下载补齐。
> 项目构建脚本会自动给 Gradle 子进程注入 `JAVA_TOOL_OPTIONS`（Windows 回环连接修复）并加
> `--no-daemon`，这些都不需要手动配置。
>
> Git 仓库里**没有** `android/`、`.expo/`、`debug.keystore`（全部被忽略，见第五节），
> 下面从克隆代码开始，到产出 `app-staging.apk` 结束，**按步骤 1 → 7 顺序执行一遍**即可；
> 之后再打新包只需重复步骤 7。

### 步骤 1：克隆代码并安装依赖

```powershell
git clone https://github.com/MouQianDi0/IRisNote.git
cd IRisNote
npm install
```

- `npm install` 结束时会自动执行 `postinstall: patch-package`，应用
  `patches/react-native-tab-view+4.3.2.patch`（主页面横滑切页手感补丁），正常会打印 patch 成功；
  **不要**加 `--ignore-scripts` 跳过，否则横滑行为会回退。
- npm 官方源慢/失败时临时换镜像：

  ```powershell
  npm config set registry https://registry.npmmirror.com
  # 用完恢复：npm config delete registry
  ```

- 项目放在**纯英文、无空格、尽量短**的路径（本机为 `D:\IRisNote`）：构建脚本会校验 `.expo`
  下 Gradle socket 路径不超过 100 字节，路径过深会在构建启动时直接报「Gradle socket 路径过长」，
  届时按报错提示用环境变量 `IRIS_GRADLE_SOCKET_DIR` 指定一个可写的短目录即可；
  浅路径还能一并规避 Windows 260 字符路径上限。

### 步骤 2：创建 `.env.local`（可选，默认可不建）

当前项目**不建 `.env.local` 也能直接打包**，默认行为即正常测试包行为：

- 云存储功能**默认开放**：统一云功能门 `EXPO_PUBLIC_CLOUD_STORAGE_ENABLED` 未配置、空值或 `1` 时开放，
  `0` 或非法值时关闭（`src/core/cloud-storage/cloud-storage-policy.ts`）；即使开放，用户仍须登录后
  在本设备主动授权，并非自动上传。
- API 地址**默认即正式接口**：不设 `EXPO_PUBLIC_BASE_URL` 时，代码默认连
  `https://tech-mou.top/api`（`src/shared/http/client.ts` 的 `DEFAULT_API_BASE_URL`）。

仅在需要显式覆盖默认行为时，才在**项目根目录**创建 `.env.local`，例如：

```ini
# 可选：显式关闭云存储功能（不写该变量默认开放）
# EXPO_PUBLIC_CLOUD_STORAGE_ENABLED=0
# 可选：覆盖 API 地址（默认 https://tech-mou.top/api）
# EXPO_PUBLIC_BASE_URL=https://tech-mou.top/api
```

- 注意：旧的 `EXPO_PUBLIC_TODO_CLOUD_SYNC` 开关已随统一云存储改造**废弃，不再生效**，写了也没用。
- 打包时该文件内容会被**内嵌进 APK 的 JS bundle**，改动后需重新打包才生效。

### 步骤 3：生成 Android 工程

`android/` 整目录被 Git 忽略，仓库里没有，用 Expo 生成：

```powershell
npx expo prebuild -p android --no-install
```

首次运行需联网下载 Expo 的 Android 模板，随后生成完整 `android/` 工程
（`gradlew.bat`、`settings.gradle`、`android/app/debug.keystore` 等）。

### 步骤 4：加回 staging 构建块（必做）

prebuild 生成的工程里**没有** staging 配置，不加这步构建会直接报
`Task 'assembleStaging' not found`。

编辑 `android\app\build.gradle`，在 `buildTypes { ... }` 内、`release { ... }` 块之后加入：

```groovy
// 本地独立测试包：release 式打包（内嵌 JS/Hermes），Debug 证书签名。
// 仅用于本地分发测试；正式发布仍走发布工具（assembleRelease + 生产证书守卫）。
staging {
    initWith release
    matchingFallbacks = ['release']
    signingConfig signingConfigs.debug
    // 独立包名 com.mouqiandi.irisNote.staging：可与正式包共存、数据隔离；
    // 应用内更新器按 applicationId 判断，非正式包名时自动禁用（updateSupported）。
    applicationIdSuffix ".staging"
    // 桌面图标与应用名区分正式包，避免两个同名应用无法分辨。
    resValue "string", "app_name", "IRisNote 测试"
}
```

保存即可（同一段代码也留在第六节，供日后 `android/` 重新生成时快速找回）。

### 步骤 5：确认签名证书（通常无需操作）

`android\app\debug.keystore` 由 prebuild 自带，是 React Native 生态**统一的公开调试证书**
（storepass/keypass 均为 `android`，别名 `androiddebugkey`），所有机器生成的相同，
因此新电脑打的测试包与现有测试包**可互相覆盖升级**。需要核对时执行：

```powershell
& "$env:JAVA_HOME\bin\keytool.exe" -list -v -keystore .\android\app\debug.keystore -storepass android
# SHA256 应为：
# FA:C6:17:45:DC:09:03:78:6F:B9:ED:E6:2A:96:2B:39:9F:73:48:F0:BB:6F:89:9B:83:32:66:75:91:03:3B:9C
```

只有指纹不一致（说明该机器曾手工换过证书）时，才需要从旧电脑拷贝 `debug.keystore` 覆盖。

### 步骤 6：创建阿里云镜像脚本

国内网络直连 `dl.google.com` 下载 Gradle 依赖时 TLS 握手会被中断（原理见第四节），
**不建此脚本构建必失败**。`.expo/` 同样不入库，在**项目根目录**执行：

```powershell
New-Item -ItemType Directory -Force -Path .\.expo | Out-Null
@'
// Aliyun mirror fallback repos for local command-line builds.
// Injected via --init-script with an absolute path; lives under git-ignored .expo/.
allprojects {
    buildscript {
        repositories {
            maven { url 'https://maven.aliyun.com/repository/google' }
            maven { url 'https://maven.aliyun.com/repository/public' }
        }
    }
    repositories {
        maven { url 'https://maven.aliyun.com/repository/google' }
        maven { url 'https://maven.aliyun.com/repository/public' }
    }
}
'@ | Set-Content -Encoding ascii .\.expo\gradle-aliyun-init.gradle
```

### 步骤 7：构建

```powershell
# 常规：只打 arm64（现代手机，体积小，推荐）
npm run gradle -- assembleStaging -PreactNativeArchitectures=arm64-v8a --init-script "$PWD\.expo\gradle-aliyun-init.gradle"

# 需要全 ABI 时（去掉 -PreactNativeArchitectures 参数即可）
npm run gradle -- assembleStaging --init-script "$PWD\.expo\gradle-aliyun-init.gradle"
```

- `--init-script` 必须是**绝对路径**（`"$PWD\.expo\..."` 会自动展开为当前项目根的绝对路径）；
  相对路径会被解析到 `android/.expo/` 导致找不到文件。
- 首次构建 Gradle wrapper 会先下载发行版 zip（当前为 `gradle-9.3.1-bin.zip`，约 130 MB；
  版本随 Expo 模板演进可能变化，以 `android\gradle\wrapper\gradle-wrapper.properties` 的
  `distributionUrl` 实际文件名为准）；
  卡在 `Downloading https://services.gradle.org/...` 时，把
  `android\gradle\wrapper\gradle-wrapper.properties` 的 `distributionUrl` 临时改为腾讯镜像
  `https\://mirrors.cloud.tencent.com/gradle/<同版本文件名>`（只换域名、文件名保持不变；
  `android/` 是本地目录，随便改）。
- 全量冷构建约 19 分钟；依赖与原生编译有缓存后显著更快。
- **产物**：`android\app\build\outputs\apk\staging\app-staging.apk`
- 打包的是**当前工作区源码**（未提交的改动也会进包）；依赖偶发下载超时直接重跑同一命令，
  Gradle 会复用已完成任务。

### 之后

日常出新测试包**只重复步骤 7**（源码改动无需 prebuild）。只有 `android/` 被删除或重新
prebuild 后，才需要重做步骤 4（staging 块）和步骤 6（镜像脚本）。

## 三、构建命令（速查）

在项目根目录执行（本机为 `D:\IRisNote`，新机器按实际克隆路径）：

```powershell
# 常规：只打 arm64（现代手机，体积小，推荐）
npm run gradle -- assembleStaging -PreactNativeArchitectures=arm64-v8a --init-script "$PWD\.expo\gradle-aliyun-init.gradle"

# 需要全 ABI 时（去掉 -PreactNativeArchitectures 参数即可）
npm run gradle -- assembleStaging --init-script "$PWD\.expo\gradle-aliyun-init.gradle"
```

- **产物位置**：`android/app/build/outputs/apk/staging/app-staging.apk`
- **耗时参考**：全量冷构建约 19 分钟；依赖与原生编译有缓存时显著更快（大部分任务 up-to-date）。
- 打包的是**当前工作区源码**（未提交的改动也会进包），`.env.local` 会被读取并内嵌（如统一云功能门 `EXPO_PUBLIC_CLOUD_STORAGE_ENABLED`）；这与正式发布"只从 Git 提交导出"不同。该变量未配置、空值或 `1` 时开放功能，`0` 或非法值关闭；用户仍须按当前账号在本设备主动授权，旧待办开关不再生效。
- 本文命令均为 **PowerShell 语法**：`$PWD` 会展开为当前目录的绝对路径；若用 cmd.exe，需把
  `--init-script` 参数里的 `"$PWD\.expo\gradle-aliyun-init.gradle"` 手动替换为项目根的绝对路径。

## 四、阿里云镜像脚本（关键）

### 为什么需要

Gradle 默认从 `dl.google.com`（google()）和 `repo.maven.apache.org`（mavenCentral()）下载依赖。
本机网络直连 `dl.google.com` 时 TLS 握手会被中断（报错 `Remote host terminated the handshake`），
导致 androidx 等依赖下载失败、构建中断。

### 脚本位置与原理

- **位置**：项目根目录下 `.expo\gradle-aliyun-init.gradle`（本机为 `D:\IRisNote\.expo\gradle-aliyun-init.gradle`；
  **新电脑的创建方式见第二节步骤 6**）
- **原理**：通过 `--init-script` 注入，在 google()/mavenCentral() 之前追加阿里云 google/public 镜像仓库，
  优先走镜像下载，原仓库自动兜底；不修改工程文件、不改全局 Gradle 配置。

```groovy
// .expo/gradle-aliyun-init.gradle
allprojects {
    buildscript {
        repositories {
            maven { url 'https://maven.aliyun.com/repository/google' }
            maven { url 'https://maven.aliyun.com/repository/public' }
        }
    }
    repositories {
        maven { url 'https://maven.aliyun.com/repository/google' }
        maven { url 'https://maven.aliyun.com/repository/public' }
    }
}
```

### 使用注意

1. **必须用绝对路径**：`npm run gradle` 是在 `android/` 目录下调 Gradle 的，
   相对路径（如 `.expo\...`）会被解析到 `android/.expo/` 导致找不到文件。
2. 之前放在系统 Temp 的旧脚本（`%TEMP%\gradle-aliyun-init.gradle`）已废弃，不要再用。
3. 若镜像也偶发超时，重跑同一命令即可，Gradle 会复用已完成任务，只重试失败部分。

## 五、Git 忽略说明（为什么这些改动不进版本库）

| 路径 | Git 状态 | 说明 |
| --- | --- | --- |
| `.expo/` | 整目录忽略（.gitignore 第 8 行） | 镜像脚本、ninja 工具、delta 测试产物都放这里 |
| `android/` | 整目录忽略（.gitignore 第 52 行） | 本地预构建目录；staging 构建类型、包名后缀等配置只存在于本机 |
| `.env*.local` | 忽略（.gitignore 第 43 行） | 本地环境变量，含 `.env.local` 与正式发布的 `.env.release.local` |
| `*.keystore` / `*.jks` | 忽略（.gitignore 第 20-21 行） | 签名证书不入库 |

- **`android/` 是本地预构建目录**：`staging` 构建块（含包名后缀）写在 `android/app/build.gradle`，
  只对本机构建生效，不进版本库。正式发布工具会从 Git 提交导出源码并**重新生成** Android 工程，
  天然不含 staging，因此测试包配置不可能混入正式发布。
- **代价**：如果 `android/` 被删除或用 `expo prebuild` 重新生成，staging 构建块会丢失，
  需按本文档第六节的代码手动加回。新电脑首次搭建即此场景，完整流程见第二节。

## 七、限制与常见问题

- **http 明文地址不可用**：staging 用 main manifest，无 Debug 变体的 cleartext 配置，
  只能连 HTTPS 接口（如 `https://tech-mou.top/api`）。
- **签名注意**：Debug 证书来自本机 `android/app/debug.keystore`，测试包之间覆盖升级需同一 keystore
  （新电脑 prebuild 自带的是同一公开证书，见第二节步骤 5）；
  与正式包（生产证书）即使包名相同也无法互相覆盖——现在包名不同，彻底无关。
- **依赖下载失败**（`Could not HEAD 'https://dl.google.com/...'` / `Remote host terminated the handshake`）：
  检查命令是否带了 `--init-script <项目根>\.expo\gradle-aliyun-init.gradle`（绝对路径）。
- **npm install 后出现两条新机器现象（npm 11 行为，均无害）**：一是警告
  `npm warn allow-scripts ... unrs-resolver@... (postinstall)`，不影响安装与构建，可忽略；
  二是 `git status` 显示 `package-lock.json` 被改（根包多一行 `"hasInstallScript": true`），
  是 allow-scripts 记录的项目元数据，忽略或不提交均可。
- **原生编译报缺 NDK / CMake**（如 `Could not find NDK` / cmake 相关报错）：按第二节前提安装
  NDK 27.1.12297006 与 CMake 3.22.1，或先 `sdkmanager --licenses` 接受许可后让 Gradle 自动下载。
- **Gradle 发行版下载卡住/失败**（首次构建停在 `Downloading https://services.gradle.org/distributions/...`）：
  按第二节步骤 7 临时改用腾讯镜像（文件名保持 wrapper 里的实际版本，只换域名）。
- **npm install 慢或失败**：按第二节步骤 1 临时切换 npmmirror 镜像。
- **expo-dev-client 在非 debuggable 构建中的运行时行为**待装机确认（staging 非 debuggable）。
- 构建中断/取消后残留的 java 进程可能锁住 `android/` 目录：确认无构建在进行后，
  可结束 `$env:JAVA_HOME` 下的 `java.exe`（gradle-wrapper / Gradle daemon）进程再重跑；
  VS Code 的 Java 语言服务进程（路径含 `.vscode\extensions`）与此无关，不要动。
