# 本地测试包构建指南（staging）

> 适用场景：给测试人员分发一个**免 Metro 开发服务器、免电脑连线、可独立运行**的测试 APK。
> 本文所有内容只涉及**本机测试包**，与正式发布流程（`docs/构建发布/android-releases.md`）互不影响。

## 一、测试包是什么

| 项 | 测试包（staging） | 正式包（release） |
| --- | --- | --- |
| 包名 | `com.mouqiandi.irisNote.staging` | `com.mouqiandi.irisNote` |
| 桌面显示名 | **IRisNote 测试** | IRisNote |
| 打包方式 | release 式（内嵌 JS bundle + Hermes 字节码 + 符号裁剪） | 同左 |
| 签名证书 | Debug 证书（本机 `debug.keystore`） | 生产正式证书 |
| 是否需要 Metro | 不需要，独立运行 | 不需要 |
| 应用内更新 | 自动禁用（包名非正式包名） | 走自有 `/api/releases` 更新接口 |
| 数据 | 与正式包完全隔离（独立数据库/存储/文件） | — |

**共存说明**：测试包与正式包包名不同，Android 视为两个独立应用，可同时安装、互不覆盖、互不影响升级。
两者本地数据（SQLite、AsyncStorage、文件目录）完全隔离，测试数据不会污染正式包。
应用内更新检查按包名判断（`updateSupported()` 要求 `applicationId === "com.mouqiandi.irisNote"`），
测试包中该功能自动禁用，手动检查只会提示"请在正式 Android 安装包中检查更新"，
不存在测试包误装正式更新包的风险。

**注意**：登录同一账号时云端数据不隔离（如 Todo 云同步会连同一服务端账号，双向同步），测试时留意。

## 二、新电脑从零搭建

> Git 仓库里**没有** `android/` 目录、`.expo/` 目录、`.env.local` 和 `debug.keystore`（全部被忽略，见第五节），
> 新电脑克隆后必须按下述步骤重建，缺一不可。按 2.1 → 2.8 顺序执行一遍后，后续日常构建只需第三节命令。

### 2.1 软件清单

| 组件 | 版本要求 | 本机实测版本 | 说明 |
| --- | --- | --- | --- |
| Git | 任意较新 2.x | — | 克隆代码用 |
| Node.js | ≥ 22.13.x（建议 LTS） | v24.18.0（win-x64） | Expo SDK 57 的最低 Node 版本；`npm run gradle` 入口脚本和 Expo CLI 都依赖它 |
| JDK | 17（建议） | OpenJDK 21.0.12.1 | Expo Android 环境文档以 JDK 17 为基线；本机以 JDK 21 通过编译，但新电脑优先安装 17，避免工具链差异 |
| Android SDK | Platform 36 + Build-Tools 36.0.0 + Platform-Tools | `D:\Android\Sdk` | compileSdk/targetSdk = 36、minSdk = 24（Expo SDK 57 默认） |
| Gradle | **无需手动安装** | 9.3.1 | wrapper 首次构建自动下载，见 2.8 |

- 不需要 Ninja / HDiffPatch（那是正式发布构建的差分工具链）；不需要 EAS 账号。
- Android SDK 两种获得方式：
  1. **装 Android Studio**（最省心），由其 SDK Manager 安装上述组件并自动接受许可；
  2. 只装 **commandline-tools**，然后用 `sdkmanager` 手动装：

     ```powershell
     sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0"
     sdkmanager --licenses   # 全部接受
     ```

     `sdkmanager` 位于 `<Android SDK>\cmdline-tools\latest\bin`；未加入 `PATH` 时请在该目录执行，
     或改用 Android Studio 的 SDK Manager。若首次构建仍提示缺少其他 SDK 组件，按报错中的
     包名用 `sdkmanager` 补装即可。

### 2.2 系统环境变量（必设）

新电脑必须设置以下两个**系统级用户变量**（值按新机器实际安装路径替换）：

| 变量 | 本机值（示例） | 用途 |
| --- | --- | --- |
| `JAVA_HOME` | `D:\Android\jdks\jdk-17.0.20.1+1` | Gradle 定位 JDK 17 |
| `ANDROID_HOME` | `D:\Android\Sdk` | Gradle 定位 Android SDK |
| `PATH` 追加 | `%ANDROID_HOME%\platform-tools` | 可选，提供 `adb` 命令 |

PowerShell 设置（设置完**重开终端**生效）：

```powershell
setx JAVA_HOME "D:\Android\jdks\jdk-17.0.20.1+1"
setx ANDROID_HOME "D:\Android\Sdk"
```

**以下变量不要手动设置**（项目脚本自动处理）：

- `JAVA_TOOL_OPTIONS`：`npm run gradle` / `npm run android` 会自动给 Gradle 子进程注入
  `-Djdk.net.unixdomain.tmpdir=<项目>\.expo`，修复 Windows 下 Java 回环连接失败
  （原理见 `docs/构建发布/android-releases.md`「Java 回环连接」一节）。
- `IRIS_GRADLE_SOCKET_DIR`：仅当项目 `.expo` 路径过长或不可写、构建报
  "Gradle socket 路径过长"时，才需要手动指定一个可写短路径。

验证：

```powershell
java -version                # 新电脑建议显示 openjdk version "17.x"
node -v                      # v22.13.x+
echo $env:JAVA_HOME          # JDK 17 实际路径
echo $env:ANDROID_HOME       # Android SDK 实际路径
```

### 2.3 获取代码与安装依赖

```powershell
git clone https://github.com/MouQianDi0/IRisNote.git
cd IRisNote
npm ci
```

- `npm ci` 会严格按仓库 `package-lock.json` 安装，并自动执行 `postinstall: patch-package`，应用
  `patches/react-native-tab-view+4.3.2.patch`——**不要**加 `--ignore-scripts` 跳过。
- npm 官方源慢/失败时临时切换镜像：

  ```powershell
  npm config set registry https://registry.npmmirror.com
  # 用完可恢复：npm config delete registry
  ```

- 建议把项目放在**纯英文、无空格**的路径下（本机为 `D:\IRisNote`），避免各工具链的路径兼容问题。

### 2.4 创建 `.env.local`（必建）

`.env*.local` 被 Git 忽略，克隆下来没有。在**项目根目录**创建 `.env.local`，内容如下：

```ini
# Enables logged-in Todo cloud sync for local Expo sessions.
EXPO_PUBLIC_TODO_CLOUD_SYNC=1
```

| 变量 | 是否必填 | 作用 |
| --- | --- | --- |
| `EXPO_PUBLIC_TODO_CLOUD_SYNC` | 必填（与正式行为一致） | `1` = 启用 Todo 云同步功能 |
| `EXPO_PUBLIC_BASE_URL` | 可选，默认不设 | 不设时代码默认 `https://tech-mou.top/api`（`src/shared/http/client.ts` 的 `DEFAULT_API_BASE_URL`）；测试包只能连 HTTPS，见第七节 |
| `EXPO_PUBLIC_RELEASE_API_URL` | 可选，默认不设 | 不设时由上述基础地址拼接 `/releases`；staging 包会禁用应用内更新，通常无需设置 |

注意：这些 `EXPO_PUBLIC_*` 变量在打 staging 包时会被**内嵌进 JS bundle**（见第三节说明）。

### 2.5 生成 Android 工程，加回 staging 块

`android/` 整目录不入库，用 Expo 重新生成：

```powershell
npx expo prebuild -p android --no-install
```

- 首次运行需联网下载 Expo 的 Android 模板；生成物含 `gradlew.bat`、`settings.gradle`、
  `android/app/debug.keystore` 等完整工程。
- **生成后必须**按第六节的代码把 `staging` 构建块加进 `android/app/build.gradle` 的
  `buildTypes`，否则没有 `assembleStaging` 任务、打不出测试包。
- 若日后 `android/` 被删除或重新 prebuild，staging 块会再次丢失，同样按第六节加回。

### 2.6 debug.keystore（签名证书，自动生成，无需迁移）

- prebuild 生成的 `android/app/debug.keystore` 是 React Native 生态**统一的公开调试证书**
  （storepass/keypass 均为 `android`，别名 `androiddebugkey`），所有机器生成的相同。
- 本机证书指纹（SHA256）：

  ```
  FA:C6:17:45:DC:09:03:78:6F:B9:ED:E6:2A:96:2B:39:9F:73:48:F0:BB:6F:89:9B:83:32:66:75:91:03:3B:9C
  ```

- 新电脑生成后可用下述命令核对指纹一致（一致则新旧测试包可互相覆盖升级）：

  ```powershell
  & "$env:JAVA_HOME\bin\keytool.exe" -list -v -keystore .\android\app\debug.keystore -storepass android
  ```

- 只有在曾手工替换过证书的机器上，才需要从旧电脑拷贝 `debug.keystore` 覆盖。

### 2.7 重建阿里云镜像脚本

`.expo/` 目录不入库，新电脑需手动创建镜像脚本（作用见第四节）。在**项目根目录**执行：

```powershell
New-Item -ItemType Directory -Force -Path .\.expo | Out-Null
@'
// Aliyun mirror fallback repos for local command-line builds.
// Injected via --init-script with an absolute path; lives under git-ignored .expo/.
allprojects {
    buildscript {
        repositories {
            maven { url 'https://maven.aliyun.com/repository/google' }
            maven { url 'https://maven.aliyun.com/repository/public' }
        }
    }
    repositories {
        maven { url 'https://maven.aliyun.com/repository/google' }
        maven { url 'https://maven.aliyun.com/repository/public' }
    }
}
'@ | Set-Content -Encoding ascii .\.expo\gradle-aliyun-init.gradle
```

（脚本内容与本机既有版本一致，仅注释为英文，避免跨机器编码问题。）

### 2.8 Gradle 发行版首次下载

首次构建时 Gradle wrapper 会从 `services.gradle.org` 下载 `gradle-9.3.1-bin.zip`
（约 130 MB，存到 `%USERPROFILE%\.gradle\wrapper\dists`），此后不再下载。

直连官方源慢/失败时，临时把 `android\gradle\wrapper\gradle-wrapper.properties` 的
`distributionUrl` 改为腾讯镜像：

```properties
distributionUrl=https\://mirrors.cloud.tencent.com/gradle/gradle-9.3.1-bin.zip
```

`android/` 是本地目录（不入库），此改动只影响本机；下载完成后可改回，也可保留。

## 三、构建命令

在项目根目录执行（本机为 `D:\IRisNote`，新机器按实际克隆路径）：

```powershell
# 常规：只打 arm64（现代手机，体积小，推荐）
# --init-script 必须给绝对路径；PowerShell 下写 "$PWD\.expo\gradle-aliyun-init.gradle" 会自动展开为当前项目根的绝对路径
npm run gradle -- assembleStaging -PreactNativeArchitectures=arm64-v8a --init-script "$PWD\.expo\gradle-aliyun-init.gradle"

# 需要全 ABI 时（去掉 -PreactNativeArchitectures 参数即可）
npm run gradle -- assembleStaging --init-script "$PWD\.expo\gradle-aliyun-init.gradle"
```

- **产物位置**：`android/app/build/outputs/apk/staging/app-staging.apk`
- **耗时参考**：全量冷构建约 19 分钟；依赖与原生编译有缓存时显著更快（大部分任务 up-to-date）。
- 打包的是**当前工作区源码**（未提交的改动也会进包），`.env.local` 会被读取并内嵌（如 `EXPO_PUBLIC_TODO_CLOUD_SYNC`）；这与正式发布"只从 Git 提交导出"不同。

## 四、阿里云镜像脚本（关键）

### 为什么需要

Gradle 默认从 `dl.google.com`（google()）和 `repo.maven.apache.org`（mavenCentral()）下载依赖。
本机网络直连 `dl.google.com` 时 TLS 握手会被中断（报错 `Remote host terminated the handshake`），
导致 androidx 等依赖下载失败、构建中断。

### 脚本位置与原理

- **位置**：项目根目录下 `.expo\gradle-aliyun-init.gradle`（本机为 `D:\IRisNote\.expo\gradle-aliyun-init.gradle`；
  **新电脑的创建方式见第二节 2.7**）
- **原理**：通过 `--init-script` 注入，在 google()/mavenCentral() 之前追加阿里云 google/public 镜像仓库，
  优先走镜像下载，原仓库自动兜底；不修改工程文件、不改全局 Gradle 配置。

```groovy
// .expo/gradle-aliyun-init.gradle
allprojects {
    buildscript {
        repositories {
            maven { url 'https://maven.aliyun.com/repository/google' }
            maven { url 'https://maven.aliyun.com/repository/public' }
        }
    }
    repositories {
        maven { url 'https://maven.aliyun.com/repository/google' }
        maven { url 'https://maven.aliyun.com/repository/public' }
    }
}
```

### 使用注意

1. **必须用绝对路径**：`npm run gradle` 是在 `android/` 目录下调 Gradle 的，
   相对路径（如 `.expo\...`）会被解析到 `android/.expo/` 导致找不到文件。
2. 之前放在系统 Temp 的旧脚本（`%TEMP%\gradle-aliyun-init.gradle`）已废弃，不要再用。
3. 若镜像也偶发超时，重跑同一命令即可，Gradle 会复用已完成任务，只重试失败部分。

## 五、Git 忽略说明（为什么这些改动不进版本库）

| 路径 | Git 状态 | 说明 |
| --- | --- | --- |
| `.expo/` | 整目录忽略（.gitignore 第 8 行） | 镜像脚本、ninja 工具、delta 测试产物都放这里 |
| `android/` | 整目录忽略（.gitignore 第 52 行） | 本地预构建目录；staging 构建类型、包名后缀等配置只存在于本机 |
| `.env*.local` | 忽略（.gitignore 第 43 行） | 本地环境变量，含 `.env.local` 与正式发布的 `.env.release.local` |
| `*.keystore` / `*.jks` | 忽略（.gitignore 第 21-22 行） | 签名证书不入库 |

- **`android/` 是本地预构建目录**：`staging` 构建块（含包名后缀）写在 `android/app/build.gradle`，
  只对本机构建生效，不进版本库。正式发布工具会从 Git 提交导出源码并**重新生成** Android 工程，
  天然不含 staging，因此测试包配置不可能混入正式发布。
- **代价**：如果 `android/` 被删除或用 `expo prebuild` 重新生成，staging 构建块会丢失，
  需按本文档第六节的代码手动加回。新电脑首次搭建即此场景，完整流程见第二节。

## 六、staging 构建块参考（android/app/build.gradle）

`android/app/build.gradle` 的 `buildTypes` 中（丢失时按此加回）：

```groovy
// 本地独立测试包：release 式打包（内嵌 JS/Hermes），Debug 证书签名。
// 仅用于本地分发测试；正式发布仍走发布工具（assembleRelease + 生产证书守卫）。
staging {
    initWith release
    matchingFallbacks = ['release']
    signingConfig signingConfigs.debug
    // 独立包名 com.mouqiandi.irisNote.staging：可与正式包共存、数据隔离；
    // 应用内更新器按 applicationId 判断，非正式包名时自动禁用（updateSupported）。
    applicationIdSuffix ".staging"
    // 桌面图标与应用名区分正式包，避免两个同名应用无法分辨。
    resValue "string", "app_name", "IRisNote 测试"
}
```

## 七、限制与常见问题

- **http 明文地址不可用**：staging 用 main manifest，无 Debug 变体的 cleartext 配置，
  只能连 HTTPS 接口（如 `https://tech-mou.top/api`）。
- **签名注意**：Debug 证书来自本机 `android/app/debug.keystore`，测试包之间覆盖升级需同一 keystore
  （新电脑 prebuild 自带的是同一公开证书，见 2.6）；
  与正式包（生产证书）即使包名相同也无法互相覆盖——现在包名不同，彻底无关。
- **依赖下载失败**（`Could not HEAD 'https://dl.google.com/...'` / `Remote host terminated the handshake`）：
  检查命令是否带了 `--init-script <项目根>\.expo\gradle-aliyun-init.gradle`（绝对路径）。
- **Gradle 发行版下载卡住/失败**（首次构建停在 `Downloading https://services.gradle.org/distributions/gradle-9.3.1-bin.zip`）：
  按 2.8 临时改用腾讯镜像。
- **npm install 慢或失败**：按 2.3 临时切换 npmmirror 镜像。
- **expo-dev-client 在非 debuggable 构建中的运行时行为**待装机确认（staging 非 debuggable）。
- 构建中断/取消后残留的 java 进程可能锁住 `android/` 目录：确认无构建在进行后，
  可结束 `$env:JAVA_HOME` 下的 `java.exe`（gradle-wrapper / Gradle daemon）进程再重跑；
  VS Code 的 Java 语言服务进程（路径含 `.vscode\extensions`）与此无关，不要动。
