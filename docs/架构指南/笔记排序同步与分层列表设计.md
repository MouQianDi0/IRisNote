# 笔记排序同步与分层列表设计

> 版本 v1.0（2026-09-17 立项稿）。状态：设计已确认，未实施。实施前 UI 分层部分须按变更管控流程补文字预览。

## 1. 背景与问题

- **闪退**：release 包（versionCode 2）三次在启动约 40-48 秒前台闪退，Fabric `addViewAt: failed to insert view at index 13`，根因 `The specified child already has a parent`。
- **根因链**：`GET /notes` 不下发排序字段，客户端 `reconcileServerNotes` 每次同步无条件重写 `local_order`（覆盖为服务端数组下标）、抹空 `pinned_order`、刷新 `local_updated_at` → 服务端回包后整表排序改变 → FlatList 批量挂载窗口内整表 key 搬移 → RN 0.86 Fabric「插入先于移除」竞态崩溃。
- **伴生数据丢失**：用户排定的置顶顺序每次同步被抹空。
- **多端不一致**：置顶/标星顺序无云端状态，设备间各自为政。

**阶段一护栏已落地**（2026-09-16，`reconcileServerNotes` 无变化行跳过 + 排序字段保序回填，见 CHANGELOG 2026-09-16 23:46:17）：消除「无变化回包引发的重排」，并使 `local_updated_at` 回归「本地最后编辑时间」语义。本设计的推导排序以其为兼容层。

## 2. 设计总则

**排序不是需要同步的状态，而是从已同步字段推导的函数。**

排序键全部由服务端字段推导：`is_pinned`、`is_starred`、`pinned_at`、`starred_at`、`updated_at`、`id`。所有设备从同一份数据算出同一顺序，排序冲突问题不复存在，无需独立排序值上传、无需 LWW 比较协议。

## 3. 数据模型

### 3.1 服务端 `notes` 表新增三列

| 列 | 类型 | 语义 |
|---|---|---|
| `updated_at` | `TIMESTAMPTZ NOT NULL` | 标题/正文/分类最后一次实际变更时间 |
| `pinned_at` | `TIMESTAMPTZ NULL` | 最近一次置顶操作时间；未置顶为 NULL |
| `starred_at` | `TIMESTAMPTZ NULL` | 最近一次标星操作时间；未标星为 NULL |

### 3.2 盖章规则（服务端唯一盖章方，不信客户端时钟）

| PUT 内容 | 盖章动作 |
|---|---|
| 标题/正文/分类值**实际变更** | `updated_at = now()` |
| `is_pinned` 假→真 | `pinned_at = now()` |
| `is_pinned` 真→假 | `pinned_at = NULL` |
| `is_starred` 假→真 | `starred_at = now()` |
| `is_starred` 真→假 | `starred_at = NULL` |

要点：**值变化才盖章**。PUT 已有 `SELECT ... FOR UPDATE` 读旧行做字段合并（irisapi `src/router/notes.ts`），新旧值比对零成本；客户端重复上传相同布尔值不误刷时间戳。三个时间戳互不牵连——置顶/标星不刷 `updated_at`，编辑不刷 `pinned_at`/`starred_at`。

### 3.3 客户端 `local_notes` 表镜像三列

`server_updated_at` / `server_pinned_at` / `server_starred_at`（TEXT，存服务端下发值）。与既有 `local_updated_at`（本地最后编辑时间，未同步笔记的排序兜底）分工：服务端值优先，缺省回退本地值。

## 4. 排序规格

统一排序键（总序，无歧义）：

```
(is_pinned DESC,
 is_starred DESC,
 层内时间戳 DESC,   -- 置顶层 pinned_at；标星层 starred_at；普通层 updated_at
 id DESC)           -- 同刻决胜，防两设备间振荡
```

服务端/SQL 实现（`getLocalNotes` 的 ORDER BY 同步换键）：

```sql
ORDER BY is_pinned DESC,
         is_starred DESC,
         CASE WHEN is_pinned THEN server_pinned_at
              WHEN is_starred THEN server_starred_at
              ELSE server_updated_at END DESC,
         id DESC
```

客户端排序函数与上式严格等价；未同步本地笔记的层内时间戳取 `server_* ?? local_updated_at`。

## 5. 列表分层（单容器分段）

**单 FlatList 四段渲染**，禁止多个滚动容器：

```
┌──────────────────────────┐
│ 段1 置顶 · 已标星          │  pinned_at DESC
│ 段2 置顶 · 未标星          │  pinned_at DESC
│ 段3 标星 · 未置顶          │  starred_at DESC
│ 段4 普通                   │  updated_at DESC
└──────────────────────────┘
```

层间距、分隔线、是否加段头（如「已置顶」标签）属界面变更，**实施前须出文字预览（含 dp 标注）单独确认**。

## 6. 行为语义

| 用户操作 | 列表反应 |
|---|---|
| 编辑笔记正文/标题/分类 | 普通层内跳顶；**不打乱**置顶/标星层内位置 |
| 置顶 | 进入置顶层段顶（`pinned_at` 最新） |
| 取消置顶 | 离开置顶层，落入标星层段顶或普通层段顶（按标星态；兜底时间戳为 `updated_at`） |
| 重置顶（取消再置顶） | `pinned_at` 重新盖章，回到置顶层段顶 |
| 标星/取消标星/重标星 | 同理，作用于标星层与 `starred_at` |
| 另一设备同步来的变更 | 按同一排序键收敛到相同顺序 |

与旧语义的差异（已确认接受）：置顶层内按**最近置顶在前**（替代原 `pinned_order` 计数器语义，且天然多端一致）；编辑不再改变置顶/标星层内次序。

## 7. 多设备与冲突

- 时间戳全部服务端盖章：单一权威，无时钟偏差问题。
- 同笔记并发操作按**到达序 LWW**（与现有标星行为一致）；不同笔记互不影响。
- 同刻并列（批量导入等）由 `id DESC` 决胜，保证全设备确定性一致。

## 8. 存量迁移（服务端一次性回填）

| 列 | 回填值 |
|---|---|
| `updated_at` | `created_at` |
| `pinned_at`（仅现存已置顶行） | `created_at`（保持现有相对序，用户重新置顶后被真实时间戳接管） |
| `starred_at`（仅现存已标星行） | `created_at` |

回填策略为建议值（替代方案：统一回填迁移时刻），实施前最终确认。

## 9. 字段退役

`pinned_order`、`local_order`：本设计落地后**停读停写**（客户端排序键、`reconcileServerNotes` 回填、置顶交互全部切换到新键），列保留待后续清理迁移。`sortNotesByPinned` 由新排序函数替代；`withLocalOrder` 随 `local_order` 一并退役。

## 10. 实施顺序

1. 前置：阶段一护栏的真机验收（v3 包不再闪退）。
2. 服务端（irisapi）：三列迁移 + 回填 + 盖章逻辑 + GET 增列下发。旧客户端无感知（多出的 JSON 字段被忽略）。
3. 客户端：镜像列迁移 → `Note` 类型与 reconcile 读写（护栏的「有变化才写」检测纳入三新列）→ 排序键切换（SQL + JS）→ 置顶/标星交互适配。
4. UI 分层重构：文字预览 → 确认 → 实施 → 真机验收。

## 11. 残余风险

其他设备**批量**真实变更（如整分类迁移）下发时，本机仍发生多键合法移动——RN 0.86 Fabric 批量挂载竞态的残余风险仍在，兜底依赖上游修复后升级；`applyNotes` 等价跳过仅能挡「无变化重放」，不适用于合法变序。
