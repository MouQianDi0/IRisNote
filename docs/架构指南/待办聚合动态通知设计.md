# 待办聚合动态通知设计（Android 16）

> 状态：**已实施（2026-09-26），转为设计决策存档**。代码现状以 `docs/架构指南/系统通知模块负责说明.md` 为准；本文保留设计决策、实施时的口径调整及原因，供后续演进追溯。
> 前置阅读：`docs/架构指南/系统通知模块负责说明.md`（现有 Live Updates 链路）、`docs/UI/通知渠道适配.md`（渠道政策边界）。

---

## 一、背景与目标

聚合动态卡：向用户直观展示待办模块总状态（今日 / 临近 / 进行中 / 结束 四场景），应用退后台时由原生续算，锁屏与提升位可见。实施落在 `features/todos/services/todo-aggregate-live.service.ts`（纯函数）+ `TodoLiveUpdateCoordinator` 复用节拍 + 独立渠道 `irisnote.live-todo-summary.v1`（ID 7002）。

## 二、最终展示口径（实施后）

- **标题（胶囊位）**：`进行中 N`；存在临近（开始前 1 小时内）待办时 `进行中 N·临近 M`。
- **副标题（content text）**：分段统计 `今日 N 条待办 | N条重要 | N条待完成 | N条进行中 | N条已完成`（" | " 连接）。
  - 重要 = 未完成且 `priority = high`（创建时的重要度选择）；待完成 = 未完成数；进行中 = 已开始且未过结束的有时间待办；已完成 = 今日已完成数。
- **场景优先级**：进行中 > 临近 > 今日待办 > 结束；四场景共用同一标题/副标题（除结束态 `待办结束 / N·已完成`）。
- **无进度条**：聚合卡 `hideProgress = true`，原生不设置 ProgressStyle / setProgress，纯文本状态卡。
- **无 chronometer**：弃用秒级倒计时（`chronoAt` 恒 null），`secondsEligible` 恒 false；原生镜像 `LiveTodoSummary.scene` 同口径，分钟级兜底节拍一并移除。
- **统计口径独立于逐条卡资格**：含无提醒、无开始时间待办；`todoTimelineEligibleTodo` 不复用、不改动。
- **结束态**：须曾展示活动卡（seenActivity），最后结束/完成后保留 10 分钟撤卡；当日无待办不发。

## 三、提升（promoted）策略：重要事件提升

最终规则（原设计「聚合卡唯一提升、逐条卡全量非提升」在实施中演进两次，最终按重要度分流）：

| 卡片 | promoted |
|---|---|
| 聚合卡 | 恒 `true` |
| 逐条待办卡 | 创建时 `priority = high` 才 `true`；low/normal 非提升 |
| 60 秒模拟演示卡（7001） | 恒 `true`（保留提升演示效果） |

演进记录：设计稿为「仅聚合卡提升」→ 第一轮实施改「逐条卡全量提升（动态大卡）」→ 最终按用户需求改为「仅重要事件（priority=high）提升」，普通事件降级非提升。聚合卡副标题「重要」计数随之从 is_starred 口径改为 priority 口径；`TodoSummaryItem / NativeTodoSummaryItem / LiveTodoSummaryItem` 的 `starred` 字段统一替换为 `priority`（JSON 解析缺省回落 `"normal"`，兼容旧持久化快照）。

政策边界（通知渠道适配 §2.4）：用户在系统设置手动降级过提升通知后，同类内容不可重发提升式——切换优先级可能不上岛，属系统约束。

## 四、时间与更新节拍（实施后）

- 前台：复用协调器 30 秒例行 + 仓库变更即刷；文案为静态计数，无秒级模式依赖（`smoothSeconds` 参数保留但不再影响聚合卡）。
- 退后台：随 `handoffLiveTodoTimelines` 持久化（JSON 字符串入参），原生 `LiveTodoSummary`/`LiveTodoScheduler` 按临近/开始/结束/保留终点节拍重算。
- 冷启动：`clearStaleLiveUpdates` 同时清理聚合渠道残留。

## 五、架构分层（维持设计）

纯函数在 feature 层可被 node --test 直测；状态卡发送协议收口 `core/system-notifications`（`postStateCard`）；其他模块接入时声明自己的渠道 + 同构快照 + 同一 port，禁止直接 import todo 的 service；原生 `LiveTodoTimelineCard` 扩展 `summaryItems` 聚合字段，SharedPreferences 持久化与进程被杀恢复链路不变。

## 六、诊断与隐私（维持设计）

`live_update` scope 只记通知 ID、场景名、计数；不记待办正文与账号标识。

## 七、降级矩阵（维持设计）

| 环境 | 行为 |
|---|---|
| API ≥ 36 正式包 | 完整；上岛需 36.1+ 且系统未关闭"实时更新"，36.0 退化普通卡片 |
| API < 36 | 聚合卡与逐条卡均不发（动态通知整体按兼容档门禁） |
| Expo Go / 模块缺失 | 不发，设置页入口禁用 |
| 通知权限拒绝 / 聚合渠道被关 | 聚合卡不发，不影响逐条卡与到点提醒 |
| 逐条渠道被关 | 不影响聚合卡（渠道独立） |

## 八、遗留真机确认项

- 提升位/胶囊上计数标题与分段副标题的实际渲染与截断（36.0 / 36.1 / 国产 ROM）。
- 结束场景 10 分钟保留是否符合体感。
- 用户手动降级提升通知后，priority 切换的重发边界观察。
