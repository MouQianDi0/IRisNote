# 自动上传队列开发约定

> 状态：笔记与分类上传已接入；设置同步仅提供任务类型、入队函数和适配器注册口，尚无实际设置后端服务。交互与网络切换仍待用户真机验收。

## 1. 目标与边界

自动上传队列是按账号隔离的 SQLite 持久队列。业务数据先完成本地保存，再写入队列；全局协调器仅在应用前台、设备网络可用且服务端探测成功后串行执行任务。

- 支持 Wi-Fi、移动数据及系统报告为可联网的其他网络类型。
- 设备“已联网”不代表服务器可用；每轮上传前必须先执行只读服务端探测。
- 队列保存任务引用和上传所需业务参数，不复制笔记正文；执行笔记任务时读取最新本地快照，避免旧任务覆盖新编辑。
- 预计流量按 UTF-8 JSON 请求体字节数计算，不包含 HTTP/TLS 头、响应体、系统重传和网络协议开销，因此只作为上传量估算。
- 当前监听只在应用前台运行，不承诺应用被系统终止后的后台唤醒。

## 2. 状态机

```text
业务本地保存
  -> queued（SQLite 暂存）
  -> 检查设备网络
  -> 探测服务器
  -> running（串行上传）
     -> accepted：删除任务
     -> retry：最多累计 10 次
     -> paused：第 10 次仍失败，等待一次离线 -> 在线变化
     -> blocked：401/403/校验拒绝、未知创建结果或缺少适配器，禁止盲重试
```

应用意外退出时，遗留的 `running` 任务下次启动恢复为 `queued`。达到 10 次的排队任务会先转为 `paused`，不会跨重启产生第 11 次请求。`blocked` 不随网络恢复自动重启，避免重复创建或持续发送无效凭据。

## 3. 横幅与暂存列表

- 服务器未连接且存在暂存任务时，全局 `server-connection` 横幅显示任务数量、预计上传量及“查看暂存”。暂存列表入口只挂在该全局横幅及暂停横幅正文，不加入设置页。
- `/pages/user/sync-queue` 获得焦点后临时收回 `server-connection` 横幅，并在页面保持聚焦期间阻止两个协调器重新发布；页面失焦后若故障仍存在则恢复横幅。该行为只改变展示，不把服务器状态误标为已恢复。
- 上传期间使用稳定 ID `upload-queue-sync` 原位更新“当前任务 / 总任务、操作名称、第 N/10 次”；单次失败后的退避等待仍保持横幅，并显示“云同步失败，正在自动重试”。
- 全部或部分任务成功后显示“网络恢复，暂存任务执行成功”，并显示本轮成功数量和实际可观测上传字节。
- 连续 10 次失败后使用 `upload-queue-paused` 常驻横幅；“网络设置”打开 Android 网络面板，其他平台回退到应用设置；点击横幅正文进入暂存列表。
- 云端明确拒绝或创建结果未知时使用 `upload-queue-blocked` 常驻横幅，只提供“查看暂存”，不会错误引导用户检查 Wi-Fi。

暂存列表页面为 `/pages/user/sync-queue`。顶栏高 64dp，左右各 44dp；内容左右 16dp，概览卡内边距 16dp、圆角 16dp，概览到列表间距 20dp。列表卡按内容自动增高，超过剩余视口后才在 16dp 圆角裁切范围内滚动，不使用空白区域撑满页面。任务行最小高度 72dp、内边距 16dp；文字区字段间距 4dp，文字区到删除组件间距 12dp。删除组件使用 40×40dp `IconButton compact`、20dp 垃圾桶图标和 44×44dp 触控热区。

### 3.1 删除与本地回滚

- 笔记任务的删除语义是“回滚本地笔记”：队列行删除与本地版本回滚必须处于同一个 SQLite 事务，任一步失败都不得只提交另一半。
- 只允许回滚任务载荷所指向的当前 Revision；若笔记已产生更新版本则拒绝操作，避免旧弹窗覆盖新编辑。
- 回滚不会删除当前 Revision，而是读取其父 Revision 的内容并创建新的 `origin=restore` 版本，因此被取消的版本仍能在版本历史中追溯。
- 没有父 Revision 的新笔记禁用删除；`running` 任务已被协调器认领，也禁用删除。协调器认领必须使用 `status=queued` 条件更新，与删除形成互斥。
- 未尝试上传且已有服务端副本的笔记回滚后可恢复 `synced`；尚无服务端副本则保留 `pending` 供笔记页手动同步。已经尝试过上传的任务回滚后标记为 `unknown`，提醒用户核对云端状态。
- 删除笔记任务前显示 280dp 宽二次确认弹窗，明确“当前版本仍保留在版本历史中”；确认执行时锁定遮罩关闭与重复提交，并在弹窗内显示失败原因。
- 分类与设置任务删除时只取消队列任务；分类事件会重新计算队列叠加视图。分类目前没有完整 SQLite 快照，完全离线时已加载视图可能要等下次成功刷新后才恢复服务器基线。

## 4. 接入新上传服务

1. 在 `UploadTaskKind` 增加稳定任务类型，并定义可 JSON 序列化的最小载荷。
2. 调用 `enqueueUploadTask`，提供按账号唯一的 `dedupeKey`。同一业务对象的后续修改应覆盖或合并旧任务，不能无限追加。
3. 用 `registerUploadTaskAdapter` 注册执行器。执行器只能返回 `accepted`、`retry` 或 `blocked`，不得直接删除队列行。
4. 仅对无响应、408、429 和 5xx 等可恢复故障返回 `retry`。401、403、业务校验失败和创建结果未知必须返回 `blocked`。
5. 成功必须以服务端明确接受为依据；网络恢复、请求发出或本地保存均不能当作云端成功。

设置服务接入时使用 `enqueueSettingsUpload`，并先注册 `settings-sync` 适配器；未注册时任务会被安全阻断并保留供排查。

## 5. 当前限制

- 分类没有独立的 SQLite 实体缓存；已加载分类可叠加排队中的更新/删除，但应用冷启动且完全离线时无法仅靠队列重建完整分类列表。
- 分类新建在服务端确认前只显示于暂存列表，不生成虚假的本地服务端 ID。
- 队列尚未提供手动改序或强制继续 `blocked` 任务的操作。
- Android 网络设置跳转、iOS 回退、Wi-Fi/移动数据切换、进程终止恢复和横幅层级需要真机验收。
