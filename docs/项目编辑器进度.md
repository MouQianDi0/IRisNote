## 2. 当前架构

```text
src/app
├── AppProviders
│   └── src/core/database
│       ├── ApplicationDatabaseProvider：获取共享初始化资源租约
│       ├── migration ledger：记录并核对结构版本
│       ├── serial queue：收口公开操作，关闭时拒绝新任务并排空
│       ├── transaction：事务前确认外键，使用写锁；原生独立连接 / Web 复用连接
│       └── diagnostics：显式开发开关下的临时库故障与恢复诊断
└── Notes 路由
    └── src/features/notes
        ├── Screen：解析笔记 ID、加载状态和页面组合
        ├── data：按用户隔离的 local_notes 仓库与服务器列表合并
        ├── services：本地事务、缓存事件、云端上传和状态日志
        ├── NoteEditor：标题校验、本地优先保存和业务提示
        ├── drafts：独立草稿表、会话、写入调度、恢复与本地提交关联
        ├── revisions：阶段 3 实现
        └── src/core/editor
            ├── editor.types.ts：通用纯文本输入输出契约
            ├── plain-text-editor.tsx：输入状态和通用编辑界面
            └── index.ts：稳定公共出口

src/shared：主题、UI 和无业务归属基础能力
```

依赖规则：

1. `app` 只负责路由转发和导航容器。
2. Notes、Excerpts 等 Feature 可以依赖 `core/editor`。
3. `core/editor` 禁止依赖任何 Feature，也不读取业务 API、缓存或数据库。
4. Notes 的草稿、版本、分类、同步和容量仍属于 Notes 领域。
5. Excerpts 当前尚无实体和保存契约，后续通过自己的适配层复用编辑器。
6. 原始 SQLite 实例不进入应用组件树；Feature 不得直接导入 `expo-sqlite`，只能使用 `core/database` 的公共端口。
7. Web 与原生共用迁移和数据契约；平台差异只允许存在于事务和运行环境配置层。

## 3. 当前具体操作与逻辑

### 3.1 从详情页进入编辑器

1. 用户打开 `/pages/note/[id]`。
2. `NoteDetailScreen` 校验 ID 并加载笔记。
3. 用户点击顶部右侧“编辑笔记”按钮。
4. 路由携带字符串形式的 ID 跳转到 `/pages/note/edit/[id]`。
5. 根 Stack 对编辑路由设置 `headerShown: false`，页面只展示编辑器自己的顶部栏。

### 3.2 初始化编辑器

1. `EditNoteScreen` 先读取进程内笔记缓存。
2. 缓存缺失时读取当前用户的 SQLite 本地笔记；仍缺失才请求 `GET /notes` 并合并入本地表。
3. `NoteEditor` 把 `Note.title` 和可空的 `Note.content` 转成通用纯文本值。
4. `useNoteDraft` 取得按账户和草稿键隔离的会话，读取草稿及最新本地笔记，比较基础内容快照。
5. 有草稿时先展示恢复/对照/确认放弃；完成选择后才挂载 `PlainTextEditor`，避免空值覆盖草稿。
6. 编辑页及 Notes 适配层随账户重新挂载，账户不匹配的笔记不能进入会话。

### 3.3 编辑与保存

1. 输入立即更新编辑器内存，同时通知 Notes 会话；草稿保留原始空白、空标题和空正文。
2. 停止输入 750ms 或连续输入达到 5 秒时，通过串行调度器写入 `note_drafts`；写入中只合并补写最新快照。
3. 失焦、页面失去焦点、返回、应用退后台、Web 页面隐藏和卸载请求补写。正常返回等待写入完成；写入失败显示错误并每 3 秒重试，也可手动重试。
4. 点击保存后锁定输入并排空草稿任务；事务校验会话/序号和基础内容快照，写入 `local_notes`，同时将草稿关联实际客户端笔记 ID并更新基础快照。
5. 本地提交后增量更新缓存和事件，使用既有接口上传。云端接受后仅条件清理本次提交草稿；拒绝/结果未知保留草稿。
6. 新建入口每账户保留一个待处理草稿槽。已提交但云端失败的草稿关联已有笔记，恢复后更新该笔记；结果未知的新建不会自动重复 POST。
7. 放弃草稿需二次确认，按会话和序号删除并记录无正文日志；重新读取已保存内容后开始会话。

当前限制：基础快照仅检测本地内容变化，不是正式 Revision 或服务端条件更新协议；冲突时保留草稿供查看/复制，阻止直接保存。新增历史和块模型留在后续阶段。异常终止前未落盘的尾部输入仍可能丢失，后台事件不能保证执行完成。旧会话失去写入权后，未落盘输入须先复制保留。
