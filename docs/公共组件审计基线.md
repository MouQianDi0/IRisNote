## 4. 现有公共组件完整性

| 组件 | 当前能力 | 主要缺口 | 决定 |
| --- | --- | --- | --- |
| `Button` | 基础 variant、原生 disabled | 无统一尺寸、加载、文字、圆角、按压和语义禁用色 | 由 `AppButton` 替代并提供迁移兼容 |
| `TextField` | 包装原生 TextInput | 无状态配方、ref 约束、前后内容、错误和只读语义，业务调用少 | 由 `Input` 替代 |
| `Card` | surface/muted 变体 | 圆角与内边距仍交给调用方 | 保留并补齐有限变体 |
| `ModalPanel` | 三种固定面板尺寸 | 与新 AppDialog 外壳职责重叠 | 并入或服务 `AppDialog` |
| `AppModal/Overlay` | 处理原生 Modal 层级 | 未统一内容外壳 | 保留为基础设施 |
| `Banner` | 全局通知、操作和加载 | 尚未接入新语义主题 | 保留并迁移主题 |
| `Popover` | 锚点、自适应和动效 | compact 圆角仍用旧 Token | 保留并按组件配方迁移 |
| `ProgressBubble` | 拖动定位、文本和书签 | 裸字号、阴影尚未 Token 化 | 保留；圆角已迁到 16dp |

## 6. 审计命令与判定规则

- `npm run design:audit`：输出总量、逃逸计数和每类前五个文件。
- `npm run theme:check`：检查 `global.css` 托管区块是否与默认主题预设一致。
- `npm run theme:sync`：主题预设修改后重新生成 CSS 托管区块。

审计命中只是候选：

- 导出图片/PDF、光学微调和业务专用尺寸可以保留，但必须记录理由。
- 同一字面值重复出现两次以上，优先提取 Token 或组件配方。
- 页面不得新增公共组件身份色、身份圆角或状态优先级。
- 迁移按业务域小批进行，每批复跑审计；指标原则上应单调下降，新增命中必须有说明。

## 7. 当前结论

- 最高优先级不是清理所有任意值，而是先完成公共文字、按钮、输入框和弹窗入口。
- 主题值已具备单一默认预设与 CSS 一致性检查，旧导出继续保留兼容。
- `hyperControl` 的历史复用已经隔离：公共按钮和编辑器浮动工具栏均为 16dp，但工具栏使用独立 `editorToolbar` 语义，不再借用按钮 Token。
- 下一批以认证域作为第一个完整迁移样板，再按分类、草稿、阅读与笔记域推进。
